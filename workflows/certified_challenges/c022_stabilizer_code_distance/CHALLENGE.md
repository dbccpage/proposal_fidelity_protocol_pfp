# C022: Stabilizer Code Distance with Lower-Bound Certificates

**AuthorityEffect:** None. **Status:** planned. **Domain:** c_quantum. **Tier:** T3.
**Budget:** $1.00 billed inference per arm. **Models:** open weights, at most 70B total
parameters. **Protocol:** [SG-CP v1](../01_challenge_protocol.md).

## 1. Challenge

> Use the existing Symbol Game and models no larger than 70 billion parameters to produce a
> solver that returns the exact distance of hidden stabilizer codes on up to 20 qubits, with a
> minimum-weight logical operator and a checkable proof that no lighter one exists, for under $1.

## 2. Why This Task

Computing the minimum distance of a stabilizer code is hard in general, but checking a claimed answer splits into two cheap parts: an upper bound (one logical operator of the stated weight) and a lower bound (a certificate that nothing lighter exists). Q40 asked only for an upper-bound style answer; this challenge forces the solver to produce the lower bound too, which is where plausible but wrong answers fail.

The task stresses decomposition in OEWAS (Engine Workflows, Agents, Skills): parse a tableau, build a normalizer, encode a weight-bounded search, and return a proof object. It stresses OEEIS (Engine Epistemic Immune System) on degenerate codes, where the lightest element of the normalizer is a stabilizer and must be excluded. A pass shows the arm can assemble a certified distance pipeline. It does not show a new algorithm: exhaustive and SAT-based distance computation are standard.

## 3. Formal Problem and Bounds

Input: a stabilizer group S on n qubits, 1 ≤ n ≤ 20, given by m = n − k generators as Pauli words with signs, 1 ≤ k ≤ n − 1. The normalizer N(S) is the set of Pauli operators commuting with every generator. The distance is

d = min { wt(P) : P ∈ N(S), P ∉ S (up to phase) }.

Work is over F2^{2n} in symplectic coordinates; phases do not affect distance but the input signs must still be consistent (−I ∉ S).

Known reference values (hidden base cases may include relabelled copies): the five-qubit code [[5,1,3]] (Laflamme, Miquel, Paz, Zurek 1996; Bennett, DiVincenzo, Smolin, Wootters 1996), the Steane code [[7,1,3]] (Steane 1996), the Shor code [[9,1,3]] (Shor 1995), and the toric code [[2L², 2, L]] (Kitaev 2003) for L = 2, 3. Every other hidden distance is computed by the independent second checker at packet-build time.

Edge cases the hidden set must contain: degenerate codes (Shor code: weight-2 stabilizers below d); codes where a minimum-weight logical has a Y on some qubit; non-CSS codes; k > 1; dependent generators (malformed); anticommuting generators (malformed); generators whose product is −I (malformed).

## 4. Deliverable and Output Contract

A frozen module `solve(case: dict) -> dict`. The sandbox exposes one pinned tool, `tools.sat_solve(cnf) -> {"status", "model" | "lrat"}`, wrapping a pinned CaDiCaL binary. Input:

```json
{"case_id": "code_11", "num_qubits": 7,
 "generators": ["+IIIXXXX", "+IXXIIXX", "+XIXIXIX", "+IIIZZZZ", "+IZZIIZZ", "+ZIZIZIZ"]}
```

Outputs:

```json
{"id": "code_11", "status": "SOLVED", "distance": 3, "logical": "XXXIIII",
 "lower_bound": {"format": "lrat", "encoding_sha256": "…", "proof_b64gz": "…"}}
{"id": "code_12", "status": "OUT_OF_SCOPE", "witness": {"kind": "anticommuting", "pair": [0, 3]}}
{"id": "code_13", "status": "UNKNOWN", "refusal_code": "LOWER_BOUND_NOT_CERTIFIED", "upper_bound": 5}
```

A `SOLVED` certificate is complete when: `logical` has weight `distance`, commutes with every generator, and is not in the F2 span of the generators; and `lower_bound` is an LRAT refutation of the published CNF encoding "there is P ∈ N(S) \ S with 1 ≤ wt(P) ≤ d − 1", with the encoding regenerated by the checker from the input (the solver's CNF is never trusted). For d = 1 no lower bound is needed. `OUT_OF_SCOPE` witnesses cover an anticommuting generator pair, a dependent generator (with its F2 combination) or a product equal to −I. Proof size is capped at 64 MB per case.

## 5. Participant Packet

- `TASK.md` with §3, §4, the exact CNF encoding convention (variables per qubit for x and z bits, the "not in S" constraint via a parity-check matrix of the stabilizer span, and a sequential-counter cardinality bound).
- `examples/`: 10 cases with exact expected output: the [[5,1,3]], [[7,1,3]] and [[9,1,3]] codes, the 2 × 2 toric code, two random CSS codes, one non-CSS code, and three malformed cases.
- `runner.py`, `tools.py` (`sat_solve`), `accounting.json`.

## 6. Judge Packet

- **Hidden base cases:** 30 codes, n from 5 to 20, d from 1 to 7, at least 8 degenerate and at least 8 non-CSS.
- **Relabel and gauge controls:** 10 controls: qubit permutation, a different generating set for the same S (row operations over F2 with sign bookkeeping), and a local Clifford applied to every qubit. Distance is invariant under all three.
- **Poisoned-but-schema-valid cases:** 6 cases, among them a code whose lightest normalizer element is a stabilizer (a solver that forgets `P ∉ S` reports a smaller d), and a code where a weight-(d − 1) operator commutes with all but one generator.
- **Exact checker (Rust):** recomputes commutation, span membership and weight, regenerates the CNF, and checks the LRAT proof with a pinned LRAT checker.
- **Independent second checker:** enumerates every Pauli word of weight below d, confirms none lies in N(S) \ S, then confirms a weight-d logical exists. At n = 20 and d = 7 that is Σ_{j≤6} C(20, j)·3^j, about 3·10⁷ words; this is feasible in Rust and shares no code with the SAT path.
- **Mutation suite:** a stabilizer offered as `logical`, a logical of weight d + 1, a proof for a different encoding, a truncated proof, a distance one below the truth with a valid-looking logical, a witness pair that commutes.

## 7. Arms and Baselines

Arms A–D per the protocol, each synthesizing the solver. Arm E is the no-model baseline: the checker's own enumeration plus direct CaDiCaL calls, packaged as a solver. E is expected to pass; if A only matches E, the result is useful automation without a model advantage. Arm F does not apply.

## 8. Budget, Models and Provenance

$1.00 per arm, enforced before each call. Candidate models: `meta-llama/llama-3.3-70b-instruct`, `deepseek/deepseek-r1-distill-llama-70b`, Qwen3 32B, `qwen/qwen3-30b-a3b`. ## 9. Pass Gates and Statistics

- **Capability gate:** 30/30 base and 10/10 controls with every `SOLVED` certificate accepted by both checkers. `UNKNOWN` with a correct upper bound is not a pass but is scored as honest, not wrong.
- **Primary metric (pre-registered):** per-case certified-correct rate on base cases, arm A vs arm B, paired exact McNemar within seed-matched runs.
- **Seeds:** at least 3 per arm; report the distribution.
- **Secondary:** poisoned-case accuracy, proof size, cost per verified success.

## 10. Interpretation

- A correct `logical` with a missing or invalid lower bound is scored wrong. That is the point of the task.
- If every arm passes non-degenerate codes and fails degenerate ones, the shared failure is the `P ∉ S` constraint, not the representation.
- If A beats B only on proof validity, the host checks are doing the work; compare with C.

## 11. OEEIS, Attention, Logit and Scratch-Space Hooks

The catalog declares no required OEEIS hooks. Relevant mechanisms:

- **Danger gate:** signal 1 is a schema-valid `SOLVED` answer; signal 2 is a `logical` that lies in the stabilizer span. Together they mark the degenerate-code antimorphism.
- **Kinetic proofreading:** upper bound, then encoding hash, then LRAT check, in that order; a candidate is admitted only after all three.
- **Complement** is not implemented in the estate and is not required.

No Layer-1 or Layer-2 controls (no arm F). Host scratch space (U12) should hold the F2 parity-check matrix of the stabilizer span so repair turns do not rebuild it.

## 12. Run Folder, DDC Trace and Operand Mining

Expected DDC pattern: `C` (expose tableau), `I` (build normalizer and span test), `Λ` (lift from weight w to w + 1 in the search), `R` (residual: lightest non-excluded candidate), `D` on each certified weight layer, `M` on a refuted candidate, `T` on a complete certificate. Logged measures: current certified lower bound, best upper bound, gap, and proof size.

Operands expected: (1) span-exclusion constraint via a parity-check matrix; (2) sequential-counter cardinality encoding for weight ≤ w; (3) degenerate-code check "lightest normalizer element is in S"; (4) gauge invariance of distance under local Clifford maps.
