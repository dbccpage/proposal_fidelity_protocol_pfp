# Offline mechanism recreations

These executions recreate mechanical components with declared finite fixtures.
They are executable demonstrations, with actual tensor changes, emitted bytes,
native requests, checker responses and negative controls. They do not establish
the empirical success gates of the planned C002–C010 studies. Every receipt has
`empirical_result: false`, `challenge_gate_satisfied: false` and an explicit list
of remaining obligations.

The retained C001 and C005 packages exist; C002–C004 and C006–C010 are planned
Markdown specifications. The source binding records the ten specifications,
C001 key-mask implementation, C005 schema and checker, and both prose-demo
READMEs. Capture pins the current raw bytes once; replay rejects changed bytes
and never overwrites an existing binding. Only the two small C005 Python
modules are imported from that source set. The tensor adaptations are new
paper demonstrations of the declared intervention rules, and are labeled as
such rather than being attributed to an executed model hook.

The C004 repair uses a three-edge directed cycle with unit weights and original
claims `(1, 1, 1)`. The emitted candidate is `(1, 1, -2)`. Rust independently
checks the candidate against the declared incidence matrix and potential,
then checks the original primal-dual certificate with exact repair cost `3`.
A changed final candidate and a changed dual witness both fail native replay.
This is an optimality certificate for this finite cycle, without a model claim.

C005 is a reproduced falsifier, not a successful contradiction verdict. Its
schema-valid proposal declares `INCONSISTENT` for `(1, 1, -2)`, and the retained
checker accepts it without requiring an obstruction. The independently invoked
graph evaluator returns `phi1 = 0`. Schema enforcement therefore cannot repair
the mathematical verification gap.

The retained neural mechanism fixtures were executed with CPU PyTorch
`2.6.0+cu124` and float64 tensor operations. A current run requires torch
`>=2.13.0`. These inexact neural values are explicitly separate from the exact
Rust graph and certificate results. There are no downloaded weights, provider
calls, implicit native builds or mathematical solver implementations in this
module. Native executables are explicit capabilities checked by SHA-256 before
and after every invocation. Receipts retain the complete native input and
output objects and hashes of the actual response bytes.

From the paper root, after supplying the explicit engine capability and the
existing source binding:

```console
py -3.12 code/mechanism_recreations.py --repository <source-checkout> --source-bindings docs/mechanism_recreated_run/source_bindings.json --engine-capability docs/recreated_run/engine_capability.json --output-dir docs/mechanism_recreated_run
```

Append `--terminal-view packet`, `--terminal-view cemetery`, or
`--terminal-view hodge` to display that inspected view. The Hodge page names
the absent decomposition port rather than drawing fabricated proportions.

The focused test command is:

```powershell
$env:PAPER011_ENGINE_CAPABILITY = Join-Path (Get-Location) 'docs/recreated_run/engine_capability.json'
```

not be reported as native verification. The retained run used the declared
