Its catalog closes over the 27 entries actually present in the preserved `DEMO_DISPATCH`, C001–C060, the separate G01–G25 obligations, and the 13 aggregate families in `findings_demo_inventory.json`. ## Evidence boundaries

`SOURCE_RECREATION_PYTHON` means a fresh execution of a retained source algorithm and its retained checkers. It is not a new mathematical solver, a native certificate, an independent-provenance theorem, or a model-accuracy result. Every scored input, response and checker return is retained. Literal Boolean checker outcomes are required; truthy metadata is refused. UNKNOWN answers, typed refusals and negative claims are counted separately. A negative label alone does not establish a checked obstruction. Each unsupported mutation shape is recorded and prevents mutation completeness.

`FINITE_MECHANISM_REPLAY` joins the separately owned C001–C010 mechanical interventions. Their real finite tensors, decoder masks, scratch-space examples and native graph certificates are executable, while all empirical model-study gates remain false. The C005 unconditional inconsistency acceptance is a reproduced checker defect, not an accepted mathematical result. The mechanism module also supplies a finite terminal view; the MUB6–Regge README still lacks the declared constraint systems and certificates needed for its advertised positive result.

Native evidence retains actual requests, captured responses and executable hashes. The canonical engine transport uses the OEOS host boundary; the source dossiers retain their original certificate wire. Requests naming a Rust verifier through the old Cargo fallback are routed to the explicitly pinned existing binary. The routing receipt records the original command and new executable. Cargo never runs inside a replay worker. Missing verifier capabilities refuse instead of passing.

Tapes from `full_v2`, `affected_v3`, `final_bindings_v4` and `c041_pinned_v4` can contain UTF-8 re-encodings of the original subprocess's decoded/newline-normalized text observation. They bind that retained observation, not necessarily physical stdout/stderr bytes. Coverage labels their representation `LEGACY_REPRESENTATION_NOT_ASSERTED_PHYSICAL_RAW`; later environment/capture repairs do not change that history. New tapes explicitly marked `RAW_SUBPROCESS_BYTES` capture physical stdout/stderr and actual encoded input bytes before returning the original encoding/error-handled, universally newline-normalized text view to unchanged source code. A non-ASCII/CRLF/invalid-byte control distinguishes those representations. Lean proof/judge/module snapshots are actual file bytes in both versions.

C060 executes the retained classifier and all 48 checker mutants. This measures classification and mutant detection on the retained 64-case set. It does not synthesize a checker and does not recreate an absent model experiment. The stored result states that ceiling explicitly.

## Failure and completion

A bounded timeout is `BUDGET_EXHAUSTED`, never rejection, exhaustive search or completion. A reference crash, incomplete mutation binding, UNKNOWN answer, missing audit signature or unavailable positive native port remains explicit. An accepted historical refusal may faithfully recreate a negative example while leaving the intended positive demonstration open. Worker and batch command failures propagate a nonzero exit. Integrity verification only verifies artifact custody; it does not rerun calculations.

The preserved dossier checkers receive explicitly bound original read-only inputs when their audit interface permits it; checkers requiring adjacent writable resources run in temporary copies. Both paths retain their actual valid and near-miss verdicts. Their returned PASS summaries require inspection alongside actual native transport tapes. Discovery or execution of a checker does not make the positive witness valid. Full paper completion also requires the source archive's independent byte-custody check, separately owned aggregate recreations, the remaining positive obligations and paper packaging.

Demo 6 has a direct seam: `check_exact_phi2_certificate(input_data, witness_data, repo_root)`. Its retained YAML, valid witness and four near-miss candidates per dossier are bound by original path/hash and called with the explicit engine root. Native positive coverage requires a new `verify_phi2` transport event with actual `PASS`, matching reported value and zero gap. The source's unconditional final `CERTIFIED` label cannot supply that gate; its `betti_2` literal remains declared metadata, not a rank proof.

Demo 7 and Demo 9 use their unchanged `run_dossier_audit` or `run_dossier2_audit` interfaces with the same explicit engine root. The adapter binds all three original input/witness files per dossier and retains every returned field, including Bianchi defects, declared cochain pairings and topology refusals. A native certificate requires exactly one captured call to the correct pinned `verify_phi3` or `verify_phi4`, an actual PASS with zero gap, and matching source/request/response values. Negative-control completeness requires the original four case IDs in order and each exact declared refusal, allowing only the source protocol's existing `REFUSED_` prefix spelling. A source PASS without that tape or a shortened near-miss collection cannot pass composition.

These scoped ports are injected through the existing `native_demo` composition path, with the original production adapter output retained under `canonical_adapter_diagnostic`. A checked rational Phi certificate cannot establish a manifold, intersection form or cup product. Demo 9's original second audit explicitly refuses its declared topology and leaves the exact gauge cup pairing unsupported; those literal residuals remain in both the receipt and coverage matrix even when its Phi4 witness verifies. Separate root-owned native homology evidence can assess the declared matrices without rewriting these source assertions.

`--proposals code/fixtures/c041_supplemental_candidates.json` selects exactly the two explicit original C041 targets for supplemental checking. Each case must match its original raw hash and interpretation; the historical solver is not invoked or changed. Their two candidate checks and four newly generated corruption/wrong-kind-target controls have a separate denominator from the full source's 64 cases and 48 mutations. Coverage retains the original C041 row and appends these receipts under `supplemental_candidate_checks`; a later selected run cannot discard the other 62 original cases or replace the recorded solver abstentions.

## Commands

Run from the paper directory with an explicitly configured Python 3.12 runtime. `catalog --source-root <PFP demos> --output docs/recreation_catalog.json` records the source-derived scope. `lock-engine` takes `--engine-root`, `--source-head`, `--native-host`, `--functional-host`, repeated `--verifier-bin NAME=PATH`, and `--build-receipt docs/native_build_receipt.json`.

`run-batch --source-root <PFP demos> --capability docs/recreated_run/engine_capability_v3.json --output-dir <fresh directory> --timeout 60` executes the declared demonstration/challenge catalog. `--ids` selects an explicit subset; the receipt identifies it as a subset. C041's separately declared worker budget is 1800 seconds, retaining the original per-compiler-call resource bounds. `run --id C017` executes one row with a complete independent custody recheck. `verify --run-dir <run>` checks canonical receipt and complete artifact inventory. The focused file `code/tests/test_paper011_recreations.py` tests mutation completeness, refusal accounting, import fidelity, digest tampering, proof/module byte custody and fresh-cache runtime configuration.

Aggregate families use `code/aggregate_recreations.py` and their own source capability and receipts. The findings inventory is a source map and falsifier specification, never an execution receipt.

`coverage --primary-batch docs/recreated_run/full_v2 --supplemental-batch <closed targeted run> --output <matrix.json>` emits the receipt-bound outcome matrix. It reports actual case records, mutation outcomes, native transport outcomes, dossier audits and concrete remaining inputs/capabilities; it explicitly leaves full positive recreation completion false when those obligations remain.
