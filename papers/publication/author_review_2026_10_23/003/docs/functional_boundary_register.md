# PFP functional ownership and availability

Source baseline: `52cb5457f6c485ba548cfd292f6012a941ed22cf`

The calculation owner for named Phi1/Gamma2/Xi functionals is
`omega_engine/crates_rs/omega_functional/src`.
A Python caller may prepare inputs or transport results. A stored number, a
model statement, or an adapter's success Boolean does not establish a native
calculation.

| Surface | Boundary at the stated baseline |
| --- | --- |
| Canonical Demo 3 host | All witness routes return `NO_NATIVE_PORT`; phase/fuel/rollback checks remain available |
| Symbol Game runtime seam | `omega_engine_pfp/ffi.py` delegates to the operating-system native process adapter |
| Exact functional port | `infrastructure/adapters/exact_rust_adapter.py` transports native results or typed failures |
| Graph tutorial adapter | `omega_engine_providers/adapters/native_functional.py` requires graph executable path and SHA-256 pin |
| Legacy run-turn/run-bout/run | Required by boundary tests to refuse before writing functional results |
| Restricted Rust prime host | Exact same-carrier replay can execute while admission remains refused |
| Historical Python calculators | Preserve their documented retirement/refusal boundaries; no silent fallback |
| Stored pilot/log fields | Historical caller/provider records requiring their own custody analysis |

The Rust runtime dispatcher, additive foundation library, and restricted host
have different contracts. Their presence does not establish a completed
Demo 3 route integration or global Python/Rust parity. See PFP IV, the fourth
paper in this series, for the full native architecture and encoding distinctions.

The earlier validation report is preserved as historical evidence with its
own source pin. No count there is a fresh result for this manuscript.
