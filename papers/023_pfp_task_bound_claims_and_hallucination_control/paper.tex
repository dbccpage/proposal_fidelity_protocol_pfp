\subsection{Abstract}\label{abstract}

A certificate establishes a declared property of a declared task. It
need not establish surrounding prose. We give a finite claim-scoping
rule that admits only the claims actually discharged by independent
checks, and a counterexample to promoting a correct witness into a
correct explanation. This supplies a precise PFP response to some
hallucinations while retaining the boundary around unchecked
natural-language claims and source quotations.

\subsection{1. Task, claim, and evidence}\label{task-claim-and-evidence}

A task is a tuple \(P=(D,R,H)\): a finite candidate domain, a solution
predicate, and supplied assumptions. Its identity includes all three. A
claim index \(J\) names predicates \(R_j(P,w)\) with separately supplied
checkers \(C_j\). A receipt contains the original task identity,
submitted witness, checker identities, and exactly the set
\(J_{\rm checked}\) for which those checks accepted. An admission schema
checks this binding; it does not decide every predicate. Authorization
to use the result remains an independent input.

\subsection{2. Scope theorem}\label{scope-theorem}

\textbf{Theorem.} Assume each invoked checker is sound on its declared
input: \(C_j(P,w)=\mathsf{accept}\Rightarrow R_j(P,w)\). A receipt
admitting only \(J_{\rm checked}\) establishes
\(\bigwedge_{j\in J_{\rm checked}}R_j(P,w)\). It establishes no supplied
predicate for a different task, assumption set, witness, or uninvoked
claim index without an additional checked implication.

\textbf{Proof.} Apply the corresponding soundness implication to each
checked index and form their finite conjunction. No implication to
another index is among the premises. A countermodel can keep every
checked predicate true and make an unchecked predicate false, disproving
that further inference. This last argument is a limitation of these
premises, not a claim that every pair of mathematical predicates is
independent. An actual proved implication can of course transport a
claim when its assumptions and task bindings are checked.

\subsection{3. A correct witness with a false surrounding
claim}\label{a-correct-witness-with-a-false-surrounding-claim}

Let \(D=\{0,1\}^2\) and \(R(x,y)\) mean \(x+y=1\). Both \((0,1)\) and
\((1,0)\) solve the task. The witness \((1,0)\) passes the equation
checker, but the sentence ``every solution has \(x=1\)'' is false. A
receipt for equation satisfaction cannot validate that sentence. The
companion independently checks the universal claim against all four
assignments and rejects it.

An invented source quotation is a third obligation. Its check needs
supplied source bytes, their identity, and a span or other declared
matching rule. The equation witness supplies none of those. Missing
quotation evidence therefore leaves the quotation unverified even when
the equation is solved.

\subsection{4. Two-level PFP exchange}\label{two-level-pfp-exchange}

The shared system prompt describes proposing, checking, repair, and
refusal, with a worked example. The user instance supplies \(P\), its
permitted witness language, required claims, and response schema. The
model returns a candidate; the host chooses the relevant declared
checkers and replays that candidate. The packet can contain an
explanation, but the receipt records its exact checked scope. A failed
required claim prevents full acceptance; an optional unchecked
explanation remains explicitly outside the accepted scope.

\subsection{6. What this contributes and what remains
open}\label{what-this-contributes-and-what-remains-open}

The logical conjunction rule is elementary. PFP's contribution here is
the operational requirement that claim scope, task identity, and
independent checking survive prompt and packet handling. It prevents
these particular forms of unsupported promotion under the sound-checker
assumptions. It does not make all language true, resolve inconsistent
assumptions, or establish the soundness of an arbitrary checker solely
on the basis of a checker returning \passthrough{\lstinline!PASS!}.
General extraction of prose into faithful mathematical obligations
remains a separate research and implementation problem.

The
\href{https://github.com/dbccpage/the_symbol_game/blob/main/omega_engine_atlas/coda_atlas/F004_papers/015_pfp/023_pfp_task_bound_claims_and_hallucination_control/prompts/example.yaml}{two-level
teaching packet} includes shared system rules, this typed user instance,
a different worked example and a required candidate response schema. It
keeps provider system/user roles separate. It is a saved example, not a
schema-admission or model-run receipt; the local replay checks the
mathematical or protocol obligations stated above.

\subsection{7. Claim scope in the operadic
implementation}\label{claim-scope-in-the-operadic-implementation}

The current implementation separates capability composition from
execution, immune screening, and lineage. OEOP supplies typed operation
declarations and source-bound instructions; Woland executes configured
callbacks; OEEIS supplies the immune observation; Prompt Civilization
records lineage. Generated host instructions are discovery views, not
additional claim authorities.

The
\href{https://github.com/dbccpage/the_symbol_game/blob/main/omega_engine_atlas/coda_atlas/F004_papers/015_pfp/028_pfp_operadic_composition_and_bounded_ddc_repair/paper.md}{bounded
DDC repair study} applies this paper's distinction to one supplied code
patch. A successful typed composition is not an executed repair. A
\passthrough{\lstinline!REPAIRED!} outcome means the declared baseline
failures were removed without breaking the supplied passing controls; it
does not establish correctness on untested inputs. An immune result of
\passthrough{\lstinline!NOT\_MEASURED!} cannot be read as clearance. A
recorded lineage is not detector admission, and the example does not
apply the patch to the original source.

These are implementation correspondences to the scope theorem's
premises, not new consequences of the finite Boolean replay. The
original proof and example are unchanged. No model-performance
measurement or new Lean proof is reported by this revision.
