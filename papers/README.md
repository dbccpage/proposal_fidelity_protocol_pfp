# Proposal Fidelity Protocol paper collection

The [WDP Paper Trio](../../../../../atlas/coda_atlas/F004_papers/001_finite_obstruction_calculus/WDP_PAPER_TRIO.md) places the foundations in Papers 000–002. Existing deposits here retain their identities and release records.

Proposal Fidelity Protocol (PFP), historically called **The Symbol Game**,
separates candidate proposals, checks of declared properties, and decisions
about their use. This collection explains the method for researchers,
implementers, and readers learning the system.

Start with [Paper 000](000_pfp_introduction/README.md) for S(n),
MSS-N, and basic packets, then [Paper 001](001_pfp_discrete_cochain_retraction_and_toy_involutions/README.md)
for a worked finite example, or with the
[practitioner guide](005_pfp_practitioners_field_manual/README.md) for
the operating workflow. Each folder in the v0.1.0 publication array is a
self-contained package: the manuscript (`paper.md`, `paper.tex`, `paper.pdf`),
its claim ledger and change log, code with tests, and a release archive with
checksum manifests. The [publication](publication/) folder holds linked
renderings of those deposited manuscripts. The earlier 011–020 set was removed; a current shelf 011 now contains [PFP shape, review findings, and the next test campaign](011_pfp_the_minimum_theorem/paper.md). Shelves 012–020 are absent at this baseline. Shelves 023–027 are
unpublished author-review drafts and do not have that deposit shape. The new
implementation study on shelf 028 has the same author-review, non-deposit status.

## Build the collection

With Python 3.12, Pandoc, and XeLaTeX installed, run from this directory:

```powershell
py -3.12 tools/build_publications.py --pdf --deposit
py -3.12 tools/check_publications.py
py -3.12 -m unittest discover -s tools -p test_publication_checks.py
```

`--pdf` compiles the collection renderings under `publication/`; `--deposit`
writes and compiles each package's standalone `paper.tex` and `paper.pdf`.
Both use three XeLaTeX passes and refuse overfull lines. The builder snapshots
its inputs and refuses a source change during the build. After a deposit
build, each package's `tools/rebuild_release.py` regenerates its manifests and
release archive, and `verify_deposit.py` checks them.

The current bounded replay selects sixteen named offline test files and records
all outputs, skips, and source hashes. Run it with a fresh receipt path outside
the paper deposits:

```powershell
py -3.12 replay_completion.py --timeout 180 --output verification/my_selected_checks.json
py -3.12 replay_completion.py --notebook-only --output verification/my_notebook_check.json
```

An optional `--deadline-utc` timezone-aware ISO timestamp applies to either
mode. Test timeouts terminate their process trees; thirty-five seconds are
reserved for cleanup. Notebook kernels exclude provider credentials and Python
optimization, and verify that their assertions are active. Lean and native
replays are separate checks; the default deposit verifier checks manifests and
structure.
