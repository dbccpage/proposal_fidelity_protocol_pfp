## What a prompt means in the current code

| Concept | Existing owner | Meaning and limit |
| --- | --- | --- |
| Text leaf | `omega_engine_pfp/domain/prompts/pfp_prompt.py` | Immutable text with a checked UTF-8 content digest. The optional system text has a separate role. A digest identifies bytes, not meaning or truth. |
| Containment | `domain/rewriting/prompt_containment.py::ExpansionNode` | Ordered child references, cardinality and bounded depth. Sections in prose do not automatically create children. |
| Template | `domain/prompts/prompts.py::PromptTemplate` | Versioned rendering instructions and declared slots. Keep task data distinct from instructions. |
| Dispatch packet | `domain/contracts/pfp_runtime.py::PfpPrompt`, `PromptPacket` and `PreparedTaskTurn` | Rendered system/user/schema and task/attempt/input bindings. PFP checks the actual response bytes. |
| Task family | `domain/task_families/task_family_types.py` | Input/solution modalities and checker contract. This is not the constant wire-family name `prompt_artifact`. |
| Reader-relative family | `omega_engine_woland/domain/prompt_family.py::PromptFamilyV1` | Prompt nodes, actual readers, calls and repair ancestry. Its integer-cost call ledger now refuses unobserved billing and lossy numeric coercion; native IDE usage uses the explicitly unobserved procedure path. |
| Reusable DDC procedure | `DdcProgramBinding` and `use_cases/prompt_family_replay.py` | Prompt digest, versioned family, template, premises, semantic trace root and retained stage/mode artifacts. It conveys no accepting verdict. |

Text is a useful primitive at the byte boundary. A composed prompt additionally
needs typed relationships, ordering, provenance, boundaries and a response
contract. The existing leaf/container/packet separation supports this; one
universal string type would lose those distinctions. A containment record does
not itself implement expansion or adoption: documentation references to missing
runtime helpers remain an integration gap.

## Repairs supported by this experiment

The canonical DDC logger emits `omega.ddc.trace.v2`, `ddc_dialect` and
`DDC_STEP_NNN`; the existing research reader accepted only the historical DDA
profile. The reader now accepts explicit profiles for both, verifies their
original hashes and rejects mixed chains. Historical bytes are not renamed.
An independent review found an unchecked schema-value lookup; array and object
schema values now receive the typed refusal, with regression cases.

The existing relational prompt v1 deliberately preserves non-executable recorded
wire bytes. `SqlitePromptRepresentation` adds the separate
`sqlite_strict_utf8_v2` profile, with fixed DDL/table names and UTF-8 data literals.
Actual SQLite roundtrips preserve quoted text, Unicode and NULs without executing
embedded commands. This represents prompt text; Meron physics still uses its
original SQL/model owner. Arbitrary model-supplied SQL is not authorized by it.

`persist_ddc_program` uses the existing native five-file writer and requires
successful readback. `load_ddc_program` checks the native storage envelope,
original logger chain, semantic root, premises and stage/mode bindings.
`prepare_ddc_reuse_turn` puts that revalidated procedure in a fresh PFP context
and refuses changed seed bytes or premises. Unknown native billing stays null.
Every reuse carries `fresh_checker_required=true` and mathematical acceptance
`UNVERIFIED`; the current candidate must be checked again. These helpers are an
explicit research path, not a claim that ordinary `teamwork persist` now records
mathematical DDC automatically.

Independent review also reproduced three consumer failures, now covered by
regression checks: a free task string could contradict validated side arguments;
a record containing `C.E` could bypass the obligations of an `E` transition; and
coherently edited receipt/billing metadata could be accepted. Reuse now constructs
the actual structured input from the validated seed and premises, each record
must contain one operation, and the reader checks the skill receipt profile,
storage task, source, objective, authority and unobserved billing policy. The
reuse context retains those premises and billing limits. These checks establish
internal consistency; they are not authentication of an operator or execution.
The recheck found a mutable-input stability defect: changing the caller's premise
dictionary changed the retained prepared task while its serialized prompt stayed
fixed. Preparation now owns a private premise snapshot; the original bound reply
continues to validate after the caller changes its dictionary.
