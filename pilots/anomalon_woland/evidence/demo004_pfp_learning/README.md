# PFP challenge integration evidence

AuthorityEffect: None. Execution is partial; this is not a claim that the sixty
challenges are solved.

Seven family pilots preserve the original challenge problems and their separate
judges. The matrix indexes 2,777 source cases. Local case-custody tests check those
inputs; they do not measure model capability. Thirty attention-intervention
conditions remain skipped until the required hooks exist.

`trial_register.json` indexes every completed provider run, its cost, its source
snapshot, and known experimental defects. `learning_candidates.json` connects
observed failures to repairs and follow-up tests. Candidates have no automatic
skill or immune-system admission authority.

The twenty completed DeepSeek runs contain thirty-five provider replies and cost
USD 0.018768 in total, rounding each reply upward to integer microdollars. Each
run was capped at USD 0.05 across at most two stages. A separate free Gemma request
received HTTP 429; its billing remains unknown. The obsolete Qwen model identifier
was rejected by the live catalog before dispatch. There were no hidden retries.

The first DeepSeek run had a schema/parser mismatch. Several subsequent runs had
protocol literals removed by prompt redaction. C005 then exposed an exact-schema
overwrite. These are harness defects, not clean measurements of model capability.
Their raw replies and historical source bytes are retained. After the repairs,
C039, C050, and C055 each produced an accepted one-shot witness on one development
case. This small sequential sample does not establish a comparative advantage.

C005's corrected-schema trial still failed arithmetic in both stages. C011 had
both one-shot successes and a two-stage development repair, but its held-out
transfer trial failed both stages. C021's signed-Pauli guidance also failed both
stages. Python judges and the actual Rust checker agreed on rejection. Those
rules remain unadmitted candidates.

`host_controls/manifest.json` records an exploratory NO_LLM integration sweep:
97 fixture verifications, 23 typed refusals, 79 infrastructure errors, and one
checker defect. Its eight-second timeout and evolving imports/adapters make it
unsuitable as a mathematical failure rate. Not all 200 historical controls have
been execution-replayed. Current scoped regression checks supersede those
diagnostics; the historical receipts are not rewritten to manufacture success.

Use the shared campaign's `--replay-live` for a run whose source bytes match the
checkout. Older runs deliberately refuse current-source replay. Restore that
run's `source_snapshot/` bytes into a disposable checkout of this integration
branch before replaying it. Preserve the prompt template and source-case bytes
bound by the matrix. Set `OMEGA_SYMBOL_GAME_HOST` to the built native executable
for C021. Replaying saved replies performs no provider dispatch. The independent
replay receipt records the actually verified scope and any remaining failures.

`frozen_replay_v4.json` verifies all twenty completed runs and thirty-five saved
replies. The earlier replay receipts record missing dependencies in the initial
sparse checkout; they are setup failures. `case_custody.json` verifies the 2,777
case rows and template against 2,503 distinct committed blobs. These results
establish scoped replay and custody, not successful solutions for every case.

For historical-source replay, prepare a clean detached checkout containing the
PFP package, the six sampled challenge directories, the matrix and C005 corpus,
Symbol Game, Providers, Governance, Operations, and Operating System dependencies.
Then run `python -m omega_engine_education.pfp.infrastructure.challenge_campaign.replay_snapshots --help`.
The command temporarily overlays only explicitly recorded, tracked source paths
in that disposable checkout, runs the saved-reply verifier, and restores them.

## Bounded implementation checks, 12 October 2026

[`validation/implementation_20261012/observations.json`](validation/implementation_20261012/observations.json)
preserves three genuine DeepSeek V3.2 responses and their exact requests, source
hashes and implementation commit. The C039 baseline used two stages: the first
reply had a fenced envelope; the second omitted the required case identifier
and certificate fields. Both were rejected. The existing typed-witness arm
returned a complete certificate accepted by both retained judges in one stage.
The three calls cost USD 0.004146. Offline replay reproduced all three outcomes
without provider calls. A mutated ground-state degeneracy was rejected by both
judges. This single development case does not establish comparative benefit or
close the challenge suite.

The new regression consumes these original response bytes through the existing
`grade` and isolated checker path. No additional source archives or receipt
framework were added. Earlier evidence remains byte-identical.

The same bounded check sampled C005, C011, C021, C039, C050 and C055 host fixtures;
all six were verified by their existing Python judges. This did not rerun the
native C021 checker. The frozen 2,500-row grid was reproduced exactly, and all 74
seed digests and 50 MSS-N catalog counterparts validated. Five of the six frozen
model IDs were absent from the live catalog at this check; only the recorded
Nemotron free ID remained listed. No frozen-grid trial was dispatched and no
model assignment was substituted. The full grid, unavailable mechanism hooks
and seed-specific mode/stage execution remain unfinished.
