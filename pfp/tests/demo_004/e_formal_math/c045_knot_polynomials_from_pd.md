# C045: Knot Polynomials from Planar-Diagram Codes

**AuthorityEffect:** None. **Status:** planned. **Domain:** e_formal_math. **Tier:** T2.
**Budget:** $0.50 billed inference per arm. **Models:** open weights, at most 70B total
parameters. **Protocol:** [SG-CP v1](../01_challenge_protocol.md).

## 1. Challenge

> Use the existing Symbol Game and models no larger than 70 billion parameters to produce a frozen module that computes exact Alexander and Jones polynomials from planar-diagram codes of knots with up to 14 crossings, invariant under relabelled and Reidemeister-moved diagrams, for under $0.50.

## 2. Why This Task

Computing the polynomials is not the hard part. A Kauffman-bracket state sum over 2¹⁴ states is small. The difficulty is correctness under conventions:

- PD orientation;
- crossing signs;
- the writhe normalisation of the bracket (Kauffman 1987);
- the normalisation of the Alexander polynomial;
- the mirror relation `V_mirror(t) = V(t⁻¹)`.

Each is a place where a plausible module is silently wrong, and the relabel and Reidemeister controls expose exactly those errors.

This stresses the Symbol Game's typed residuals when two computed invariants disagree across equivalent diagrams, the OEWAS (Omega Engine Workflows, Agents, Skills) workflow that separates parsing from evaluation, and the OEEIS (Omega Engine Epistemic Immune System) against overreach such as "Δ = 1, so unknot". A pass shows a correct convention-disciplined implementation. It does not show knot recognition.

## 3. Formal Problem and Bounds

Input is a PD code for a single-component knot diagram with `n ≤ 14` crossings. It uses the `X[i,j,k,l]` convention: the incoming under-strand is listed first, then the others counter-clockwise, and edge labels `1…2n` follow the orientation. `TASK.md` restates this convention with a worked example. Outputs:

- the writhe `w`;
- the Alexander polynomial `Δ(t)`, normalised so that `Δ(t) = Δ(t⁻¹)` and `Δ(1) = 1`;
- the Jones polynomial `V(t)`, normalised so that `V(unknot) = 1`, obtained from the Kauffman bracket with the writhe correction and the substitution fixed by the public examples.

Both polynomials are Laurent polynomials with integer coefficients, given as maps from exponent to coefficient.

Known values used in the public set are the trefoil's Alexander polynomial `t − 1 + t⁻¹` and the figure-eight knot's `Δ = −t + 3 − t⁻¹` and `V = t² − t + 1 − t⁻¹ + t⁻²`. Every hidden value comes from the second checker at packet-build time.

Edge cases the hidden set must contain:

- diagrams of the unknot with crossings;
- nontrivial 11-crossing knots with `Δ = 1` (the Conway and Kinoshita–Terasaka mutant pair);
- mutant pairs, which share Jones polynomials;
- diagrams with nugatory crossings;
- mirror pairs.

## 4. Deliverable and Output Contract

**Mode: frozen module.** `def solve(case: dict) -> dict` is synthesized by the model and makes no model calls at scoring. Coefficients are canonical integer strings. The figure-eight example below is regenerated by the second checker at packet-build time.

```json
{"case_id": "pd_ex_02", "pd": [[4,2,5,1],[8,6,1,5],[6,3,7,4],[2,7,3,8]]}
{"case_id": "pd_ex_02", "status": "SOLVED", "writhe": 0, "alexander": {"-1": "-1", "0": "3", "1": "-1"}, "jones": {"-2": "1", "-1": "-1", "0": "1", "1": "-1", "2": "1"}}
{"case_id": "pd_ex_09", "status": "OUT_OF_SCOPE", "witness": {"reason": "TWO_COMPONENTS", "component_edges": [[1, 2, 3, 4], [5, 6]]}}
{"case_id": "pd_ex_10", "status": "OUT_OF_SCOPE", "witness": {"reason": "EDGE_LABEL_MULTIPLICITY", "label": 7, "count": 3}}
{"case_id": "pd_ex_12", "status": "UNKNOWN", "code": "PARSE_AMBIGUITY"}
```

A complete answer gives exact equality of the writhe and both polynomials with the checkers' values. There is no short certificate here: verification is independent recomputation by two implementations. `OUT_OF_SCOPE` witnesses are recomputable, and there are four kinds:

- a label appearing other than twice;
- more than one component;
- a face count different from `n + 2` (non-planar);
- a crossing tuple inconsistent with the orientation.

## 5. Participant Packet

- `TASK.md` with the PD convention, a picture-free worked example of edge traversal, the normalisations and the JSON Schema.
- 12 public examples with exact input and output JSON: both trefoil chiralities; the figure-eight knot; an unknot with two nugatory crossings; a 5-crossing and a 7-crossing knot; a Reidemeister-moved trefoil; a relabelled figure-eight; a two-component input; a label-multiplicity error; a non-planar tuple set; one `UNKNOWN` example.
- `runner.py` and `accounting.json`.

## 6. Judge Packet

- **Hidden base:** 40 diagrams with 3 to 14 crossings, drawn from random braid closures and generated diagrams rather than published tables, including the `Δ = 1` pair and a mutant pair.
- **Relabel and gauge controls:** 20. Cyclic edge relabelling, orientation reversal (both polynomials are unchanged for knots), mirror images (the Jones polynomial must satisfy `V(t) ↦ V(t⁻¹)`), and R1, R2 and R3 moves applied by the operator. R1 changes the writhe but not the normalised polynomial.
- **Poisoned but schema-valid:** 8. Tuples rotated so that the under-strand is not first. That either changes the diagram or fails the orientation check, and the expected answer comes from the second checker. Also links presented as knots, `note` fields naming the wrong knot, and labels out of range.
- **Exact checker:** a Rust state-sum bracket implementation and an Alexander-matrix determinant computed with the Bareiss routine in `omega_engine/crates_rs/omega_linear_algebra/src/determinant.rs`, extended to polynomial entries.
- **Independent second checker:** a pinned external implementation (for example SnapPy or Sage), chosen and hashed at packet-build time.
- **Mutation suite:** the checker must reject, on a chiral knot, a Jones polynomial with `t` replaced by `t⁻¹` (the mirror answer), a bracket with no writhe correction, an Alexander polynomial off by a unit `±tᵏ`, a coefficient map with an extra zero entry (the non-canonical form is rejected by schema) and a Boolean writhe.

## 9. Pass Gates and Statistics

- **Capability gate:** in at least 2 of 3 seeds, all 40 base diagrams are exactly right, all 20 controls are consistent with their base, and no poisoned case gets `SOLVED`.
- **Primary metric (pre-registered):** base diagrams exactly right. The test is an exact McNemar test on paired (seed, case) rows for A vs B, A vs C and A vs D, with Holm correction at α = 0.05.
- **Reported separately:** control consistency, broken down by control type.
- **Seeds:** 3.

## 10. Interpretation

Most failures should be convention errors, so the per-control breakdown matters more than the headline:

- mirror failures point to the substitution;
- R1 failures point to the writhe;
- reversal failures point to orientation parsing.

If A fixes these faster than B, it shows the value of typed residuals, for example "R1 control disagrees by factor `−A³`". If A ties D, repeated sampling found a correct convention by chance as often as structured repair did.

## 11. OEEIS, Attention, Logit and Scratch-Space Hooks

The catalog declares no OEEIS hook. Observed mechanisms:

- **Thymus-style self panel.** The public diagrams with known polynomials act as a self panel; a candidate module that fails any of them is discarded before hidden use. This follows the pattern of `ThymusGate` but is not wired to it.
- **Danger gate.** Signal 1 is a `note` naming a knot; Signal 2 is a disagreement between the module's answer and its own relabelled recomputation.
- **Expected antimorphisms:**
  - AM-5 (global sign inversion, here the mirror image);
  - AM-FSP-2 (an out-of-scope witness that does not recompute);
  - AM-2 (knot identification claims).
- **Layer 2:** a grammar mask for exponent and coefficient maps, via `carrier_gbnf` (unwired).
- **Layer 1:** not applicable.
- **Scratch space:** the host stores per-control disagreement factors (for example, a ratio of brackets) as scratch data for the repair prompt.

## 12. Run Folder, DDC Trace and Operand Mining

Expected Discrete Deformation Calculus (DDC) pattern: `C` (convention and examples exposed), `I` (parser and state sum), `R` (public or self-control disagreement), `D` steps, `Λ` when orientation handling is lifted into its own sub-turn, `E`, `T`. The `ObstructionScore` sets Φ₁ to the number of public examples wrong and `active_count` to relabel self-controls that disagree; Γ₂ is unused (0).

Operands to mine:

- parse the PD code into an oriented traversal first, then assign crossing signs from the traversal;
- test the mirror and R1 invariance on public examples before any hidden use;
- normalise Δ by symmetry and `Δ(1) = 1` as the last step;
- never infer knot type from a polynomial.
