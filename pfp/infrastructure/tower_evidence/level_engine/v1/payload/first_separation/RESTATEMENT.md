# Restatement: `first_separation`

AuthorityEffect: None.

Class of the challenge: externally imposed challenge. It is answered in this
harness, outside the sealed repository, and it is not attributed to the seed.

## Obligation

The first response to the first imposed separation adds exactly one form and
one instance, and the replayed history keeps the initial inscription. A
presented response that drops the kept inscription is refused.

## Refused case

A presented response without the kept inscription is refused.

## Supplied objects and terms

| name | class | what it is |
| --- | --- | --- |
| separation | externally imposed challenge | the sealed challenge that asks two admitted data to be told apart |
| reading | supplied object-language datum | the two admission readings, carried as two lineages |
| shape | proved theorem | one form and one instance; cost two is minimal (sealed Lean) |
| source_kept | metatheory apparatus | decided on the replayed history |
| pairing | optional realization | the declared order form, then instance |

## Notes

The sealed bounded search is re-run at the sealed bounds for both readings and
both measures, beside the engine's own search. Under the item-count measure the
minimum is tied (three classes in one reading, five in the other); under the
arity-refined measure it is one class in each. Every class is presented as the
same packet, so ties are lost in the presentation and the loss ledger books it.
