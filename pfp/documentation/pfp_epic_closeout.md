## Use the finite consumers

The existing canonical CLI exposes the host-pinned patch checker:

```powershell
pfp code-change-check-source-bound --packet packet.json --patch-bytes candidate.diff --source-root C:/reviewed/source --source-path src/x.py --checker-binary C:/trusted/omega_symbol_game.exe --checker-sha256 <trusted-release-sha256> --run-id review-001 --attempt-id attempt-0 --max-native-calls 3 --output new-check.json --replay-check
```

`packet.json` is the existing CodeChange `PacketEnvelopeV2`. The operator selects
the trusted executable digest and source bytes; a model reply cannot select its
own authority. This one-attempt command makes three native calls and zero provider
calls; inline replay makes zero calls. PASS exits 0; FAIL/REFUSED exits 2, retaining
diagnostics. Output must be new. The compatibility `symbol-game` command is the
same consumer. The API supports bounded same-instance continuation; saved JSON
does not authenticate a new process or establish patch applicability.

For the Level Engine, inject `FiniteLevelEngineConsumer.judge` into the existing
`CheckPfpTaskTurnUseCase` judge port with `require_checker=True`. Its only current
challenge is `edge_endpoints`, with host-selected protected pairs. The candidate
verdict and fixture calibration are separate: a protected-edge violation rejects
even when fixtures replay correctly. The ordinary `check-task` CLI does not
implicitly install that judge. Missing pins/resources remain explicit refusals.
