# OEWAS Level 00: Coloured Operad Architecture — Finite Colours, Signatures & Units

**AuthorityEffect:** None. Complete mathematical and architectural reference for the 10-Coloured Operad, colour signatures, and unit operations; no operational authorization is conferred.

---

## 1. Executive Intuition: Why Multi-Agent Systems Require Coloured Operads

In standard agentic frameworks, multi-agent communication is treated as unstructured natural-language message passing over untyped JSON sockets. This architectural choice leads to five critical failure modes:

1. **Semantic Type Leakage:** An agent expecting verified mathematical proof terms receives ungrounded prose or speculative code comments.
2. **Arity Drift:** Operations accept arbitrary variadic parameters, rendering composability and static dependency graphs undecidable.
3. **Un-Recomputed Bindings:** Agent $B$ consumes outdated evidence generated by Agent $A$ without re-evaluating whether the underlying artifact was modified.
4. **Authority Laundering:** A downstream agent treats an unverified proposal as an admitted fact simply because an upstream LLM formatted it nicely.
5. **Autoimmune Cascades:** Agents endlessly critique and revise each other's outputs without contracting the underlying residual error.

In the Anomalon Engine, all multi-agent interactions are governed by a **Symmetric Coloured Operad** (or multicategory) $(\mathcal{O}, \circ)$. An operad formalizes operations with multiple typed inputs and a single typed output, equipped with associative partial composition $\circ_i$ and identity units.

## 3. Mathematical Foundations: Coloured Multicategories & Operads

Formally, a **Coloured Operad** $\mathcal{O}$ over the set of colours $\mathcal{C}$ consists of:

1. **Colours:** A finite set $\mathcal{C} = \mathcal{C}_{10}$.
2. **Operation Sets:** For every sequence of source colours $(c_1, \ldots, c_k) \in \mathcal{C}^k$ ($k \ge 0$) and target colour $c \in \mathcal{C}$, a set of operations:
   $$\mathcal{O}(c_1, \ldots, c_k;\, c)$$
   When $k = 0$, the operation is *nullary* (a constant). When $k = 1$, it is a standard unary endomorphism or morphism. When $k \ge 2$, it represents multi-agent multi-input synthesis.
3. **Identity Units:** For each colour $c \in \mathcal{C}$, an identity morphism:
   $$\mathrm{id}_c \in \mathcal{O}(c;\, c)$$
4. **Partial Composition Operators:** For $f \in \mathcal{O}(c_1, \ldots, c_k;\, c)$ and $g \in \mathcal{O}(d_1, \ldots, d_m;\, c_i)$ with $1 \le i \le k$, a composition:
   $$f \circ_i g \in \mathcal{O}(c_1, \ldots, c_{i-1},\, d_1, \ldots, d_m,\, c_{i+1}, \ldots, c_k;\, c)$$
   splicing the inputs of $g$ into the $i$-th input slot of $f$.

## 4. Code Implementation Walkthrough

The core domain value objects live in [`omega_engine_operads/domain/operad/`](../../../../omega_engine_operads/domain/operad/):

### 4.1 Value Objects: `Colour` and `ColourSignature`

In [`colours.py`](../../../../omega_engine_operads/domain/operad/colours.py#L38-L92):

```python
@dataclass(frozen=True)
class Colour:
    """Strongly-typed colour object for the operad."""
    name: str

    def __post_init__(self) -> None:
        if not isinstance(self.name, str) or not self.name.strip():
            raise ValueError("Colour name must be a non-empty string.")
        if self.name not in ADMITTED_FINITE_COLOURS:
            raise ValueError(f"Colour '{self.name}' not in admitted finite colours: {ADMITTED_FINITE_COLOURS}")

@dataclass(frozen=True)
class ColourSignature:
    """Operadic signature specifying source colours and single target colour."""
    source: tuple[Colour, ...]
    target: Colour

    def __init__(self, source: Sequence[Colour | str], target: Colour | str) -> None:
        src_colours = tuple(c if isinstance(c, Colour) else Colour(str(c)) for c in source)
        tgt_colour = target if isinstance(target, Colour) else Colour(str(target))
        object.__setattr__(self, "source", src_colours)
        object.__setattr__(self, "target", tgt_colour)

    @property
    def arity(self) -> int:
        return len(self.source)
```

### 4.2 Derived Arity Invariant

A common bug in multi-agent registries is declaring an arity integer that disagrees with the actual number of source arguments (e.g., claiming arity 2 while supplying 3 inputs). In OEWAS:

$$\boxed{\text{arity}(f) \equiv \operatorname{len}(\text{source}(f))}$$

Arity is strictly a derived property. It is impossible for an `OperationSignature` or `ColourSignature` to disagree with its own source tuple.

```python
def ensure_units(self) -> list[str]:
    """Ensures that every admitted colour C has an identity operation id_C: C -> C."""
    added = []
    for c_name in sorted(self._colours):
        unit_op = OperationSignature.unit(c_name)
        if unit_op.op_id.value not in self._operations:
            self._operations[unit_op.op_id.value] = unit_op
            added.append(unit_op.op_id.value)
    return added
```

`id_State`, `id_Proof`, `id_Paper`, `id_Code`, `id_Contract`, `id_Receipt`, `id_Ledger`, `id_Diagram`, `id_Audit`, `id_Post`.

## 5. Equivariance and Residual Effects

Each `OperationSignature` carries two metadata fields:

```python
@dataclass(frozen=True)
class OperationSignature:
    op_id: OperationId
    signature: ColourSignature
    equivariant: bool = False
    residual_effect: str = "unknown"
```

1. **Equivariance (`equivariant: bool`):**
   Indicates whether the operation commutes with symmetric group permutations of its input arguments:
   $$f(\sigma(x_1, \ldots, x_k)) = f(x_1, \ldots, x_k) \quad \forall \sigma \in S_k$$
   For symmetric red-teaming review (where the order of submitted papers or code modules does not alter the audit defect score), `equivariant = True`.
2. **Residual Effect (`residual_effect: str`):**
   Tracks the expected impact of the operation on the defect potential $\Phi$. Admitted values include:
   - `"identity"`: Preserves input state without mutation.
   - `"contractive"`: Strictly decreases residual defect ($\Delta \Phi < 0$).
   - `"neutral"`: Preserves defect norm ($\Delta \Phi = 0$).
   - `"diagnostic"`: Probes and computes defect without altering the primary artifact.

It synthesizes them into an adversarial diagnostic record (`Audit`), which can then be spliced into a downstream receipt builder (`meta-paper--receipt--contractive`) via partial composition $\circ_0$.

### The Level 00 Governance Invariants
- **INV-00-01 (Vocabulary Closure):** No runtime component may define or ingest a colour not present in `ADMITTED_FINITE_COLOURS`.
- **INV-00-02 (Derived Arity):** Arity must never be passed as an independent constructor argument; it is strictly computed as `len(source)`.
- **INV-00-03 (Unit Totality):** Every registered operad instance must contain all 10 identity units.
- **INV-00-04 (Authority Ceiling):** All operadic representations enforce `AuthorityEffect: None`.
