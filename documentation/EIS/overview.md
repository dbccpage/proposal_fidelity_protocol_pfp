## 1. Executive Overview: Code-Grounded Reality vs. Docstring Aspiration

The Epistemic Immune System (EIS) is a defense-in-depth verification harness designed to screen, isolate, and refuse defective, unverified, or self-certified outputs generated by large language models (LLMs) or automated reasoning agents.

In literature and design comments across the codebase, the system is described with extensive biological metaphors. However, inspection of the executable source code across both Rust and Python reveals a concrete state machine and cryptographic verification system:

1. **What comments sometimes suggest:** An autonomous, self-evolving organism that independently learns, adapts, and immunizes the software estate against arbitrary hallucination.
2. **What the code actually implements:**
   - A deterministic Four-Gate state machine (`Proposed` $\to$ `Candidate` $\to$ `Admitted` $\to$ `Suspended` / `Retired`).
   - A fail-closed negative selection screen (`ThymusGate`) that matches candidate regular expressions against a sealed panel of clean strings, terminating any pattern that exhibits self-reactivity.
   - An Ed25519 cryptographic attestation system (`authenticated.rs`) that verifies external human or operator policy signatures before any detector can enter active evaluation.
   - A Two-Signal Danger Gate (`TwoSignalDangerGate`) requiring the strict conjunction of a pattern match (Signal 1) with an orthogonal, host-observed execution defect (Signal 2) while explicitly rejecting single-signal triggers and detecting `TWO_SIGNAL_COLLAPSE`.
   - Exact rational accounting for false discovery proportions (`TregSupervisor`) utilizing `num_rational::Ratio` and `num_bigint::BigUint` to prevent floating-point rounding errors.

Across every struct, function, schema, and receipt, the codebase strictly enforces `AuthorityEffect: None`. The immune system possesses no administrative capabilities, cannot modify repo permissions, and cannot promote its own candidate rules to sovereign authority.

## 2. Core Epistemic Philosophy

### 2.1 The Biological Immune Metaphor
The system draws direct structural analogies to vertebrate adaptive and innate immunology, specifically adapting Polly Matzinger's Danger Theory:

```
Biological Organism                       Epistemic Immune System (EIS)
─────────────────────────────────────────────────────────────────────────────
Pathogen / Epitope                   ──► Epistemic Defect / Hallucinated Pattern
Thymic Negative Selection (Central)  ──► ThymusGate Sealed Self-Panel Screen
Circulating Mature Naive B/T Cell    ──► Candidate Anti-Skill Detector
Antigen Binding (Signal 1)           ──► Regex / AST Pattern Match on Output
Tissue Damage / Danger (Signal 2)    ──► Host Sensor Damage (Non-zero gap, float)
Clonal Selection & Somatic Mutation  ──► Detector idle-decay & mutation tracking
Regulatory T-Cells (Treg)            ──► TregSupervisor false-discovery suspension
Self-Tolerance / Autoimmunity Avoid. ──► Apoptosis on clean reference self-fixtures
```

### 2.2 Classical Self/Non-Self vs. Matzinger Danger Theory
Under classical immunological models (Burnet/Medawar), an immune system attacks anything recognized as "foreign" (non-self). In automated LLM evaluation, treating every novel, uncatalogued pattern as defective results in severe over-blocking and false-positive cascades.

EIS implements Matzinger's Danger Model:
- **Foreignness alone does not trigger defensive suppression:** A novel pattern match (Signal 1) without evidence of host damage remains purely diagnostic (`DIAGNOSTIC_ONLY` / `HoldUncorroborated`).
- **Damage alone does not trigger learned guard suppression:** A host error (e.g., test regression or syntax error) without an epitope match is handled directly by the specific host check, not by learned immune lockdown.
- **Activation requires conjunction:** Defensive lockdown (`QUARANTINED` or `DEFENSIVE_LOCKDOWN`) activates if and only if both Signal 1 and Signal 2 coincide on the same subject through independent observation paths.

### 2.3 Zero-Authority Containment (`AuthorityEffect: None`)
A central failure mode of multi-agent cognitive systems is "authority escalation"—an automated agent declaring its own output verified, creating synthetic certificates, or modifying screening parameters. 

EIS counters this through constitutional immutability:
1. **Unconditional Neutrality:** Every data envelope (`AntiSkillSpecV2`, `AdmissionReceiptV1`, `DangerSignalReceiptV1`, `GuardActivationReceiptV1`) hardcodes `authority_effect = "None"`.
2. **No Constructor Bypasses:** In Rust (`anti_skill.rs`), `AntiSkillSpecV2::propose(...)` deliberately lacks any constructor parameter for status. It unconditionally sets `status = AntiSkillStatus::Proposed`.
3. **External Cryptographic Fences:** Elevation from `Candidate` to `Admitted` requires an Ed25519 signature from a public key declared in a statically verified `TrustPolicy`. Candidate detectors cannot admit themselves.

## 4. Concrete Invariants and Cross-Language Contracts

The Epistemic Immune System enforces three primary constitutional invariants that cannot be relaxed by runtime configuration:

### Invariant IMMUNE-001: Unconditional `Proposed` Status
- **Location:** `code/rust/core_epistemic_immune_system/src/anti_skill.rs` (lines 76–108).
- **Rule:** When a newly harvested defect motif is instantiated via `AntiSkillSpecV2::propose(...)`, its status is unconditionally assigned to `AntiSkillStatus::Proposed`.
- **Enforcement:** The constructor does not accept a status argument. The only transitions out of `Proposed` require passing `ThymusGate::screen` (advancing to `Candidate`) and external admission verification (advancing to `Admitted`).

### Invariant IMMUNE-002: Strict Two-Signal Conjunction
- **Location:** `code/rust/core_epistemic_immune_system/src/danger_gate.rs` (lines 53–99) and `eis/domain/danger_gate.py` (lines 111–182).
- **Rule:** A defensive finding or refusal is emitted if and only if:
  $$\text{externally\_admitted}(g) \land \text{detector\_match}(g, \text{subject}) \land \text{independent\_danger}(\text{subject}) \land \neg\text{suspended}(g)$$
- **Enforcement:** If Signal 1 matches without Signal 2, the evaluator returns `DangerGateVerdict::HoldUncorroborated` or `DangerDecision::DIAGNOSTIC_ONLY`. Counting Signal 1 as its own Signal 2 raises `TWO_SIGNAL_COLLAPSE`.

### Invariant PHARMACY-001: Signed External Admission Fence
- **Location:** `code/rust/core_epistemic_immune_system/src/authenticated.rs` (lines 353–376).
- **Rule:** An anti-skill cannot transition from `Candidate` to `Admitted` through automated model self-selection.
- **Enforcement:** Transition requires a verified `Attestation` carrying an Ed25519 signature from an authorized key declared in `TrustPolicy`.

### L4 Production Boundary Isolation
In the Rust engine, every critical module (`lib.rs`, `anti_skill.rs`, `thymus.rs`, `danger_gate.rs`, `formulary.rs`, `authenticated.rs`, `admission.rs`, `regulation.rs`, `clonal_selection.rs`, `independence.rs`, `activation.rs`) contains an isolated `BoundaryRecord*` struct with static invariants:
- `admitted_items >= 1`
- `capacity_bound >= 1`
- `admitted_items <= capacity_bound`

These boundary records verify that memory allocations and queue operations remain bounded within declared limits, preventing unbounded growth during adversarial fuzzing.

## 5. Artifact Claim Hygiene Summary

In strict adherence to the Claim Hygiene Rule, the claims supported by this architecture are formally bounded:

### 1. What the code supports:
- Demonstrates a typed, fail-closed negative selection mechanism (`ThymusGate`) that purges self-reactive regex patterns against a sealed reference panel.
- Demonstrates a Two-Signal Danger Gate in Rust and Python that refuses single-signal activations and detects `TWO_SIGNAL_COLLAPSE` when Signal 2 is derived from Signal 1.
- Demonstrates an Ed25519 cryptographic attestation system verifying external signatures before admitting candidate anti-skills.
- Demonstrates exact rational calculation of false discovery proportions (`Ratio<u64>`), avoiding floating-point rounding errors.
- Provides 58 executable pharmacy records, 37 authored YAML specifications, and 1,069 candidate catalog entries.

### 2. What the code does NOT support:
- Does not demonstrate that automated defect detection ensures error-free reasoning or eliminates model hallucination.
- Does not demonstrate that passing the Thymus self-panel shows that an anti-skill has zero false positives on unseen inputs.
- Does not confer execution, administrative, or repo-mutation authority to any output (`AuthorityEffect: None`).
- Does not autonomously admit candidate detectors without external operator signatures.

### 3. The narrowest defensible claim:
In this toy and laboratory setting, the Epistemic Immune System provides a deterministic, zero-authority containment envelope that enforces negative selection against reference fixtures, gates defensive actions on independent host damage signals, and requires cryptographic admission receipts for rule activation.

### 4. The next test needed:
An automated adversarial mutation test in Rust executing randomized regex patterns against `ThymusGate::standard_baseline()` to measure whether pattern compilation or screening timeouts can be induced by pathological backtracking inputs.
