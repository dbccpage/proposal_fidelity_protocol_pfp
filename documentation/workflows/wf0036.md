## 1. Objective & Purpose

WF36 refines staged packet workflows (WF8) by introducing a **complete admission guard** between intermediate stages. In multi-stage reasoning, if Stage 1 emits incomplete, corrupted, or underdetermined slot specifications, passing these flawed slots to Stage 2 causes cascading hallucinations and wastes downstream inference budgets.

WF36 enforces that Stage 2 is never dispatched unless Stage 1 satisfies a complete mathematical syndrome check. If the guard fails after a single bounded retry, the workflow cleanly **abstains** (`EPISTEMIC_ABSTENTION`), preventing false-green admissions.

---

## 2. Process Specification

1. **Stage 1 (Slot Materialization):** The model emits typed slot assignments (e.g. spanning tree potentials, cycle chord labels, carrier definitions).
2. **The Guard Gate:** The host evaluates a complete algebraic syndrome check $r^* = S c$ on the materialized slots.
   - If the guard passes: The slots are frozen and sealed; Stage 2 is dispatched.
   - If the guard fails: The model is granted exactly one retry with the specific syndrome residual.
3. **Abstention Policy:** If the guard fails the second attempt, execution halts immediately with status `GUARDED_STAGE_ABSTENTION`. Stage 2 is not invoked.
4. **Stage 2 (Chord Evaluation):** Downstream solver evaluates remaining cycle chords against the guarded tree basis.
5. **Dichotomic Guarding:** Enforces a dichotomic check that eliminates the "lazy false-refusal" attractor (where models emit empty refusal codes to trivially avoid failure).

---

## 3. Mathematical Model & Complete Syndrome Guarding

- **Syndrome Vector Invariant:**
  Let $S$ denote the parity-check or coboundary matrix:
  $$r^* = S \cdot c$$
  The guard evaluates whether $r^*$ is contained within the admissible subspace:
  $$\operatorname{Guard}(c) \iff S \cdot c == 0$$
- **Elimination of the False-Green Kernel:**
  A partial guard (checking only a subset of rows of $S$) leaves a non-trivial kernel $\ker(S_{\text{partial}}) \supsetneq \{0\}$, allowing corrupted slots to slip through to Stage 2. WF36 requires $S$ to have full rank over the constraint space.
- **Tree-Then-Chord Two-Stage Split:**
  For a graph with cycle rank $\beta_1 = |E| - |V| + 1$:
  - Stage 1 materializes potentials on spanning tree $T$ ($|V| - 1$ edges, zero cycles).
  - Stage 2 evaluates the $\beta_1$ chord edges.

## 4. Team Structure & Panel Roles

- **Pattern:** `relay`
- **Normal Path Calls:** 2 stages (plus at most 1 guard retry).
- **Roles:**
  - `coder` (Sonnet, count: $1$): Formulates the Stage 1 slot materialization and Stage 2 chord evaluation.
  - `deep_researcher` (Opus, count: $1$): Designs the syndrome matrix $S$ and tree-chord decomposition.
  - `host_checker` (None, count: $1$): Deterministic host cochain and syndrome verifier.
- **Boost Rule:** If the guard fails, exactly one retry is permitted; if that retry fails, the pipeline halts and cleanly abstains (limit 1).

---

## 5. Host Verification Protocol

- **Exact Cochain Evaluation:** Computes the syndrome vector $r^*$ in exact integer arithmetic.
- **Strict Gating:** Stage 2 prompts are generated programmatically by the host only upon receipt of a passing Stage 1 guard receipt.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Empirical ladder trials confirm that complete guarding eliminates downstream hallucination by aborting runs early when Stage 1 fails.
2. **What the Evidence Does Not Support:**
   - Guarded staging does not increase raw model knowledge; it acts as an epistemic filter that lowers total answers in exchange for high precision.
3. **Narrowest Defensible Claim:**
   - WF36 implements an exact syndrome guard between execution stages that prevents downstream propagation of flawed slot materializations by enforcing clean abstention.
