## 1. Objective & Purpose

WF9 establishes a strictly bounded iterative repair loop. When a candidate proposal is rejected by the deterministic host checker, the host returns **only a typed mathematical residual** (e.g. the non-zero coboundary syndrome or cycle parity failure), never the ground-truth answer. The model is permitted at most $L$ attempts to converge to a valid proposal.

WF9 enforces strict cost and attempt ceilings, preventing runaway API loops and ensuring that every retry is accounted in the durable ledger.

---

## 2. Process Specification

1. **Initial Proposal:** The model emits an initial candidate solution under the declared task schema.
2. **Deterministic Evaluation:** The host checker grades the candidate.
   - If accepted: The run terminates immediately with status `HOST_ACCEPTED`.
   - If rejected: The host computes the exact residual vector $r$.
3. **Bounded Repair Loop (Attempts $1 \dots L$):**
   - If the attempt count is less than $L$: The host injects $r$ into the prompt context for the next repair attempt.
   - The model emits a revised proposal.
   - The host re-evaluates the revised candidate.
4. **Terminal Halt:** The loop halts upon the first accepted proposal or when reaching the bound $L$. If $L$ is reached without acceptance, the status terminates as `REPAIR_BUDGET_EXHAUSTED`.

---

## 3. Mathematical Model & Least-Cost Repair

- **XOR Cycle Consistency Condition:**
  In an edge-labeled graph with labels $c \in \{0, 1\}^E$, a consistent potential assignment exists if and only if the sum of edge labels around every cycle $C$ is even:
  $$\sum_{e \in C} c(e) \equiv 0 \pmod 2$$
- **Minimal Perturbation Repair Formulation:**
  When a cycle is inconsistent, the model must find a minimal perturbation vector $\Delta \in \{0, 1\}^E$:
  $$\min_{\Delta} \|\Delta\|_1 \quad \text{subject to } c \oplus \Delta \in \operatorname{im}(\delta_0)$$
  where $\delta_0$ is the vertex-to-edge coboundary operator over $\mathbb{F}_2$.
- **Strict Termination Bound:**
  $$\text{Total Attempts} \le L < \infty, \quad \text{Total Cost} \le \text{Budget Ceiling}$$

## 4. Team Structure & Panel Roles

- **Pattern:** `proposer_with_residual_feedback`
- **Normal Path Calls:** $1 \dots L$ attempts.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Formulates the initial proposal and applies repairs based on typed residual feedback.
  - `host_checker` (None, count: $1$): Deterministic host verifier; evaluates parity or coboundary conditions and computes exact residuals.
- **Boost Rule:** If two consecutive repair attempts are rejected, a final escalation attempt is dispatched to Opus carrying the full residual history (limit 1).

---

## 5. Host Verification Protocol

- **Information Restriction:** The host feedback sent to the model must be strictly answer-free:
  $$\text{Feedback} = \text{ExtractResidual}(\operatorname{check}(r))$$
  Injecting the correct answer or scalar hints is strictly forbidden.
- **Host Check:** Evaluates whether $c \oplus \Delta$ has zero defect and verifies that $\|\Delta\|_1$ is minimal among declared valid repairs.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Pilot 26 and 49 confirm that bounded repair loops can be deterministically simulated and accounted without exceeding pre-allocated limits.
2. **What the Evidence Does Not Support:**
   - Repair loops do not guarantee monotonic descent in defect for general language models unless paired with explicit rejection filtering.
3. **Narrowest Defensible Claim:**
   - WF9 specifies an accounted iterative repair harness that supplies typed mathematical residuals to a proposer under a hard termination bound.
4. **Next Test Needed:**
   - Benchmark WF9 on 30 frustrated graph cycles with $L = 3$, comparing repair success rates between raw residual feedback and natural language error messages.
