## 1. Objective & Purpose

WF30 addresses the challenge of **data contamination and memorized recitation** in benchmark evaluation. Language models frequently regurgitate standard textbook solutions (e.g. Knuth's optimal 16-input sorting network, standard Dijkstra implementations) without engaging in genuine problem solving.

WF30 injects **forcing constraints** that invalidate textbook memorization while preserving the underlying mathematical problem. For example:
- Forcing a non-standard first comparator step.
- Forbidding specific canonical intermediate wires.
- Inverting parity or sorting conventions.

---

## 2. Process Specification

1. **Canonical Problem Formulation:** Identify a problem domain with prominent textbook solutions (e.g. sorting networks, minimal spanning trees, planar embeddings).
2. **Constraint Injection:** Inject explicit negative and positive constraints:
   - Positive constraint: "The network must begin with comparator $[0, 3]$."
   - Negative constraint: "No comparator may connect wires $[1, 2]$."
3. **Model Turn:** The model outputs a candidate circuit or algorithm satisfying the forced constraints.
4. **Exact Property Verification:** The host evaluates the candidate against formal mathematical invariants (e.g. the 0-1 sorting principle).
5. **Recitation Audit:** If the model emits the verbatim textbook network (ignoring the injected constraints), it is flagged as `RECITATION_FAILURE`.

---

## 3. Mathematical Model & The Zero-One Principle

- **The Zero-One Sorting Principle:**
  A comparator network $\mathcal{C}$ on $n$ wires sorts arbitrary inputs if and only if it correctly sorts all $2^n$ binary input vectors:
  $$\forall x \in \{0, 1\}^n, \quad \mathcal{C}(x)_1 \le \mathcal{C}(x)_2 \le \dots \le \mathcal{C}(x)_n$$
- **Recitation Separation Invariant:**
  Let $\mathcal{C}_{\text{textbook}}$ be the canonical memorized network and $K$ be the set of forced constraints:
  $$\mathcal{C}_{\text{textbook}} \not\models K$$
  A model that recites the standard solution fails the host pre-check:
  $$\operatorname{ValidSolution}(\mathcal{C}) \iff (\mathcal{C} \models K) \land \left(\forall x \in \{0, 1\}^n, \ \operatorname{sorted}(\mathcal{C}(x))\right)$$

## 4. Team Structure & Panel Roles

- **Pattern:** `solo`
- **Normal Path Calls:** 1 call.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Formulates the candidate circuit or algorithm respecting forced constraints.
  - `adversary` (Fable, count: $1$): Identifies standard memorized textbook networks and synthesizes minimal forcing constraints to break them.
  - `host_checker` (None, count: $1$): Deterministic host property checker (evaluates 0-1 principle over all $2^n$ binary vectors).
- **Boost Rule:** None; reciting a memorized answer is treated as a definitive empirical finding rather than an authorized retry condition (limit 0).

---

## 5. Host Verification Protocol

- **Exhaustive Binary Check:** For sorting networks up to $n = 16$, the host simulates the network across all $2^n$ binary inputs in parallel.
- **Immediate Rejection:** Any comparator violating the forbidden list or missing the forced prefix triggers an immediate `CONSTRAINT_FORCING_VIOLATION`.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Empirical findings in Challenge C057 show that 70B and 8B models recite canonical sorting networks and fail completely when standard comparator pairs are forbidden.
2. **What the Evidence Does Not Support:**
   - Passing a forced constraint test does not prove that an algorithm generalizes to infinite input spaces.
3. **Narrowest Defensible Claim:**
   - WF30 provides a methodology to separate memorized recitation from active constraint satisfaction by injecting verified forcing conditions that break canonical textbook solutions.
4. **Next Test Needed:**
   - Test 5 frontier models on 6-wire sorting networks with 3 randomized forbidden comparator constraints, evaluating compliance against the 0-1 principle.
