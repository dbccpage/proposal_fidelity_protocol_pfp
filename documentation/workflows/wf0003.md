## 1. Objective & Architectural Role

WF3 introduces a staged two-step relay architecture:
1. **Stage 1 (Mining):** A dedicated mining turn extracts reusable typed operad operations and Level-2 (L2) structural guidance from the seed prompt without calculating the task answer.
2. **Stage 2 (Solving):** The verified, frozen mining output is attached as public task context for the solver turn.

The central design imperative of WF3 is **answer-free leak suppression**. The mining prompt explicitly prohibits computing intermediate arithmetic or output totals. The host enforces this prohibition through an automated textual digit screening audit that rejects any mining output containing decimal digits outside literal source quotes.

## 3. Strict Leakage Suppression: The Digit Screen

To guarantee that structural guidance does not leak answers to the downstream solver, `screen_mining()` executes a recursive digit scan (`pfp/workflows/wf0003/workflow.py`):

```python
def text_screen(value, path=()):
    if type(value) is str and path[-2:] != ("source", "quote") and re.search(r"\d", value):
        errors.append("NUMERICAL_GUIDANCE_FORBIDDEN:" + "/".join(map(str, path)))
    elif type(value) is dict:
        for key, item in value.items():
            text_screen(item, (*path, key))
    elif type(value) is list:
        for index, item in enumerate(value):
            text_screen(item, (*path, index))
```

### Screening Rules
1. **Forbidden Digits:** Any decimal digit `0..9` found in free-text fields (such as operation descriptions, guidance sentences, or slot notes) triggers an immediate `NUMERICAL_GUIDANCE_FORBIDDEN` error.
2. **Exemptions:** Decimal digits are permitted only within:
   - `op["arity"]` (which must be an integer).
   - `op["source"]["quote"]` (literal substrings quoted from `seed_prompt` or `input_json`).
3. **No Fallback Rule:** If Stage 1 fails screening, the workflow immediately refuses execution (`WF3_MINING_NOT_SCREENED`). It is strictly forbidden to fall back silently to an unassisted WF1 run.

## 4. Frozen Mined Attachment (`pfp.wf3.mined-attachment.v1`)

Upon passing screening, the host freezes the candidate operads and L2 guidance into an immutable bundle:
```json
{
  "schema": "pfp.wf3.mined-attachment.v1",
  "sha256": "8d3c1...",
  "payload": {
    "operads": [
      {
        "id": "sum",
        "arity": 1,
        "source_colours": ["IntegerList"],
        "target_colour": "Integer",
        "source": { "kind": "seed_prompt", "quote": "Calculate the exact sum" }
      }
    ],
    "l2_guidance": [
      { "slot": "concrete_spans", "instruction": "Locate input.values" },
      { "slot": "parameter_bindings", "instruction": "Bind signed integers" },
      { "slot": "instantiated_arguments", "instruction": "Pass values to sum operad" },
      { "slot": "preservation_obligations", "instruction": "Exact arithmetic with no rounding" }
    ]
  }
}
```

The attachment's SHA-256 digest is injected into the Stage 2 task context. The solver's response schema is dynamically configured to require the exact operad IDs declared in the attachment.

## 5. Offline Replay & Dual Manifests

WF3 run directories contain two independent execution trees:
- `mining/`: Contains `task.json`, `prepared.json`, `response.raw`, `receipt.json`, and `receipt_manifest.json`.
- `solver/`: Contains `task.json` (with attachment), `prepared.json`, `response.raw`, `receipt.json`, and `receipt_manifest.json`.

Running `pfp-wf3 replay <dir>` independently replays both stages:
1. Re-verifies all hashes in `mining/receipt_manifest.json`.
2. Re-runs `screen_mining` against `mining/response.raw`.
3. Re-verifies that `solver/task.json` contains the exact frozen attachment produced by Stage 1.
4. Re-runs `integer_sum_judge` against `solver/response.raw`.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - The recursive digit screen mechanically enforces that Stage 1 cannot pass scalar integers to Stage 2 outside literal quotes.
   - Segregating structural mining from task solving is fully implemented and replayable.
2. **What the Evidence Does Not Support:**
   - Pre-mining does not guarantee that the downstream solver will execute the mined operad correctly.
3. **Narrowest Defensible Claim:**
   - WF3 implements a two-stage relay that extracts candidate operads and structural guidance while mechanically verifying the absence of ungrounded numeric answer leakage before solver dispatch.
4. **Next Test Needed:**
   - Test whether adversarial miner prompts attempting to spell out numbers in words (e.g. "forty-two") can be caught by an expanded lexical dictionary filter.
