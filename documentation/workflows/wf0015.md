## 1. Objective & Purpose

WF15 structures mathematical claim evaluation as an adversarial dialectic between two opposing roles: a **Prosecutor** (tasked with finding countermodels and edge-case failures) and a **Defender** (tasked with finding proofs and witnesses).

The governing principle of WF15 is that **rhetoric is not evidence**. Persuasive prose, conversational eloquence, and citations carry zero weight. Both submissions are frozen in isolation before seeing each other, and the tribunal verdict is rendered exclusively by a deterministic host model checker that evaluates the formal artifacts emitted by each side.

---

## 2. Process Specification

1. **Independent Formulation:** The Prosecutor and Defender receive the initial claim simultaneously.
2. **Double-Blind Freezing:**
   - The Prosecutor outputs an attack packet (countermodel or edge perturbation) under SHA-256 seal.
   - The Defender outputs a defense packet (formal witness or invariant proof) under SHA-256 seal.
   - Neither side is permitted to observe the other's submission before both are permanently frozen.
3. **Structured Encoding:** A coder agent parses both submissions into the formal input grammar of the host model checker.
4. **Deterministic Host Adjudication:** The host evaluates the formal claims against a concrete finite model or formal theory.
5. **Verdict Issuance:** The host issues an unambiguous binary verdict: `CLAIM_UPHELD` or `CLAIM_REFUTED`.

## 3. Mathematical Model & Kripke Semantics

- **Modal Kripke Model Checking ($M, w \models \Box \phi$):**
  For modal claims over a transition structure $M = (W, R, V)$:
  $$M, w \models \Box \phi \iff \forall w' \in W, \ (w, w') \in R \implies M, w' \models \phi$$
  The Prosecutor attempts to supply a concrete reachable world $w^*$ where $(w, w^*) \in R$ and $M, w^* \not\models \phi$.
- **Formal Argumentation Attack Graph:**
  The dialectic is modeled as a formal Dung argumentation framework $AF = (A, \text{Attacks})$. The host computes the unique **grounded extension** of the graph based on mathematically verified nodes.
- **Finite Invariant Evaluation:**
  Evaluates bounded linear inequalities:
  $$\sum_{i \in \text{Left}} x_i \le \sum_{j \in \text{Right}} x_j \quad (x_k \in [1, 16] \cap \mathbb{Z})$$

## 4. Team Structure & Panel Roles

- **Pattern:** `tribunal`
- **Normal Path Calls:** 2 model calls per claim (1 prosecution + 1 defense).
- **Roles:**
  - `prosecutor` (Fable, count: $1$): Argues that the claim fails; supplies concrete countermodels and boundary violations.
  - `defender` (Opus, count: $1$): Argues that the claim holds; supplies formal witnesses and proofs.
  - `coder` (Sonnet, count: $1$): Translates informal claims from both sides into structured inputs for the host checker.
  - `host_checker` (None, count: $1$): Deterministic host finite model checker; renders the final verdict.
- **Boost Rule:** If both the prosecution countermodel and the defense witness fail host syntax or validity checks, one fresh round is authorized for Opus to formulate a valid submission from checker error logs (limit 1).

---

## 5. Host Verification Protocol

- **Checker:** Finite model checker (e.g. BDD-based symbolic model checker or explicit state enumerator).
- **Zero Rhetorical Authority:** Prose justifications are discarded by the host encoder; only the mathematical assertions and countermodel coordinates are evaluated.
