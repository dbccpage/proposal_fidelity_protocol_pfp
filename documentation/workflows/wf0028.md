## 1. Objective & Purpose

WF28 expands the adversarial tribunal (WF15) into an explicit sequential council of eight specialized roles. Rather than relying on unstructured debate, the audit pipeline structures deliberation into eight strictly ordered turns, where each participant receives only the frozen, signed artifacts of preceding roles.

Crucially, the final role in the sequence—the **Terminal Arbiter**—holds **zero authority to accept**. Even if all eight roles agree that a proposal is correct, acceptance is determined exclusively by host-evaluated $L_1$ defect calculations.

---

## 2. Process Specification: The Eight Ordered Roles

The audit dialogue proceeds in rigid chronological sequence:

1. **`Proposer`:** Emits the initial mathematical claim, theorem, or candidate algorithm.
2. **`Adversary`:** Attacks the proposal with boundary perturbations, degeneracies, and countermodels.
3. **`Solver`:** Attempts to construct a formal witness or proof closing the adversarial vulnerabilities.
4. **`Overconfidence Probe`:** Audits the solver for hallucinated lemmas, unstated assumptions, or authority claims.
5. **`Stabilizer`:** Filters out brittle parameters and enforces gauge-invariant formulations.
6. **`Schema Auditor`:** Validates envelope contracts, slot typing, and AST syntax.
7. **`Truth Repair`:** Synthesizes the final candidate patch to minimize objective defects.
8. **`Terminal Arbiter`:** Emits a final discursive summary and proposed verdict.

**Host Gate:** The host evaluates whether the proposal trajectory achieved strict monotonic descent in $L_1$ defect. If the Arbiter declares "Verified" but the host checker computes non-zero defect, the Arbiter is overridden and the proposal is refused.

## 3. Mathematical Model & Strict $L_1$ Defect Descent

- **Defect Trajectory Invariant:**
  Let $D_k = D(s_k)$ denote the host-evaluated $L_1$ defect after role $k$:
  $$D_k = \sum_{e \in E} w_e \cdot |s_k(v) - s_k(u) - c_k(u, v)|$$
  Admissibility requires weak monotonic descent across stabilization turns:
  $$D_{\text{TruthRepair}} \le D_{\text{Solver}} \le D_{\text{Proposer}}$$
- **Authority Firewall Invariant:**
  $$\operatorname{Verdict} = \begin{cases}
  \text{HOST\_ACCEPTED} & \text{if } D_{\text{TruthRepair}} == 0 \land \operatorname{HostCheck}() == \text{PASS} \\
  \text{TYPED\_REFUSAL} & \text{otherwise}
  \end{cases}$$
  The Arbiter's string output $\text{Arbiter}.\text{verdict}$ is logged for telemetry but possesses zero gating effect.

## 4. Team Structure & Panel Roles

- **Pattern:** `tribunal`
- **Normal Path Calls:** 8 sequential model calls.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Executes technical role translations and schema checks.
  - `adversary` (Fable, count: $1$): Executes the Adversary and Overconfidence Probe roles.
  - `defender` (Opus, count: $1$): Executes the Solver, Stabilizer, and Truth Repair roles.
  - `host_checker` (None, count: $1$): Deterministic host verifier; evaluates exact $L_1$ defect descent.
- **Boost Rule:** If the Terminal Arbiter and the host checker disagree, the host checker wins automatically; the discrepancy is recorded in the audit log (limit 0).

---

## 5. Host Verification Protocol

- **Host Invariant:** Evaluates exact rational $L_1$ defects between intermediate turn states.
- **Isolation Guarantee:** Each role prompt contains strictly the serialized outputs of prior stages; no live hidden channels or memory caches are shared between agents.
