## 1. Objective & Purpose

WF16 specifies a formal translation protocol between disparate mathematical substrates (e.g. natural language specifications, discrete finite tables, Python ASTs, and Lean 4 formal code).

The objective is to establish **functorial relation preservation**: a crosswalk from substrate $C$ to substrate $D$ is valid if and only if every relation and axiom holding in $C$ is provably preserved in $D$. When translation ambiguities exist (multiple non-isomorphic formalizations of an informal sentence), WF16 explicitly tracks and records every non-unique generator mapping rather than arbitrarily selecting one.

---

## 2. Process Specification

1. **Substrate Definition:** Declare source substrate $C = \langle G_C \mid R_C \rangle$ and target substrate $D = \langle G_D \mid R_D \rangle$ with explicit generators and relations.
2. **Translation Mapping:** Formulate a candidate crosswalk mapping $F: G_C \to G_D$.
3. **Relation Preservation Audit:** For each relation $r \in R_C$, verify that the translated relation $F(r)$ holds in target substrate $D$.
4. **Non-Uniqueness Enumeration:** If alternative mappings $F, F'$ both preserve relations but map generators differently, record the branching non-uniqueness in the derivation ledger.
5. **Host Compilation Check:** Compile the target encoding in the host verifier (e.g. `lake build` in Lean 4 or finite relational table consistency).

---

## 3. Mathematical Model & Preservation Functors

- **Relation Preservation Condition:**
  A crosswalk functor $F: C \to D$ is admitted if and only if:
  $$\forall r \in R_C, \quad D \models F(r)$$
- **Non-Uniqueness Branching:**
  If two candidate translations $F_1, F_2$ satisfy relation preservation:
  $$(\forall r, \ D \models F_1(r)) \land (\forall r, \ D \models F_2(r))$$
  yet differ on generator $g \in G_C$ ($F_1(g) \ne F_2(g)$), the system documents a structural bifurcation rather than asserting canonical equivalence.

## 5. Host Verification Protocol

- **Target Checkers:** Lean 4 `lake build` verification (sorry-free, axiom-clean) or exact finite table relational join verification.
- **Refusal Code:** Emits `RELATION_PRESERVATION_FAILED` if any source relation fails to hold on the target substrate.
