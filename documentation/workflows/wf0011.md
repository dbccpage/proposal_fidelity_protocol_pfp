## 1. Objective & Purpose

WF11 enforces the **primal-dual certificate verification principle**: solvers must not emit bare scalar answers. Instead, every output must be accompanied by a dual certificate that allows an independent host judge to verify optimality, feasibility, or infeasibility via simple, exact dot-product operations.

WF11 utilizes a **commit-reveal architecture**: the participant commits a cryptographic hash of their solver code and public solutions before the sealed judge cases are revealed.

---

## 2. Process Specification

1. **Packet Split:** The host publishes the open participant packet and maintains the judge packet sealed under SHA-256 custody.
2. **Solver Synthesis:** The research cell synthesizes a deterministic algorithm or solver that produces primal solutions alongside dual certificate witnesses.
3. **Commit Phase:** The team commits a cryptographic hash $H(\text{salt} \mathbin{\Vert} \text{solver\_bytes})$ to the host registry.
4. **Reveal & Verification Phase:** The host reveals the hidden test cases. The committed solver is executed against the hidden cases.
5. **Exact Dual Evaluation:** The host checks duality gap closure using exact rational arithmetic:
   $$\text{Duality Gap} = b^T y - c^T x == 0$$

---

## 3. Mathematical Model & Duality Receipts

### 3.1 Linear Programming Optimality Certificate
For a primal problem $\max c^T x$ subject to $Ax \le b, x \ge 0$:
- **Primal Feasibility:** $x \ge 0 \land Ax \le b$
- **Dual Feasibility:** $y \ge 0 \land A^T y \ge c$
- **Zero Duality Gap:** $c^T x = b^T y$
By the Weak Duality Theorem, any pair $(x, y)$ satisfying primal feasibility, dual feasibility, and $c^T x = b^T y$ mathematically certifies that $x$ is globally optimal, without needing to trust the algorithm's internal search path.

### 3.2 Infeasibility Certificate (Farkas' Lemma)
When a system $Ax \le b, x \ge 0$ is infeasible, the model must emit a Farkas witness vector $y$ satisfying:
$$y \ge 0, \quad A^T y \ge 0, \quad b^T y < 0$$

### 3.3 Exact Arithmetic Engine
To guarantee zero roundoff ambiguity, intermediate operations are carried out via Bareiss fraction-free elimination or exact rational matrix multiplications.

## 5. Host Verification Protocol

- **Independent Dual Checkers:** Verification requires two independent checkers: one verifying primal constraints and objective value, and a second verifying dual feasibility and complementarity.
- **Complexity Asymmetry:** Generating the solution is computationally intensive (e.g. polynomial-time simplex or interior point), but checking the certificate requires only $O(mn)$ exact rational additions and multiplications.
