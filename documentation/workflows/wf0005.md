## 1. Objective & Architectural Role

WF5 provides an explicit, checked grammar frontend for the multi-agent execution pipeline. It takes an informal natural language prompt, verifies that it conforms to a strict declared source grammar, lowers it to a canonical Abstract Syntax Tree (AST), serializes it into an unambiguous EBNF packet format, decodes it independently, and verifies round-trip semantic preservation before dispatching to the WF4 5-agent solver.

WF5 demonstrates **deterministic grammar containment**: untrusted natural language input is converted to a formal AST under verified bijective equivalence, preventing prompt injection or ambiguous semantic drift.

---

## 2. The Formal EBNF Wire Syntax (`packet.ebnf`)

WF5 compiles integer summation tasks into an explicit S-expression wire packet defined in `packet.ebnf`:

```ebnf
packet ::= "<" "sum" ws mode ws occurrence ws values ws target ">"
mode ::= "<exact>"
occurrence ::= "<once>"
values ::= "<values" (ws integer)* ">"
integer ::= [pn] [0-9]+
target ::= "<total>"
ws ::= " "+
```

### Encoding Convention
- Positive integers are prefixed with `p` (e.g. `10` $\to$ `p10`).
- Negative integers are prefixed with `n` (e.g. `-5` $\to$ `n5`).
- Zero is encoded as `p0`.
- Example wire serialization:
  ```text
  <sum <exact> <once> <values p12 n4 p7> <total>>
  ```

## 3. The Checked Rewrite Pipeline

```
           [ Natural Language Seed Prompt ]
        "Calculate the exact sum of 12, -4, and 7."
                         |
                         v
     =========================================
     PHASE 1: SOURCE VALIDATION (source_query)
     =========================================
     - Asserts prefix: "Calculate the exact sum of "
     - Asserts suffix: "."
     - Asserts canonical English listing: "a, b, and c"
     - Verifies integer tokens (length <= 101 digits, no "-0")
     - Refuses with WF5_UNSUPPORTED_SEED_LANGUAGE if non-conforming
                         |
                         v
     =========================================
     PHASE 2: AST COMPILATION (encode)
     =========================================
     - Compiles tokens into grammar.App AST
     - Emits wire packet string
                         |
                         v
     =========================================
     PHASE 3: INDEPENDENT DECODING (decode)
     =========================================
     - Binds wire size (<= 65536 bytes)
     - Binds parse depth (depth <= 3, depth >= 0)
     - Parses packet back into canonical query dictionary
                         |
                         v
     =========================================
     PHASE 4: ROUND-TRIP PRESERVATION CHECK
     =========================================
     Asserts: decode(encode(source_query(seed))) == source_query(seed)
     - Hashes bundle into SHA-256 digest rewrite_ref
                         |
                         v
     =========================================
     PHASE 5: WF4 MULTI-AGENT SOLVE
     =========================================
     - Dispatches 1 miner + 5 parallel isolated solvers
     - Evaluates LGGR boundary gluing defect Delta_E
     - Generates global receipt
```

## 4. Bounded Parsing & Depth Defense

To protect the host parser against deeply nested or malformed inputs, `decode()` in `pfp/workflows/wf0005/rewrite.py` enforces pre-parse character scanning:
```python
depth = 0
for char in wire:
    depth += (char == "<") - (char == ">")
    if depth > 3 or depth < 0:
        raise ValueError("WF5_PACKET_DEPTH")
```
If bracket nesting exceeds depth 3 or becomes negative, the host refuses immediately before invoking the recursive grammar parser, preventing stack overflow or recursive backtracking attacks.

## 5. Artifacts & Pre-dispatch Refusal Modes

WF5 run directories contain:
- `rewrite.json`: Records `source_query`, `encoded_packet`, `decoded_query`, and `round_trip_passed`.
- `mining/`: Stage 1 mining run.
- `agent-1/` through `agent-5/`: 5 solver runs.
- `global_receipt.json`: Composite receipt.

### Refusal Codes
- `WF5_UNSUPPORTED_SEED_LANGUAGE`: Input prompt does not start with `"Calculate the exact sum of "` or end with `"."`.
- `WF5_SOURCE_INTEGER_SYNTAX`: Non-canonical integer format (e.g. `"-0"`).
- `WF5_UNACCOUNTED_OR_NONCANONICAL_SOURCE`: Discrepancy between raw string and canonical English rendering.
- `WF5_PACKET_SIZE_OR_TYPE`: Wire length exceeds 64 KiB.
- `WF5_PACKET_DEPTH`: Nesting depth exceeds 3.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - WF5 implements exact, bijective round-trip AST translation between natural language subsets and EBNF packets.
   - Syntactic and structural checks run entirely on the host before any model is invoked.
2. **What the Evidence Does Not Support:**
   - The grammar parser only covers the declared arithmetic seed subset; it is not a general English parser.
3. **Narrowest Defensible Claim:**
   - WF5 demonstrates that natural language prompts conforming to a restricted grammar can be lowered to an explicit EBNF packet with verified round-trip preservation and fed into a multi-agent solver under host accounting.
4. **Next Test Needed:**
   - Extend the EBNF grammar to support rational fractions (e.g. `p3/4`) and verify depth bounding across nested algebraic expressions.
