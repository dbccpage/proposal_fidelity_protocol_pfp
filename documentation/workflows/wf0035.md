## 1. Objective & Purpose

WF35 evaluates the comparative efficacy of different **generation and intervention channels** through which proposals are elicited from a model. Rather than altering the underlying task or the evaluation criteria, WF35 holds the task and host checker completely constant while systematically varying the transmission channel:
- Free natural language prompt.
- Compact glyph-encoded prompt.
- Logit bias mask.
- Strict CFG/EBNF grammar constraint mask (constrained decoding).
- Attributed typed tree representation.
- Internal attention or activation steering bias.

The goal is to determine which intervention channel maximizes host acceptance on identical test instances.

---

## 2. Process Specification

1. **Fixed Problem & Oracle:** Fix a battery of test items and their deterministic host verification oracle.
2. **Channel Arm Configuration:** Configure parallel transmission channels under identical base model weights:
   - Channel 1: Free decoding.
   - Channel 2: Token-constrained grammar mask.
   - Channel 3: Glyph-substituted carrier encoding.
   - Channel 4: Null control channel (verifying that no intervention preserves exact baseline decoding).
3. **Execution & Telemetry:** Dispatch each capsule, capturing generated tokens, latency, and FLOPs/resource usage.
4. **Shared Oracle Grading:** Grade all outputs using the fixed host oracle.
5. **Item-by-Item Channel Comparison:** Evaluate acceptance differences across channels on a per-item basis.

---

## 3. Mathematical Model & Channel Invariance

- **Host Channel-Invariance Principle:**
  The host acceptance function $\operatorname{Accept}(y)$ is strictly channel-invariant: it depends solely on the candidate output bytes $y$, never on the mechanism or channel used to produce it:
  $$\operatorname{Accept}(y, \text{channel}_1) == \operatorname{Accept}(y, \text{channel}_2) \quad \forall y \in \mathcal{Y}$$
- **Channel Acceptance Differential:**
  For channel $\alpha$ vs channel $\beta$ over $N$ items:
  $$\Delta_{\alpha, \beta} = \frac{1}{N} \sum_{i=1}^N \left( \mathbf{1}[\operatorname{Accept}(\text{channel}_\alpha(x_i))] - \mathbf{1}[\operatorname{Accept}(\text{channel}_\beta(x_i))] \right)$$
- **Null Channel Fidelity Invariant:**
  $$\text{tokens}(\text{NullChannel}(x)) == \text{tokens}(\text{FreeDecoding}(x))$$

## 4. Team Structure & Panel Roles

- **Pattern:** `sweep_with_shared_judge`
- **Normal Path Calls:** Channels $\times$ Items.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Configures provider sampling parameters, logit masks, and grammar parsers.
  - `deep_researcher` (Opus, count: $1$): Designs channel hypotheses and statistical significance tests.
  - `host_checker` (None, count: $1$): Fixed exact host oracle.
- **Boost Rule:** None; channels represent experimental treatment arms rather than runtime escalation boosts (limit 0).

---

## 5. Host Verification Protocol

- **Single Unchanged Oracle:** The exact same Python verification class is executed against outputs from all channels.
- **Strict Blind Grading:** The host grader has zero access to the channel metadata when evaluating the response string.

---

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Preliminary testing on Qwen-0.5B confirms that null control channels reproduce free decoding token-for-token.
2. **What the Evidence Does Not Support:**
   - Activation steering and internal attention bias channels have not been exercised on live frontier models in this repository.
3. **Narrowest Defensible Claim:**
   - WF35 specifies an experimental protocol to compare the acceptance rates of model proposals generated across diverse transmission and decoding channels using a fixed, channel-blind host oracle.
4. **Next Test Needed:**
   - Compare unconstrained JSON vs grammar-masked JSON decoding across 50 integer partition tasks to measure the exact impact of grammar masks on syntax errors.
