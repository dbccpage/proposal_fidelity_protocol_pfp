## 1. Objective & Architectural Role

WF2 extends WF1 by requiring the model to address an explicit 16-slot problem specification catalogue, emit candidate operad operations with literal source grounding, and declare Discrete Deformation Calculus (DDC) moves. Rather than emitting an ungrounded scalar total, WF2 captures the model's declared domain abstraction as unadmitted candidate material. Crucially, the host deterministically audits the structural integrity of these declarations, refusing proposals that exhibit arity mismatches, ungrounded source quotes, or unresolved core slots.

---

## 2. Pinned Slot Catalogue & DDC Alphabet

### 2.1 The 16 Catalogue Slots (`slot_catalogue.json`)
The model must explicitly address every slot in `slot_catalogue.json`:
- **Core Slots (Must be `provided`):**
  - `carrier`: Domain and codomain types (e.g. `IntegerList -> Integer`).
  - `equality_policy`: Equality criteria governing evaluation.
  - `operands`: Pointer to input data items.
  - `colours`: Type colours used in the operad algebra.
  - `operators`: Operations licensed for the turn.
  - `terminal`: Target terminal field (`task_result.total`).
- **Auxiliary & L2 Slots (May be `not_applicable` with non-empty reason):**
  - `concrete_spans`, `parameter_bindings`, `instantiated_arguments`, `preservation_obligations`, `boundary_conditions`, `witnesses`, `countermodels`, `residual_invariants`, `subproblems`, `refusal_criteria`.

### 2.2 Canonical DDC Alphabet (`ddc_alphabet.rs.txt`)
Each declared move in `ddc_moves` must specify an operation from the canonical 8-element DDC alphabet:
- `E`: Exact repair.
- `R`: Residual projection.
- `C`: Context exposure.
- `I`: Integration.
- `Λ`: Structural lift (canonical Unicode `\u039b` or `Meta`).
- `D`: Descent.
- `M`: Mutation / typed refusal.
- `T`: Terminalization.

## 3. Data Contracts & State Transformations

### 3.1 Extended Answer Schema (`answer.schema.json`)
WF2 wraps the task result inside a structured envelope containing three mandatory audit sections:
```json
{
  "task_result": { "total": 15 },
  "slot_report": [
    { "slot": "carrier", "disposition": "provided", "value": "IntegerList -> Integer", "reason": "" },
    { "slot": "boundary_conditions", "disposition": "not_applicable", "value": "", "reason": "Finite list without edge boundary" }
  ],
  "operad_candidates": [
    {
      "id": "sum",
      "arity": 1,
      "source_colours": ["IntegerList"],
      "target_colour": "Integer",
      "source": { "kind": "seed_prompt", "quote": "Calculate the exact sum" },
      "witness_refs": ["carrier", "task_result"]
    }
  ],
  "ddc_moves": [
    {
      "id": "move-1",
      "op": "E",
      "operad_id": "sum",
      "local_log": "Evaluated integer sum over input.values",
      "refusal": "",
      "witness_refs": ["task_result"]
    }
  ]
}
```

## 4. Deterministic Host Verification (`finalize_check`)

The host audits the returned envelope in Python (`pfp/workflows/wf0002/workflow.py`):
1. **Slot Coverage Audit:** Every slot in the catalogue must appear exactly once. Required core slots must have disposition `provided` with a non-empty value.
2. **Operad Arity Check:** For each candidate operad, `op["arity"] == len(op["source_colours"])`.
3. **Literal Quote Grounding:** `op["source"]["quote"]` must appear verbatim in `seed_prompt` or compact sorted `input_json`.
4. **Witness Reference Containment:** `witness_refs` may only reference valid slot names, emitted operad IDs, or `task_result`.
5. **DDC Move Audit:** Each move must have a valid DDC operator, a non-empty `local_log` or `refusal`, and resolve referenced operads.
6. **Semantic Check:** Evaluates `integer_sum_judge` on `task_result`.

If structural audits fail, the host sets `failure_class="WF2_OPERAD_STRUCTURE"` and refuses the submission, regardless of whether `task_result.total` was mathematically correct.

---

## 5. Artifacts & Candidate Collection (`collection.json`)

When structural checks pass, the runner invokes `collect_emitted` (`collection.py`) to emit `collection.json`, indexing all discovered operad candidates and DDC moves for downstream analysis. The material is explicitly flagged:
```json
{
  "workflow_id": "WF2",
  "disposition": "UNVERIFIED_CANDIDATE_MATERIAL",
  "authority_effect": "None"
}
```

---

## 6. Offline Replay & Verification

Replay via `pfp-wf2 replay <dir>`:
- Recomputes SHA-256 hashes for `task.json`, `prepared.json`, `response.raw`, `receipt.json`, and `collection.json`.
- Re-runs `finalize_check` and verifies that recomputed structure errors and candidate collections match the recorded files.

## 7. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - WF2 forces language models to emit formal structural metadata (operad arity, quotes, DDC moves) alongside task answers.
   - Host verification deterministically detects hallucinated quotes, arity errors, and missing slots.
2. **What the Evidence Does Not Support:**
   - The emitted operad candidates and DDC moves do not prove that the model executed category-theoretic reasoning internally.
3. **Narrowest Defensible Claim:**
   - WF2 validates that a candidate response satisfies explicit multi-field structural constraints and literal textual grounding while evaluating the core task.
4. **Next Test Needed:**
   - Measure the failure rate of various model tiers on the literal quotation check when prompt text contains complex syntactic punctuation.
