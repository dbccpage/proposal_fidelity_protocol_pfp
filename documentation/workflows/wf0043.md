## 1. Objective & Purpose

WF43 is an adversarial **harness-honesty audit gate** that tests whether verification gates are genuinely evaluating task calculations or are susceptible to "answer-free cheats."

A verification harness is dishonest if a model can achieve a passing grade without computing anything—for example, by:
- Emitting a constant generic refusal (`UNRESOLVED`).
- Submitting an empty JSON object `{}`.
- Exploiting descriptive case identifiers that leak expected outcomes (e.g. `test_case_infeasible_01`).
- Echoing prompt keywords that trigger naive string-matching regex judges.

WF43 subjects the entire evaluation pipeline to a battery of degenerate inputs to prove that no answer-free submission can pass.

---

## 2. Process Specification

1. **Operation Provenance Audit:** Trace every verdict in the receipt back to an explicit host mathematical operation; any verdict not backed by an executable check is invalidated.
2. **Degenerate Input Probing:** Run the harness against four adversarial probe suites:
   - **Constant Refusal Probe:** Submits `ANSWER: UNRESOLVED <CODE>` on known-solvable tasks.
   - **Empty Object Probe:** Submits `{}` or null payloads.
   - **Constant Answer Probe:** Submits fixed dummy integers (e.g. `0`, `1`, `42`) across all test instances.
   - **Phantom Evidence Probe:** Submits fabricated citations or mock proof hashes.
3. **Keyword Adjudication Bypass Test:** Verify that judges do not use heuristic keyword presence (e.g. searching for `"proved"`, `"optimal"`, or `"verified"`) to award passes.
4. **Identifier Neutralization:** Verify that case identifiers are strictly neutral hashes (e.g. `case_7a8f3b`), ensuring zero semantic label leakage.
5. **Certification:** If any degenerate submission passes any check, the challenge and checker are immediately locked and blocked from use.

## 3. Mathematical Model & Gate Honesty

- **The Gate-Honesty Principle:**
  Let $\mathcal{D}_{\text{degenerate}}$ be the set of answer-free dummy submissions (empty payloads, constant refusals, uncomputed literals). A verification gate $\mathcal{G}$ is honest if and only if:
  $$\forall d \in \mathcal{D}_{\text{degenerate}}, \quad \mathcal{G}(x, d) == \text{FAIL}$$
- **Zero Mutual Information of Identifiers:**
  Let $\text{ID}(x)$ be the case identifier string and $y^*(x)$ be the ground-truth outcome:
  $$I(\text{ID}(x); y^*(x)) == 0$$
- **Verdict Traceability Invariant:**
  Every accepted verdict $V$ must satisfy:
  $$V \in \operatorname{Range}(\text{ExecutableHostChecker}) \land \text{ExecutedBytesMatchSealedDigest}$$

## 4. Team Structure & Panel Roles

- **Pattern:** `red_team_pair`
- **Normal Path Calls:** 0 calls (executed via deterministic host audit test runners).
- **Roles:**
  - `coder` (Sonnet, count: $1$): Neutralizes case identifiers and implements provenance tracing.
  - `adversary` (Fable, count: $1$): Generates devious answer-free payloads and exploits heuristic judge shortcuts.
  - `host_checker` (None, count: $1$): Deterministic host harness auditor; executes degenerate probes against candidate checkers.
- **Boost Rule:** If any leak or trivial bypass is discovered, the gate is immediately locked until the vulnerability is patched and re-certified (limit 0).

---

## 5. Host Verification Protocol

- **Automated Replay Suite:** The host runs all four degenerate probe suites against every registered checker before any benchmark campaign is permitted to launch.
- **Refusal Code:** Any unexpected pass on a degenerate probe raises `GATE_HONESTY_AUDIT_FAILED`.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Offline audit traces in Pilot 10 confirmed that neutral case identifiers and strict schema parsing eliminate accidental passes on dummy answers.
2. **What the Evidence Does Not Support:**
   - The absence of trivial leaks does not guarantee that a benchmark task is immune to advanced statistical correlations.
3. **Narrowest Defensible Claim:**
   - WF43 provides a deterministic audit protocol that verifies that no answer-free, empty, or constant dummy proposal can pass host verification checkers.
4. **Next Test Needed:**
   - Run the 4-probe degenerate test suite against all 50 certified challenge checkers (`c011-c060`), confirming 100% failure on empty and constant inputs.
