## 1. Objective & Purpose

WF24 enforces an explicit, grammar-constrained operational scratchpad for path-dependent algebraic calculations (e.g. discrete gauge holonomies and matrix path products).

Instead of permitting free-form natural language "chain of thought"—which is susceptible to drift, ungrounded leaps, and post-hoc rationalization—WF24 pins canonical coordinate tokens and algebraic operators directly in the response grammar. The model must emit its calculation step-by-step as an explicit operational trace that can be deterministically audited by dual host checkers.

---

## 2. Process Specification

1. **Token & Coordinate Pinning:** The host injects a strict response grammar binding coordinate names (e.g. vertices $v_0, \dots, v_n$, oriented edges $e_{ij}$) and algebraic group operators.
2. **Scratchpad Generation:** The model evaluates the task turn by writing an operational scratchpad: each line records an accumulated group element after traversing an edge.
3. **Dual Verification:** The final computed value and the scratchpad trace are passed to two independent host holonomy checkers.
4. **Concordance Audit:** The host accepts if and only if both checkers independently confirm that the step-by-step path products match the final output.

---

## 3. Mathematical Model & Path Holonomy

- **Discrete Gauge Path Product:**
  Along a directed loop $\gamma = (e_1, e_2, \dots, e_m)$ on a graph, the total holonomy $g_\gamma$ in a gauge group $G$ is given by the ordered path-ordered product:
  $$g_{\text{acc}}^{(0)} = \operatorname{id}_G$$
  $$g_{\text{acc}}^{(k)} = g_{\text{acc}}^{(k-1)} \cdot U(e_k) \quad \text{for } k \in \{1, \dots, m\}$$
  where $U(e_k) \in G$ is the parallel transport link variable.
- **Flatness Invariant:**
  A connection is flat if and only if for every contractible loop $\gamma$, $g_\gamma == \operatorname{id}_G$.
- **Trace Audit:**
  The host asserts that each intermediate state $g_{\text{acc}}^{(k)}$ in the scratchpad matches the host-computed prefix product.

## 4. Team Structure & Panel Roles

- **Pattern:** `solo`
- **Normal Path Calls:** 1 call.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Generates the typed proposal adhering to the pinned-token grammar.
  - `deep_researcher` (Opus, count: $1$): Specifies the algebraic group presentation and audits trace residuals.
  - `host_checker` (None, count: $1$): Evaluates dual independent holonomy checkers.
- **Boost Rule:** If the host checkers reject the proposal, Opus reviews the algebraic residual and repairs the scratchpad (limit 1).

---

## 5. Host Verification Protocol

- **Dual Checkers:** Two separate Python implementations (one using direct permutation matrices, one using cycle generators) must agree on the holonomy calculation.
- **Trace Rejection:** A correct final group element with an invalid or skipping scratchpad is rejected with `SCRATCHPAD_TRACE_INVALID`.

---

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Empirical findings in Challenge C017 indicate that pinning coordinate tokens and requiring explicit step products prevents arbitrary hallucinated jumps in path traversal tasks.
2. **What the Evidence Does Not Support:**
   - The operational scratchpad does not prove that the model internally computes group representations.
3. **Narrowest Defensible Claim:**
   - WF24 forces models to externalize path-dependent algebraic calculations as formal, grammar-pinned traces that are deterministically verifiable by dual host checkers.
4. **Next Test Needed:**
   - Benchmark WF24 on 20 non-abelian $S_3$ holonomy loops, comparing pass rates between unconstrained reasoning and pinned operational scratchpads.
