## 1. Objective & Purpose

WF26 couples the bounded iterative repair loop of WF9 with the antibody synthesis mechanisms of the Epistemic Immune System (EIS, WF14). In complex multi-turn problem solving, models often repeat the same conceptual mistake across successive retries.

WF26 dynamically converts each observed intermediate failure into a formal **negative-constraint antibody** (e.g. "Do not assume the gauge connection is abelian", "Do not assign non-zero potential to vertex $v_3$"). These antibodies accumulate in the turn context, progressively fencing off falsified solution paths.

---

## 2. Process Specification

1. **Initial Dispatch:** Dispatches initial attempt under the task schema.
2. **Deterministic Evaluation:** The host oracle checks the output. If accepted, halts immediately.
3. **Antibody Generation:** On rejection, Fable and the host extract a typed negative constraint:
   $$a_t = \operatorname{ExtractAntibody}(\text{attempt}_t, \operatorname{residual}_t)$$
4. **Context Accumulation:** The active antibody set $A_{t+1} = A_t \cup \{a_t\}$ is injected into the prompt for turn $t+1$.
5. **Convergence or Budget Halt:** Continues for up to $R$ rounds. The host accepts if and only if the exact oracle check passes.

---

## 3. Mathematical Model & Negative Constraint Fencing

- **Antibody Accumulation Recurrence:**
  $$A_0 = \emptyset$$
  $$A_{t+1} = A_t \cup \{ a_t \}$$
  where each antibody $a_t: \mathcal{X} \to \{\text{True}, \text{False}\}$ forbids candidate proposals $x$ satisfying $a_t(x) = \text{True}$.
- **Feasible Space Contraction:**
  The admissible search space contracts monotonically:
  $$\Omega_{t+1} = \Omega_t \cap \{ x \in \mathcal{X} \mid \neg a_t(x) \}$$
- **Termination Criterion:**
  $$\text{Halt} \iff \operatorname{check}(x_t) == \text{PASS} \lor t == R$$

---

## 4. Team Structure & Panel Roles

- **Pattern:** `proposer_with_residual_feedback`
- **Normal Path Calls:** Up to $R$ dialogue rounds.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Generates successive candidate proposals respecting all active accumulated antibodies.
  - `adversary` (Fable, count: $1$): Formulates sharp, minimal negative-constraint antibodies from rejected traces.
  - `host_checker` (None, count: $1$): Deterministic host exact oracle.
- **Boost Rule:** If two consecutive rounds occur without defect reduction, Opus rewrites and consolidates the active antibody set (limit 1).

---

## 5. Host Verification Protocol

- **Exact Oracle:** Proposals are evaluated exclusively by the exact mathematical oracle; antibody satisfaction is necessary but not sufficient for acceptance.
- **Leakage Prevention:** Antibodies must express negative constraints (what not to do), never positive answer disclosures.
