---

## 1. Objective & Purpose

WF6 is an experiment design workflow that measures, item by item, which presentation (dialect or grammar rewrite) of an identical task achieves higher host acceptance, without altering the underlying mathematical problem.

By keeping the host checker and task seed constant while systematically varying the prompt's linguistic or syntactic representation, WF6 separates presentation effects from semantic reasoning capabilities.

---

## 2. Process Specification

1. **Seed Freezing:** Freeze a single seed problem $s$ and its ground-truth host answer $q(s)$.
2. **Dialect Compilation:** Compile $P^*$ and $k$ checked rewrites (dialects $\rho_1, \dots, \rho_k$) of both the seed and $P^*$.
3. **Preservation Precondition:** For every dialect $\rho_k$, deterministically verify on the host that $\operatorname{decode}(\rho_k(s)) = q(s)$ before dispatch.
4. **Uniform Dispatch:** Dispatch each capsule under identical model, temperature, and decoding parameters.
5. **Shared Host Evaluation:** Grade every model reply using the same unchanged deterministic host checker.
6. **Pairwise Analysis:** Compare acceptance rates per dialect item by item.

---

## 3. Mathematical Model & Acceptance Formulations

- **Preservation Obligation:**
  $$\operatorname{decode}(\rho_k(s)) = q(s) \quad \forall k \in \{1, \dots, K\}$$
- **Item-level Empirical Acceptance:**
  $$A_k = \frac{1}{N} \sum_{i=1}^N \mathbf{1}[\operatorname{check}(r_{ik})]$$
- **Net Rational Structure Delta:**
  $$\text{Net} = \Delta_{\text{created}} - \Delta_{\text{removed}}$$

---

## 4. Team Structure & Panel Roles

- **Pattern:** `sweep_with_shared_judge`
- **Normal Path Calls:** $2 + 2k$ per seed.
- **Roles:**
  - `coder` (Sonnet, $\times 1$): Builds dialect rewrites, encoders, and decoders; verifies preservation.
  - `coder` (Sonnet, $\times 1$): Executes capsules and captures raw provider wire bytes.
  - `deep_researcher` (Opus, $\times 1$): Selects informative dialect candidates and analyzes item-by-item residuals.
  - `host_checker` (None, $\times 1$): Deterministic host verifier (e.g. exact linear algebra, graph facts, typed refusal).
- **Boost Rule:** If a dialect fails the preservation check, Opus proposes a corrected rewrite based on the preservation residual; the host re-checks preservation before any provider dispatch (limit 1).

---

## 5. Host Verification Protocol

- **Check Routine:** Family checker (exact linear algebra, graph facts, or graph repair).
- **Pre-dispatch Gate:** Any dialect failing $\operatorname{decode}(\rho_k(s)) = q(s)$ is blocked before dispatch.
- **Evaluation Criteria:** Acceptance is strictly binary per item ($\{0, 1\}$). No partial credit or semantic similarity scoring is permitted.

---

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Historical pilot records (Pilots 0–19) contain offline test capsules documenting syntax variations across linear algebra and graph problems.
2. **What the Evidence Does Not Support:**
   - The design does not demonstrate that any single dialect universally improves language model reasoning across diverse task domains.
3. **Narrowest Defensible Claim:**
   - WF6 specifies a controlled experimental protocol to evaluate how syntactic prompt variations affect deterministic host acceptance on fixed task instances.
4. **Next Test Needed:**
   - Execute a 4-dialect sweep across 50 linear algebra instances using a single fixed model to measure item-level variance under exact rational checks.
