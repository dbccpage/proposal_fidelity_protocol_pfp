## 1. Objective & Purpose

WF44 defines standardized, reusable **certificate presets** that embody the "verify-easy, solve-hard" computational paradigm. Rather than forcing downstream workflows to invent bespoke certificate schemas for each new task, WF44 provides pre-registered mathematical receipt formats:
1. $L_1$ potential, residual, and dual circulation certificates.
2. Sparse homological cycle representatives.
3. Equal-weight pairing involutions (matching certificates).
4. Typed DSL program certificates.

The host verifier grades these certificates in exact rational arithmetic, guaranteeing that verifying a complex optimization or graph problem requires only elementary matrix-vector operations.

---

## 2. Process Specification

1. **Preset Selection:** The task declares one of the pre-registered WF44 certificate schemas.
2. **Candidate Synthesis:** The model emits the certificate payload (e.g. vertex potential vector $s$, dual circulation vector $z$, or DSL program AST).
3. **Pre-Evaluation Typing Audit:** The host parses the certificate syntax; ill-typed programs or dimension-mismatched vectors are refused before execution.
4. **Exact Rational Check:** The host evaluates the certificate invariants (e.g. weak duality closure, circulation divergence, or pairing symmetry) using exact fractions.
5. **Disposition Receipt:** Emits `CERTIFICATE_VERIFIED` or `CERTIFICATE_REFUTED` with the exact numerical residual.

## 3. Mathematical Model & Duality Formulations

- **$L_1$ Minimum-Weight Potential Duality Certificate:**
  For edge weights $w \in \mathbb{Q}^E$ and boundary incidence matrix $B$:
  - Primal residual: $r = w + B f$
  - Dual circulation: $B^T z = 0$
  - Dual boundedness: $|z_e| \le w_e \quad \forall e \in E$
  - Complementary slackness (Zero Duality Gap):
    $$w^T z = \|r\|_1$$
- **Equal-Weight Pairing Involution:**
  For graph matching and bipartite covering: an involution $\tau: V \to V$ ($\tau^2 = \operatorname{id}_V$) satisfying edge coverage and matching bounds.
- **Typed DSL Program AST:**
  A sequence of typed instructions whose execution trace terminates in a verified invariant without host side effects.

## 5. Host Verification Protocol

- **Exact Fraction Arithmetic:** All dot products, matrix multiplications, and duality gap checks execute using Python `fractions.Fraction`.
- **Dimension & Type Guards:** Any certificate with incorrect dimensions, non-rational coordinates, or undeclared indices is rejected with `CERTIFICATE_SYNTAX_ERROR`.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Standalone Python test suites confirm that $L_1$ duality certificates can be verified deterministically via fraction dot-products.
2. **What the Evidence Does Not Support:**
   - The existence of a certificate checker does not make NP-hard problems easier for models to solve; it only makes verified answers easy to audit.
3. **Narrowest Defensible Claim:**
   - WF44 provides standardized, exact rational certificate formats that allow host verifiers to validate proposed solutions via polynomial-time matrix and dot-product operations.
4. **Next Test Needed:**
   - Execute the $L_1$ duality checker on 20 random graph instances with known optimal potentials, confirming that correct dual certificates produce zero duality gap.
