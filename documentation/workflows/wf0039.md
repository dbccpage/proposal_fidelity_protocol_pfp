## 1. Objective & Purpose

WF39 establishes the definitive **Authority Firewall Gate** of the Proposal Fidelity Protocol. It enforces the constitutional security guarantee of the entire architecture: **there exists no execution path through which an untrusted, fluent, or confident language model response can acquire epistemic authority without passing all host-evaluated formal guards**.

WF39 separates operational halting (e.g. an agent completing its turns or an API tool returning exit code 0) from epistemic acceptance. A rejected or obstructed candidate proposal can only be converted into diagnostic residual evidence—it can never be promoted to an admitted solution.

## 2. Process Specification

1. **Ingress Isolation:** Candidate response is ingested into an untrusted quarantine buffer.
2. **The Guard Vector Evaluation:** The host evaluates an exhaustive 7-dimensional binary guard vector $\vec{g} = (g_1, \dots, g_7)$ over the proposal:
   - $g_1$ (`ReplayHashMatch`): Verifies SHA-256 match with recorded ingress bytes.
   - $g_2$ (`ReplayExecutionMatch`): Verifies that deterministic re-execution reproduces the result.
   - $g_3$ (`TerminalizerContract`): Verifies schema closure and absence of dangling pointers.
   - $g_4$ (`ExhaustionControl`): Verifies that budget limits were strictly respected.
   - $g_5$ (`ZeroDefectGuard`): Verifies that host-computed defect $D == 0$.
   - $g_6$ (`DescentWitness`): Verifies that the proposal demonstrates strictly lower defect than predecessor states.
   - $g_7$ (`FreshnessNonce`): Verifies that replay nonces and timestamps are valid and unspent.
3. **Packet Gates C1–C8:** Validates that tool execution exit codes are evaluated as potential evidence, never as authority claims.
4. **All-or-Nothing Admission:** Admission requires $\bigwedge_{i=1}^7 g_i == 1$. If any guard evaluates to 0, the proposal is permanently quarantined.

## 3. Mathematical Model & Firewall Invariants

- **The Fundamental Firewall Invariant:**
  $$\operatorname{Admit}(x) \iff \prod_{i=1}^7 g_i(x) == 1$$

  $$[c] \ne 0 \implies g_5(x) == 0$$
  A non-zero obstruction class cannot satisfy a truthful zero-defect guard under any parameter assignment.

## 5. Host Verification Protocol

- **Strict Binary Vector:** The output receipt records the explicit 7-bit evaluation vector `guard_vector: [1, 1, 1, 1, 1, 1, 1]`.
- **Refusal Code:** Any failing bit emits its specific guard failure code (e.g. `FIREWALL_ZERO_DEFECT_VIOLATION`, `FIREWALL_REPLAY_HASH_MISMATCH`).
