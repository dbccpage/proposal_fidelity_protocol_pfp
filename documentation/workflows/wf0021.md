## 1. Objective & Purpose

WF21 formalizes prompt modification using algebraic graph rewriting (specifically Category-Theoretic Attributed C-Set Double-Pushout (DPO) rewriting). When a prompt is rewritten to inject scaffolding, translate syntax, or attach domain guidance, WF21 guarantees under declared assumptions that **protected semantic nodes remain strictly invariant**.

WF21 prevents two pervasive failure modes in prompt engineering:
1. **Meaning Loss:** A rewrite normal form that inadvertently drops the question or changes constants.
2. **Recursive Data Substitution:** Accidental template substitution inside user data fields (prompt injection).

---

## 2. Process Specification

1. **Attributed Graph Modeling:** The input prompt is parsed into an attributed graph $G$ whose vertices represent distinct semantic components: `TaskNode`, `ConstraintNode`, `ProtectedDataNode`, and `OutputContractNode`.
2. **DPO Rule Formulation:** Transformations are expressed as span spans of graph homomorphisms $L \xleftarrow{l} K \xrightarrow{r} R$.
3. **Injective Match Audit:** A rule is applied only via an explicit injective graph match $m: L \hookrightarrow G$. The host verifies that the pushout complement exists (satisfying the dangling condition and identification condition).
4. **Byte-Level Preservation Check:** After rewriting $G \rightsquigarrow G'$, the host extracts protected nodes and asserts exact byte equality:
   $$\operatorname{bytes}(\operatorname{protected}(G')) == \operatorname{bytes}(\operatorname{protected}(G))$$
5. **Normal Form Refusal:** If rewriting simplifies the prompt such that the core query is eliminated, the rewrite is refused.

---

## 3. Mathematical Model & Double-Pushout (DPO) Rewriting

- **DPO Algebraic Pushout Diagram:**
  A rewrite step from graph $G$ to $G'$ using rule $p = (L \leftarrow K \rightarrow R)$ is governed by two pushout squares in the category of attributed C-sets ($\mathbf{ACSet}$):
  $$\begin{array}{ccccc}
  L & \xleftarrow{l} & K & \xrightarrow{r} & R \\
  \downarrow{\scriptstyle m} & & \downarrow{\scriptstyle k} & & \downarrow{\scriptstyle m'} \\
  G & \xleftarrow{d} & D & \xrightarrow{g} & G'
  \end{array}$$
  where $D$ is the pushout complement (the context remaining after removing elements of $L \setminus K$).
- **Protected Node Invariant:**
  Let $P \subseteq V(G)$ be the subobject of protected data nodes. The rewrite is admissible if and only if:
  $$P \subseteq K \quad \text{and} \quad r|_P = \operatorname{id}_P$$
  ensuring that protected nodes are neither deleted nor mutated.

## 4. Team Structure & Panel Roles

- **Pattern:** `red_team_pair`
- **Normal Path Calls:** 0 calls (deterministic host execution) or 1 call per proposed rewrite rule.
- **Roles:**
  - `coder` (Sonnet, count: $1$): Implements DPO graph rewrite rules and AST parsing routines.
  - `adversary` (Fable, count: $1$): Constructs adversarial prompts and rules that syntactically pass parsing but eliminate semantic intent.
  - `host_checker` (None, count: $1$): Deterministic host verifier; evaluates byte-preservation and executes domain judges.
- **Boost Rule:** When a meaning-loss case is discovered by the adversary, it is added to the permanent refusal test suite; no retry is authorized on that rule (limit 0).

---

## 5. Host Verification Protocol

- **Byte-Preservation Gate:** The host directly hashes and compares the byte slice of all protected spans before and after the rewrite.
- **Refusal Codes:**
  - `PROTECTED_SPAN_MUTATION_DETECTED`
  - `DANGLING_CONDITION_VIOLATION`
  - `NORMAL_FORM_DROPPED_QUERY`

---

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - The codebase contains working implementations of ACSet graph representations and DPO rewriting with byte-preservation checks.
2. **What the Evidence Does Not Support:**
   - DPO rewriting does not automatically infer the semantic correctness of informal, unstructured natural language prompts.
3. **Narrowest Defensible Claim:**
   - WF21 provides an algebraic graph-rewriting harness that guarantees under declared assumptions that declared protected prompt spans cannot be modified or deleted during prompt transformation.
4. **Next Test Needed:**
   - Run 50 DPO rewrite rules on prompt templates containing mathematical equations, confirming that all 50 preserve the equation substrings bit-for-bit.
