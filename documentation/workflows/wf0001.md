## 1. Objective & Architectural Role

WF1 defines the minimal atomic task-turn contract in the Proposal Fidelity Protocol. It establishes the baseline single-turn protocol: a frozen task specification is presented to a solver under an explicit response schema, producing a single candidate response that is evaluated exclusively by a deterministic host judge. WF1 omits intermediate mining, rewriting, or multi-agent decomposition, serving as the foundation upon which WF2 through WF49 build.

---

## 2. Specification & Data Contracts

### 2.1 Task Specification (`task_spec.schema.json`)
The input to WF1 is a JSON dictionary validated against `task_spec.schema.json`:
- `task_id` (string): Unique identifier for the problem instance.
- `seed_prompt` (string): Natural language description of the task.
- `input` (object): Public inputs (e.g., `{"values": [12, -4, 7]}`).
- `answer_schema` (object): JSON Schema governing the model's required response payload.
- `checker` (string): Identifier of the host verification routine (`"integer_sum_v1"` or `"schema_only"`).

### 2.2 Response Envelope
The model must emit a JSON object conforming strictly to `answer_schema`:
```json
{
  "task_id": "task-001",
  "attempt_id": "wf0001-stage-1",
  "input_sha256": "4a5e...",
  "answer": {
    "total": 15
  }
}
```

## 3. Execution Lifecycle & State Transformations

WF1 executes through `pfp.infrastructure.workflow_runtime.WorkflowRuntime`:

```
[task_spec.json]
       |
       v
validate_task() ---> prepare_task()
       |
       v
[Preparation Phase] (Zero network I/O)
Writes:
  - task.json
  - prepared.json
  - system_prompt.txt
  - user_prompt.txt
  - response_schema.json
  - preparation_manifest.json (SHA-256 seal)
       |
       v
[Dispatch Phase] (Single Provider Call)
Accounted Budget Gateway ($0.004999 ceiling)
Dispatches CandidateRequest -> Captures response.raw
       |
       v
[Verification Phase] (Deterministic Host Judge)
Evaluates exact integer equality: sum(input.values) == answer.total
       |
       v
[Receipt Sealing Phase]
Writes:
  - receipt.json
  - provider.json (telemetry and cost)
  - receipt_manifest.json (Cryptographic seal of all files)
```

---

## 4. Host Judges & Operators

- **Semantic Template Operator:** `basic_task_template` projects the task into a rigid prompt instructing the model to return only the schema-valid response without discursive filler.
- **Deterministic Judge (`integer_sum_judge`):**
  $$f_{\text{judge}}(\text{input}, \text{answer}) = \left(\sum_{v \in \text{input.values}} v == \text{answer.total}\right)$$
  The judge recomputes the sum directly in Python; it does not consult the model's reasoning trace.

---

## 5. Offline Fixture Replay

WF1 supports complete offline, zero-network bit-for-bit replay via `pfp-wf1 replay <run_dir>`:
1. Re-reads and verifies all file hashes in `receipt_manifest.json`.
2. Validates that the runtime source code digests match the recorded manifest.
3. Re-evaluates `check_reply` on `response.raw` against `task.json`.
4. Asserts that the recomputed status and failure codes equal those in `receipt.json`.

---

## 6. Failure Modes & Refusal Behaviors

WF1 enforces explicit refusal codes:
- `SCHEMA_INVALID`: The model response fails JSON Schema validation.
- `JUDGE_FAILED`: The calculated total does not equal the host's independent sum.
- `ESTIMATED_BUDGET_EXCEEDED`: Estimated cost of dispatch exceeds $0.004999.
- `CALL_ALLOWANCE_EXHAUSTED`: Gateway maximum calls limit (1 call) exceeded.
- `RECEIPT_DIGEST_MISMATCH`: File tampering detected during offline replay.

## 7. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - WF1 provides an automated, accounted, single-call harness that validates model responses against strict schemas and exact Python judges.
   - Run directories can be replayed and verified offline with 100% bit-for-bit fidelity.
2. **What the Evidence Does Not Support:**
   - Passing WF1 does not prove mathematical capabilities beyond the specific tested task instance.
3. **Narrowest Defensible Claim:**
   - WF1 confirms that a language model proposal either satisfies or fails a predefined schema and exact integer check under accounted resource bounds.
4. **Next Test Needed:**
   - Execute WF1 across 100 random 50-integer sums to measure the baseline zero-shot accuracy under schema constraints.
