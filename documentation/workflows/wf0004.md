## 1. Objective & Architectural Role

WF4 coordinates five isolated parallel solvers against a shared, frozen public task profile and evaluates the resulting multi-agent ensemble using Local Green Global Red (LGGR) gluing defect analysis.

WF4 rejects majority voting or peer-consensus authority. Five agreeing model responses do not establish mathematical truth. Instead, WF4 requires:
1. Complete agent isolation (zero cross-talk).
2. Unanimous local structural compliance.
3. Unanimous overlap agreement on the scalar answer.
4. Independent verification by a deterministic host judge.
5. Exact evaluation of the boundary gluing defect $\Delta_E$.

## 3. Local Green Global Red (LGGR) Boundary Gluing Defect

The interaction between local patch evaluations $E_i \in \{0, 1\}$ and the global composite evaluation $E_G \in \{0, 1\}$ is quantified by `LggrGluingAdapter` (`ops/adversary/infrastructure/lggr_adapter.py`):

$$\Delta_E = E_G - \prod_{i=1}^5 E_i$$

### Boundary Defect Classifications:
1. **$\Delta_E = -1$ (`NegativeGluingDefect_LocalGreenGlobalRed`):**
   - Every individual agent satisfies local structural and schema constraints ($\prod E_i = 1$), but the global composite evaluation fails ($E_G = 0$).
   - This occurs when agents disagree on the total, or when all agents agree on an incorrect sum.
   - Detects non-factorization defects where local checks are insufficient to guarantee global truth.
2. **$\Delta_E = 0$ (`ZeroDefectResidual`):**
   - The local and global evaluations are concordant (either all pass, or at least one local check fails alongside global failure).
3. **$\Delta_E = 1$ (`PositiveGluingDefect`):**
   - Global evaluation passes while one or more local evaluations fail (forbidden under WF4's strict consensus rule).

---

## 4. Strict Non-Voting Rule

WF4 explicitly prohibits majority voting:
- If 4 agents output `total = 15` and 1 agent outputs `total = 16`, the run does NOT accept `15`.
- Any local failure, disagreement, or schema defect forces the global status to `TYPED_REFUSAL`.
- The host accepts the run (`HOST_ACCEPTED`) if and only if all 5 agents pass locally, all 5 agree unanimously, and the host's independent judge confirms the shared total.

## 6. Claim Hygiene Evaluation

1. **What the Evidence Supports:**
   - Multi-agent parallel execution under accounted atomic reservations is fully operational.
   - The LGGR adapter calculates exact gluing defects $\Delta_E \in \{-1, 0, 1\}$, identifying non-factorization failures.
   - Peer agreement is mechanically rejected as an acceptance criterion without independent host verification.
2. **What the Evidence Does Not Support:**
   - Five agreeing agents do not guarantee correctness; experiments show ensembles can agree on identical false calculations.
3. **Narrowest Defensible Claim:**
   - WF4 provides a multi-agent harness that evaluates 5 isolated solver proposals against local and global contracts, measuring the boundary gluing defect without granting voting authority to the ensemble.
4. **Next Test Needed:**
   - Evaluate WF4 on 30 multi-step modular arithmetic problems to identify the empirical incidence rate of $\Delta_E = -1$ across model families.
