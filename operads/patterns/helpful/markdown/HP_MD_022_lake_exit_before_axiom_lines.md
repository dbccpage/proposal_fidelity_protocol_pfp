# Healthy Pattern: The Lake Exit Comes Before Axiom Lines (`HP_MD_022`)

## Description

The formal stage result is the current `lake build` exit and the `.olean` it failed to create. Axiom-free info lines in that log name only the declarations that printed them. They do not replace exit 1.

## Construction

- Write exit 1 and the `.olean` create error next to any `does not depend on any axioms` line from the same log.
- Keep `formal_lean4_mechanization` at `FAIL` when the build exits 1. Do not promote stage 1's mechanized-proof bullet to that result.
- Name the failed target. A paper-edition `rebuild` command is not a repair of `failed to create file`.
- Do not attach proof editing, algorithm redesign, or further mathematical research unless a listed unresolved error is that kind of gap. The shared fuel-exhausted sentence does not name an `.olean` create.
- Leave pytest, ruff, notebook, and packaging results on their own stages.
- Do not invent the filesystem cause. Path length, permissions, and a missing directory are not distinguished by this receipt.

## Limit

No gate, pytest, ruff, notebook, or Lean command was rerun. The recorded stage-2 `FAIL` is historical. This digest did not decide why the `.olean` create failed, and it did not rerun `lake build`.
