# Healthy Pattern: The Direct Baseline Comes Before A Cochain Gain (`HP_MD_031`)

## Description

An efficiency sentence names enumeration and the strong direct reconstruction before it attributes any drop in checker calls to a cochain encoding. If the encoding does not beat that direct baseline, the sentence says no efficiency advantage is established.

## Construction

- Report checker calls for enumeration, for direct reconstruction, and for the cochain method as three counts.
- Include representation, canonical closure, and repair work the cochain method adds on a successful proposal.
- Attribute a gap versus enumeration to the encoding only when the same count also beats the direct reconstruction, with that extra work included.
- If the cochain count matches the direct count and adds work, write that no efficiency advantage is established.
- Keep the count as a partial operational metric. Do not promote it to wall-clock cost, a weighted total, or another workload.
- Leave correctness with the declared checker. A negative efficiency result does not retract a scoped acceptance bridge, and a closure check does not replace that checker.

## Limit

The counts 20375, 125, and 125, and the audit sentence that forbids an enumeration-only comparison, are the historical witness in [AP_MD_031_enumeration_baseline_credits_cochain](../../anti/markdown/AP_MD_031_enumeration_baseline_credits_cochain.md). This digest did not rerun them. The frozen comparison already uses the direct baseline. This pattern does not say a current manuscript still claims a cochain speedup.

`AP_MD_004` still owns an unfixed comparison family for unique acceptance. `woland-check-sensitivity-pattern` still owns a component check that misses a property-changing mutation. `woland-proof-scope-rule` still owns a collision or fidelity claim widened past its premises. This pattern only stops an efficiency sentence from crediting a cochain encoding with a gain the direct reconstruction already has.
