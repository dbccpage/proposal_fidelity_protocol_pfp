# Healthy Pattern: Typed Checker Receipt Binding (`HP_AUTOP_001`)

## Description

Require that every terminal status of `PASS`, `PASS_TO_MASTER`, or `completed` in an orchestration run, summary, or report explicitly binds a non-null, cryptographically verifiable `checker_receipt` generated by an actual execution of the underlying verifier binary, test harness, or proof kernel.

## Benefits

- **Fail-Closed Verification Integrity:** Prevents narrative or literary reviews from substituting for executable tests.
- **Audit Traceability:** Downstream systems can verify the exact command, exit status, stdout/stderr hashes, and timestamp recorded in the machine receipt.
- **Honest Residual Accounting:** When verifiers cannot be executed (e.g. offline environments, lack of dependencies, or resource constraints), the run truthfully preserves `OPEN_RESIDUAL` rather than falsely signaling completion.

## Implementation Pattern

In runner and summary generation logic:
```python
def finalize_run_summary(
    task_id: str,
    checker_receipt: dict | None,
    open_obligations: list[str],
) -> dict:
    if checker_receipt is None or checker_receipt.get("status") != "PASS":
        verdict = "OPEN_RESIDUAL"
        if not open_obligations:
            open_obligations.append("Fresh host acceptance of current candidate is required.")
    else:
        verdict = "PASS_TO_MASTER"

    return {
        "task_id": task_id,
        "terminal_verdict": verdict,
        "checker_receipt": checker_receipt,
        "open_obligations": open_obligations,
    }
```

## Evidence & Verification

Observed in `_ic/adversary/runs/` digestion:
- 47 runs correctly preserved `OPEN_RESIDUAL` when `checker_receipt` was `null`, accurately identifying pending host acceptance.
- 3 legacy runs recorded `PASS_TO_MASTER` despite having `checker_receipt: null`. Applying this pattern ensures future automated digestion immediately detects and prevents ungrounded pass claims.
