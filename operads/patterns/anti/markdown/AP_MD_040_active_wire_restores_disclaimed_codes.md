# Anti-Pattern: An Active Wire Restores Disclaimed Codes (`AP_MD_040`)

## Description

A companion rewriting note calls itself an active formal engine and mints evaluator error codes. The same strand's chapters say those names are labels, the grammar is notation, an empty relation has no successor, and a sufficient summary can replace raw history.

## Detection Signature

- The note's status line says it is an active architectural specification and a formal rewriting-engine reference.
- It assigns `AP-PG01` through `AP-PG06` and codes `ERR_LEXICAL_ALPHABET`, `ERR_NESTING_DISALLOWED`, `ERR_SPONTANEOUS_STEP`, `ERR_UNLICENSED_COUNTING`, `ERR_ONE_TURN_BLINDNESS`, and `ERR_UNEARNED_UNIQUENESS`.
- The strand README says earlier chapter versions contained antibody, refusal, and error-code names that exist nowhere else, and that the grammar is notation, not a finding.
- Chapter 04 says none of the failure names is a detector, a refusal code, or an admitted antibody.
- The note sets the rewrite relation empty, then Strategy PG1 rewrites `<>` to `<>`.
- The note says the Proposal Fidelity Protocol requires append-only history. Chapter 03 says a sufficient summary can replace the raw history. Chapter 04 says the trials did not test PFP.
- The same note refuses glyphs outside `{<, >, a, b}` and refuses nesting, then writes `{<>,<a>}` and nested `<<cert>...` receipts.
