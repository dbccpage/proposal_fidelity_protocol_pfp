## Contract and execution checks

1. Inspect the real consuming port and declare independent intended input/output
   signatures, ordered occurrences, source pins, effects and authority ceilings.
   Recompute bindings from the supplied task; a stored digest alone is insufficient.
2. Observe a real failure at that public port, repair its existing owner, then
   rerun the same bounded controls. Reused passing behavior is not a new failure.
3. Keep planar substitution ordered. For zero-based nested slots use
   `(A o_i B) o_(i+j) C = A o_i (B o_j C)`; for disjoint original slots `i < k`,
   the shifted second slot is `k + arity(B) - 1`. Preserve structural units,
   nullary operations, repeated-colour occurrences and tuple-valued inputs.
4. Refuse malformed declared types, stale source/candidate pins, invalid guard
   slots and unavailable executors through existing typed refusals. Never erase
   malformed effects or operands by defaulting them to empty lists.
5. Shared outputs, loop execution and automatic permutation expansion require
   separately selected semantics. Do not infer them from graph topology or names.
6. Bind execution records to actual inputs, operation/inventory/interpreter
   versions and accounting. Record only operations that ran. A declared route or
   schema-valid reply is not execution evidence or task acceptance.

## Practical verification and delivery

Run small owning test batches and selected Cargo targets with `-j 1`. Use writable
temporary outputs; preserve tracked fixtures. Include harmful, benign, malformed,
transplant and recovery controls relevant to the changed boundary. Finite parity
does not prove arbitrary callables satisfy mathematical laws.

Use the existing selected-package generator/synchronizer for host files. Preserve
host-maintained resources; package parity does not establish IDE activation.
Keep changed skill Markdown below 300 lines and 20 KB, UTF-8 without BOM.

Paid pilots retain one continuing ledger across restarts. An ambiguous send keeps
its worst-case liability and stops dispatch until an explicit authorized
reconciliation. Never silently reset spending, substitute a model or rerun failures
to improve a report. Keep unknown usage and experimental uncertainty visible.

Finish the outer Woland run with [auto-oe-autop](../auto-oe-autop/SKILL.md) and
auto-learn once. Apply a supported correction to code or existing typed guidance,
recheck the original task and regenerate only affected host packages. Routine
finish is not a whole-estate sweep. No HoTT, new framework or production custody
project is implied by ordinary development work.

## Lessons from the completed integration

- A Python dataclass's new optional field may still serialize as `null`. Check
  the actual strict native wire before claiming compatibility. The replacement
  field controls in `tests/integration/test_catalog_composition_contract.py` and
  `test_higher_operad_adapter.py` distinguish the field rejection from the intended
  colour/schema/validator refusal. Preserve legacy omission and lifecycle checks.
- A captured HTTP-200 reply with reported usage can be unpriced because the meter
  does not recognize a new billing field. The observed example was standard
  Anthropic speed. Repair the owning meter, then reprice the same hash-bound raw
  reply through keyless native replay; never resend it to obtain accounting.
  Keep unknown billing variants unknown, thinking tokens within output tokens,
  and the existing size bound before both Python and native retained-file reads.
  Harmful controls are changed raw bytes, oversized files and unknown speed;
  the benign control is the unchanged standard-speed response priced once.
