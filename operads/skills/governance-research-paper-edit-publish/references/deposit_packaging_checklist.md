# Deposit Packaging Checklist & Release Verification Reference

**AuthorityEffect:** None.  
**Domain Context:** `governance-research-paper-edit-publish`, `governance-paper-deposit`

This reference documents the procedural packaging workflows, deposit envelope manifests, rebuild vs. read-only verification distinctions, and negative control testing policies.

---

## 1. Dependency Locks vs. Transient Process Locks

- **Preserved Dependency Locks:** Reproducible build manifests and dependency resolution locks (`Cargo.lock`, package lockfiles) MUST be preserved in deposit packages and never stripped.
- **Excluded Transient Locks:** Only transient process/installer locks (e.g. `*.lock` generated by runtime concurrency or package manager temp locks) are excluded from deposit archives.

---

## 2. Rebuild vs. Read-Only Verification

- **Build vs. Verification Distinction:** Running `rebuild_release.py` updates or regenerates release assets and checksums; it does not substitute for independent verification.
- **Read-Only Verification:** `verify_deposit.py` MUST execute strictly read-only checks validating that existing checksum manifests match payload bytes without modifying any file on disk.
- **Hermeticity:** The extracted release package must be verified in isolation without ambient monorepo imports or environmental leaks.

---

## 3. Negative Control Outcomes vs. Test Failures

- **Structured Refusal in Negative Controls:** A correctly refused negative-control input (e.g. invalid certificate, perturbed basis) is an expected outcome of a passing test. Verifiers must bind test success to the expected structured result (`Refusal` or exception); unexpected bypass or unexpected refusal must fail.
- **Archive Self-Reference Exclusion:** Generated zip and tar archives must avoid self-reference in `SHA256SUMS` manifests by computing digests strictly over tracked source files.

---

## 4. Release ZIP Member Parity & Bit-Level Normalization

- **Exact Bijection with Manifest:** The release zip must contain strictly the files in `SHA256SUMS` plus `SHA256SUMS` itself (or `MANIFEST.sha256`).
- **Required Metadata Documents:** `docs/descriptions.md` must be present in the zip whenever it exists on disk in the package.
- **Zero Unmanaged Reader Artifacts:** Unmanaged root PDFs or stale compiled binaries not derived from canonical source digests must never be included.
- **Member timestamps:** Follow `rl_paper_harmonization_and_provenance_discipline.md`. The template script is `coda_atlas/_kits/paper_template/scripts/build_deposit_zip.py`.

---

## 5. Republication Pre-Flight Gates & Evidence Resolution

- **Claim Evidence Resolution:** Every referenced theorem, Lean module, and computational test in claim tables must resolve to active code.
- **Superseded Claim Quarantine:** Historical archive members with byte-pinned tarballs must never be mutated; scope retractions must be documented in `superseded_notice.md`.
- **Exact Custody Equality:** Test suites verifying archive membership must assert exact equality against `release_manifest.json` `custody_counts` (`len(members) == expected`).
- **PDF/TeX Parity:** The rendered PDF and exported TeX must match the latest markdown source, including references [1]–[N] and version/date stamps.
- **Component License Table:** `README.md` and package metadata must explicitly map licenses across prose, code, and test receipts.
- **Fail-Closed Verification:** `verify_deposit.py` must fail closed with non-zero exit on missing dependencies, missing schemas, or malformed inputs.
