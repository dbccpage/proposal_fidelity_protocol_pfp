# Benchmark accounting boundary

The ceiling is USD 0.10 **per complete workflow execution**, not per model call. Include all branches, retries and chargeable model judges. `budget_ledger.py` provides durable, transactionally serialized reservations in integer microusd. Pending/uncertain calls retain their entire reservation. A reused call identifier cannot dispatch again. Observed overruns remain in the record and block the run.

The run ledger, finite campaign ledger and guarded OpenRouter adapter are implemented and tested with synthetic transport responses. No paid request has been made. A reservation is a hard upper bound only if the quote covers all chargeable usage and the provider enforces the assumed bounds. Post-response accounting cannot reverse an overcharge. Do not turn a bytes-per-token estimate into a guaranteed input bound. See `LIVE_RUNNER.md` for the supported adapter's conservative context-window quote and refusals.

Live admission must pin the model and provider, current tariff evidence, all applicable price overrides and fixed/reasoning/cache fees, supported token ceilings, conservative input bounds, and a run-wide/campaign-wide budget. Unsupported billing components or uncertain bounds cause refusal before dispatch. No tools, paid search or implicit retries are enabled. Do not count unknown usage as zero.

OpenRouter documents provider price ceilings in USD per million prompt/completion tokens, with optional per-request limits; these ceilings filter routing and are not a complete workflow budget. Its model metadata uses per-token/request units and may contain conditional overrides. Usage responses contain actual token/cost data. See [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection), [pricing metadata](https://openrouter.ai/docs/guides/overview/models), and [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting).

Anthropic's token-counting endpoint is useful for preflight, but its documentation describes counts as estimates. Treat input framing uncertainty explicitly. See [token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting). Account-level controls are an additional layer, not a substitute for per-run reservations; see [OpenRouter spend controls](https://openrouter.ai/docs/guides/best-practices/spend-controls).

Metrics must retain model/provider identities, request/output hashes, input/output/reasoning/cache tokens when available, reported charge, reservation, wall time and sum of provider times. Parallelism changes wall time, not the sum of costs. The independent private evaluator runs after candidate bytes are frozen and must be costed separately or included explicitly in the run budget.
