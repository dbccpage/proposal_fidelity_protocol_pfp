# Two shared ACSet pilot owners

Both imported ACSet pilots duplicate existing WF21 implementations. Their core pilot/checker sources are byte-identical; the remaining differences are legacy Woland/adversary command or import names. No new workflow family is warranted.

The mathematics is useful and bounded. The executor constructs finite attributed-graph rewrites with explicit injective matches, identity-key interface inclusions, dangling checks, protected elements, fresh identifiers and decreasing fuel. It neither searches for matches nor proves confluence. The prompt judge independently compares ordered protected bytes and source identity. The cochain judge checks every exact rational edge residual against a supplied fixed potential, preserving vertices and oriented multiplicity; cancellation of an aggregate residual is insufficient.

All nine imported primary files, the corresponding WF21 content and complete diffs, both canonical 25-test sources, and the finite executor were reviewed. The imported README test paths are absent. The canonical test invocation produced two collection errors because `omega_engine_pfp` is unavailable. Six isolated finite kernel/gradient probes passed under an explicitly declared import binding; these are not an end-to-end pilot run. The prompt runner also retains an invalid parent-relative monorepo source path.

Keep WF21 as the single mechanism owner, repair its package/resource boundary and rerun its tests before consolidation. Protected seed bytes can be retained by this mechanism, but its cochain judge cannot grade an arbitrary QM derivation. No accuracy, token-saving or cost-saving benefit has been measured.

Exact source pins and assessments are in `shared_acset.json`; the original-corpus reading receipts also appear in `../reviews/additional_imported_acset.json`. No source files were changed or deleted, and no model was called.
