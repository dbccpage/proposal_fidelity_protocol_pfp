## 1. Claim Statement

Let $T$ be a finite suite of $N = 150$ test cases partitioned into four pairwise-disjoint execution outcomes $T = E_{\text{pass}} \sqcup E_{\text{fail}} \sqcup E_{\text{missing}} \sqcup E_{\text{exc}}$ with cardinalities $n_{\text{pass}} + n_{\text{fail}} + n_{\text{missing}} + n_{\text{exc}} = 150$. Under any runner status rule $\sigma_{\text{perm}}$ that maps $E_{\text{pass}} \mapsto \text{PASSED}$, $E_{\text{fail}} \mapsto \text{FAILED}$, and $(E_{\text{missing}} \cup E_{\text{exc}}) \mapsto \text{VERIFIED}$ while reporting numerator $S_{\text{perm}} = |\{t \in T : \sigma_{\text{perm}}(t) \in \{\text{PASSED}, \text{VERIFIED}\}\}|$, the summary equality $S_{\text{perm}} = 150$ holds whenever $n_{\text{fail}} = 0$, leaving $n_{\text{pass}} \in \{0, 1, \dots, 150\}$ unconstrained ($n_{\text{pass}} = 150 - n_{\text{missing}} - n_{\text{exc}}$). Retained Paper 008 audit records and repository remediation tests document that historical `projects/mssn_sn_symgam/challenges/run_150_tests_suite.py` at external commit `52cb5457f6c485ba548cfd292f6012a941ed22cf` exhibited this permissive `"VERIFIED"` fallback on missing receipts and caught exceptions (with `c005_working_report.md` recording only 10 live queries under the 150-test suite), so a `"150/150"` headline ratio does not entail 150 completed, verified executions.

### 3.2 Exact Algebraic Non-Identifiability Under Permissive Label Aggregation
Partition a 150-case suite $T$ (`|T| = 150`) into four disjoint execution classes:
- $E_{\text{pass}}$ (`n_pass`): receipt present or deterministic check executed with zero exceptions and passing oracle check;
- $E_{\text{fail}}$ (`n_fail`): deterministic check executed and returned an explicit check failure;
- $E_{\text{missing}}$ (`n_missing`): required run receipt file absent from storage;
- $E_{\text{exc}}$ (`n_exc`): execution raised a runtime exception caught by a broad handler.

By disjoint union, $n_{\text{pass}} + n_{\text{fail}} + n_{\text{missing}} + n_{\text{exc}} = 150$.

Compare two status-aggregation maps:
1. **Permissive runner map $\sigma_{\text{perm}}$**:
   $$\sigma_{\text{perm}}(t) = \begin{cases} \text{PASSED} & t \in E_{\text{pass}}, \\ \text{VERIFIED} & t \in E_{\text{missing}} \cup E_{\text{exc}}, \\ \text{FAILED} & t \in E_{\text{fail}}, \end{cases} \qquad S_{\text{perm}} = n_{\text{pass}} + n_{\text{missing}} + n_{\text{exc}} = 150 - n_{\text{fail}}.$$
   Whenever $n_{\text{fail}} = 0$, $S_{\text{perm}} = 150$ (`"150/150"`), regardless of how many rows lie in $E_{\text{missing}} \cup E_{\text{exc}}$:
   - At $(n_{\text{pass}}, n_{\text{missing}}, n_{\text{exc}}, n_{\text{fail}}) = (10, 130, 10, 0)$, $S_{\text{perm}} = 150$ while completed verified fraction is $\frac{10}{150} = \frac{1}{15}$.
   - At $(n_{\text{pass}}, n_{\text{missing}}, n_{\text{exc}}, n_{\text{fail}}) = (0, 75, 75, 0)$, $S_{\text{perm}} = 150$ while completed verified fraction is $\frac{0}{150} = 0$.
   In fact, across all non-negative integer triples $(n_{\text{pass}}, n_{\text{missing}}, n_{\text{exc}})$ summing to $150$, there are $\binom{150 + 2}{2} = \frac{152 \times 151}{2} = 11{,}476$ distinct outcome distributions that all collapse to the identical summary `"150/150"`, of which only $1$ distribution—$(150, 0, 0)$—represents $150$ completed, verified executions.

2. **Fail-closed receipt-bound map $\sigma_{\text{strict}}$**:
   $$\sigma_{\text{strict}}(t) = \begin{cases} \text{PASSED} & t \in E_{\text{pass}}, \\ \text{NOT\_RUN} & t \in E_{\text{missing}}, \\ \text{FAILED} & t \in E_{\text{fail}} \cup E_{\text{exc}}, \end{cases} \qquad S_{\text{strict}} = n_{\text{pass}}.$$
   Under $\sigma_{\text{strict}}$, $n_{\text{pass}} + n_{\text{not\_run}} + n_{\text{fail}}^{\text{strict}} = 150$ with $n_{\text{not\_run}} = n_{\text{missing}}$ and $n_{\text{fail}}^{\text{strict}} = n_{\text{fail}} + n_{\text{exc}}$, so $S_{\text{strict}} = 150$ holds if and only if $n_{\text{missing}} = n_{\text{exc}} = n_{\text{fail}} = 0$.

## 4. Limits and Non-Claims

1. **External Baseline Runner and Custody Package Not Checked Out**: `projects/mssn_sn_symgam/challenges/run_150_tests_suite.py` (both at `52cb5457` and its later `projects/` revision imported by `test_c005_bakeoff.py`) and `operating_system.adapters.intelligence_custody.intelligence_root` (imported by `run_adversary_bakeoff.py` line 73) reside outside `proposal_fidelity_protocol_pfp`.
2. **Audit Scope vs. Underlying Tasks**: Establishing that `"150/150"` under $\sigma_{\text{perm}}$ fails to imply 150 completed runs invalidates the aggregate suite label; it makes no claim that individual deterministic checkers in C005 (`checkers.py`) fail on valid inputs.

## 5. Claim Hygiene Summary

1. **What it supports**: Establishes from Paper 008's retained audit records, `c005_working_report.md` (`10 live` queries), `test_c005_bakeoff.py` counterexample specifications, exact combinatorial partition arithmetic ($11{,}476$ non-equivalent outcome triples mapping to $150/150$ when missing receipts and exceptions map to `VERIFIED`), and `run_adversary_bakeoff.py` failure-receipt execution that `"150/150"` under the historical runner does not imply 150 completed runs.
2. **What it does not support**: Does not directly execute `projects/mssn_sn_symgam/challenges/run_150_tests_suite.py` inside this standalone repository checkout, and does not adjudicate live model accuracy on C005.
3. **Narrowest defensible claim**: Because missing-receipt and caught-exception branches mapped to `"VERIFIED"` and counted toward `PASSED + VERIFIED`, $11{,}475$ incomplete or errored 150-case outcome partitions with $n_{\text{fail}} = 0$ produce the same `"150/150"` numerator as $(150, 0, 0, 0)$.
4. **Next test needed**: Keep `NOT_RUN` and `FAILED` disjoint from `PASSED` in all suite aggregators and require SHA-256-verified per-case receipts before incrementing any verified-execution counter.
