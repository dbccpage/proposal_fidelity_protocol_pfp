## 1. Claim Statement

In `code/l1_symbol_game_governor.py`, the `step_cut` method enforces a non-increase admission condition on proposed state transformations. For both section cuts (potential updates) and relational cuts (claim updates), a proposal is admitted if and only if the evaluated post-move defect is less than or equal to the pre-move defect ($\text{defect}_{\text{after}} \le \text{defect}_{\text{before}}$). Proposals that yield strictly greater defect ($\text{defect}_{\text{after}} > \text{defect}_{\text{before}}$) are refused with status `DefectIncrease`. Proposals leaving the defect unchanged ($\text{defect}_{\text{after}} == \text{defect}_{\text{before}}$) are admitted with status `IdempotentStationary`.

## 2. Context & Hypotheses

- **Target Implementation**:
  - `L1SymbolGameGovernor.step_cut` in `code/l1_symbol_game_governor.py`.
- **Governed Quantities**:
  - For section proposals: section defect $D(s) = \sum_{e=(u,v)} w_e |c(u,v) - (s(v) - s(u))|$.
  - For relational claim proposals: primary quotient obstruction $\Phi_1(c)$.
- **Admission Invariant**:
  - Enforces weak monotonicity (non-increase: $\le$), not strict decrease ($<$).

## 3. Derivation / Evidence

### 3.1 Section CUT Admission Logic
In `step_cut` for `proposed_section`:
```python
defect_before = self.section_defect()
...
defect_after = self.section_defect(proposed_section)

if defect_after > defect_before:
    return GovernorVerdict(
        admitted=False,
        status="DefectIncrease",
        defect_before=defect_before,
        defect_after=defect_after,
        details=f"Section defect increased from {defect_before} to {defect_after}. Monotonic descent violated.",
        step_id=sid,
    )

self.section = {v: proposed_section.get(v, Fraction(0)) for v in self.graph.vertices}

status = "ExactRepair" if (defect_after == Fraction(0) and defect_before > Fraction(0)) else (
    "MonotonicDescent" if defect_after < defect_before else "IdempotentStationary"
)
```
When $\text{defect}_{\text{after}} == \text{defect}_{\text{before}}$, the predicate `defect_after > defect_before` evaluates to `False`. The proposal is admitted, and the verdict receives `status = "IdempotentStationary"`.

### 3.2 Relational Claims CUT Admission Logic
In `step_cut` for `proposed_claims`:
```python
phi_before = self.primary_obstruction()
phi_after, _ = compute_phi1(self.graph, Cochain1(values=dict(proposed_claims)))

if phi_after > phi_before:
    return GovernorVerdict(
        admitted=False,
        status="DefectIncrease",
        defect_before=phi_before,
        defect_after=phi_after,
        details=f"Primary obstruction increased from {phi_before} to {phi_after}. Monotonic descent violated.",
        step_id=sid,
    )
...
status = "ExactRepair" if (phi_after == Fraction(0) and phi_before > Fraction(0)) else (
    "MonotonicDescent" if phi_after < phi_before else "IdempotentStationary"
)
```
Similarly, if $\Phi_1(\text{after}) == \Phi_1(\text{before})$, the proposal passes the monotonic check and is committed with status `"IdempotentStationary"`.

### 3.3 Stationary Moves with Distinct Claims
Admitting stationary moves allows the claims to change while preserving the checked score. For example, on the directed triangle with weights $(1, 2, 3)$ and initial claims $(1, 1, 1)$, $\Phi_1 = 3$. Proposing alternative claims $(2, 1, 0)$ also evaluates to $\Phi_1 = 3$:
1. $3 \le 3$, so the condition is satisfied.
2. The move is admitted with `status == "IdempotentStationary"`.
3. The stored claims are updated from $(1, 1, 1)$ to $(2, 1, 0)$.

## 4. Limits and Non-Claims

1. **No Termination Bound**: Because stationary moves ($\text{defect}_{\text{after}} == \text{defect}_{\text{before}}$) are admitted, the non-increase rule alone does not establish finite termination of an arbitrary sequence of CUT proposals. Cycles or infinite sequences of stationary transitions are not excluded by this gate alone.
2. **Local Gate Only**: Monotonic non-increase is enforced per individual step; it does not govern whole-session monotonicity across `step_retract` operations, which can restore higher-defect historical states.
3. **No Optimality Assertions**: Admitting a stationary move does not claim that the resulting configuration is a global minimum.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `step_cut` checks $\text{defect}_{\text{new}} \le \text{defect}_{\text{old}}$, refusing strictly increasing proposals (`>`) and admitting non-increasing proposals ($\le$), including stationary moves.
2. **What it does not support**: Does not support search convergence, finite termination, or uniqueness of minimizing configurations.
3. **Narrowest defensible claim**: In `code/l1_symbol_game_governor.py`, `step_cut` admits a proposal if and only if the evaluated score does not exceed the prior score, admitting equal-score proposals with status `IdempotentStationary`.
4. **Next test needed**: Verification of stationary cycle detection and proposal attempt budget limits in multi-turn game harnesses.
