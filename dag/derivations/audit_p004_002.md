## 1. Claim Statement

The restricted prime host binds a finite carrier complex $K = (V, E, F)$ under explicit dimension bounds and parses wire inputs using minimal signed i128 decimal string representations before exact rational solve and candidate replay. Any non-minimal encoding or carrier fence violation is refused during input decoding prior to solver invocation.

## 2. Context & Hypotheses

- **Native Host Implementation**:
  - Implemented in `code/rust/pfp/src/host.rs` and `code/rust/pfp/src/protocol.rs`.
- **Wire Encodings**:
  - Encoded in `HostRequestV1`, `CarrierDeclarationV1`, and `CarrierInputV1` data structures.
- **Exact Numeric Representation**:
  - Exact rationals over $\mathbb{Q}$ represented as `BigRational` with numerators and denominators decoded from minimal decimal signed 128-bit integers.

## 3. Derivation / Evidence

### 3.1 Minimal Signed i128 Wire Decoding
In `code/rust/pfp/src/protocol.rs:480-488`, `parse_i128` enforces canonical decimal representation:
```rust
fn parse_i128(value: &str, label: &str) -> Result<i128, String> {
    let parsed = value
        .parse::<i128>()
        .map_err(|_| format!("{label} is not a minimal signed i128"))?;
    if parsed.to_string() != value {
        return Err(format!("{label} is not minimally encoded"));
    }
    Ok(parsed)
}
```
1. Syntax check: String must parse to a 128-bit signed integer in $[-2^{127}, 2^{127}-1]$.
2. Canonical bijection: `parsed.to_string() == value` rejects:
   - Explicit plus signs: `"+0"`, `"+42"`.
   - Redundant leading zeros: `"00"`, `"07"`, `"-07"`.
   - Negative zero: `"-0"`.
   - Whitespace or trailing characters: `" 42"`, `"42 "`, `"42\n"`.
   - Non-integers: `"1.0"`, `"0x2A"`, `"NaN"`.

### 3.2 Finite Carrier Resource Fence
In `code/rust/pfp/src/protocol.rs`:
A valid 2-dimensional carrier complex $K = (V, E, F)$ must satisfy:
1. $0 < |V| \le 4096$.
2. $|E| \le 4096$.
3. $|F| \le 4096$.
4. $|V| + |F| \le 4096$.
5. Matrix cell bounds: $|V| \times |E| \le 16777216$ and $|F| \times |E| \le 16777216$.

Any declaration violating these bounds is refused with `RESOURCE_FENCE_EXCEEDED` before solver allocation.

### 3.3 Coefficient Domain and Semantics
In `code/rust/pfp/src/protocol.rs:490-495`:
`build_carrier` verifies:
```rust
if declaration.coefficient_domain != "Q"
    || declaration.coefficient_representation != "BigRational"
{
    return Err("carrier must declare Q/BigRational coefficient semantics".to_owned());
}
```
Non-rational domains (such as `"R"`, `"f64"`, or `"Integer"`) are refused immediately.

### 3.4 Residual Dimension Matching
Wire inputs supply residual cochains `before_residual_omega_i128` and `candidate_omega_i128`. The host asserts that the length of both vectors equals $|E|$. Length mismatches trigger `RESIDUAL_DIMENSION_MISMATCH`.

## 4. Limits and Non-Claims

1. **Intake Verification Only**: Establishes input validation and resource bounding prior to execution; does not evaluate solver convergence or global optimality for unbounded complexes.
2. **Finite Fence Boundary**: Applies to carrier complexes within the declared 4096 dimension envelope.
3. **Wire Protocol Scope**: Validates JSON wire decoding of `HostRequestV1`; does not characterize alternate serialization protocols.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that the restricted prime host enforces minimal signed i128 encoding, finite carrier dimension fences, and $Q$/BigRational coefficient checks during intake prior to solve.
2. **What it does not support**: Does not support claims of host behavior on carriers exceeding 4096 vertices/edges/faces.
3. **Narrowest defensible claim**: For `HostRequestV1` payloads submitted to the restricted host, non-minimal i128 encodings, carrier overflow beyond 4096 dimensions, and non-rational coefficient domains are refused before solver invocation.
4. **Next test needed**: Fuzzing the JSON deserializer with boundary i128 strings and deeply nested carrier declarations.
