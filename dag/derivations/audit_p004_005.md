## 1. Claim Statement

In the native host contract test suite, rehashed carrier mutations trigger `CARRIER_MANIFEST_MISMATCH` refusal, rehashed candidate mutations trigger `CANDIDATE_NOT_REPLAYED_NORMAL_FORM` refusal, and tampered outcome records fail cryptographic outcome root verification. A locally rehashed outcome retains `attestation: "unsigned_lab"` and cannot forge authoritative acceptance.

## 2. Context & Hypotheses

- **Native Host Implementation**:
  - Implemented in `code/rust/pfp/src/host.rs` and `code/rust/pfp/src/protocol.rs`.
- **Contract Verification Suite**:
  - Validated in `code/rust/tests/pfp/host_contract.rs`.
- **Named Test Fixtures**:
  1. `independently_rehashed_carrier_mutation_cannot_reuse_manifest_anchor`
  2. `independently_rehashed_candidate_must_equal_replayed_normal_form`
  3. `a_locally_rehashed_outcome_is_not_a_fresh_replay`

## 3. Derivation / Evidence

### 3.1 Rehashed Carrier Manifest Mismatch
When an adversary mutates carrier edge weights or boundary declarations (e.g. changing edge weight $1 \to 2$) and rehashes `request_id_sha256` to conceal the perturbation:
1. The host recomputes the carrier manifest hash directly from the decoded topology.
2. The recomputed hash diverges from the carrier manifest anchor registered in the request header.
3. The host terminates execution before solver allocation, emitting `HostOutcomeV1` with:
   - `execution_status: "REFUSED"`
   - `admission.kind: "Refused"`
   - `refusal.code: "CARRIER_MANIFEST_MISMATCH"`
   - `oesos_result: None`

### 3.2 Rehashed Candidate Replay Refusal
When an adversary mutates the proposed candidate residual vector (e.g. altering `candidate_omega_i128` at coordinate 4) and updates the top-level request hash:
1. The host executes exact normal-form solve on the carrier complex.
2. The replayed normal-form residual $r^*$ diverges from the mutated candidate vector.
3. The host refuses the request, emitting `HostOutcomeV1` with:
   - `execution_status: "REFUSED"`
   - `admission.kind: "Refused"`
   - `refusal.code: "CANDIDATE_NOT_REPLAYED_NORMAL_FORM"`
   - `prime000_result: None`

### 3.3 Cryptographic Outcome Root Verification
The host envelope contains an unkeyed SHA-256 root computed over canonical outcome fields:
- `request_id_sha256`
- `execution_status`
- `refusal_code`
- `diagnostic_kind`
- `total_runtime_micros`

When an adversary edits an emitted outcome (for example, mutating `diagnostic_kind` from `None` to `Some("ClosedResidual")`):
`verify_outcome_root(&forged)` returns `false`.

### 3.4 Unsigned Lab Attestation Barrier
Even if an attacker recomputes the local SHA-256 root over the altered payload:
1. The outcome retains `attestation: "unsigned_lab"`.
2. The local unkeyed root detects accidental corruption relative to a recorded digest, but does not identify the signing entity.
3. Because `admission.kind` remains `"Refused"`, local tampering cannot fabricate authoritative acceptance.

## 4. Limits and Non-Claims

1. **Named Test Cases Only**: This result confirms refusal on the named test perturbations in `host_contract.rs`; it does not constitute formal verification against all arbitrary adversarial payloads.
2. **Unkeyed Root Semantics**: An unkeyed hash function detects tampering relative to a recorded digest but does not identify the signing entity or defend against an active adversary with rewriting authority.
3. **Bounded Threat Model**: Operates under the assumption of host process execution integrity.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that named carrier mutations, candidate mutations, and outcome record edits fail verification checks and produce typed refusal outcomes in the native host test suite.
2. **What it does not support**: Does not support claims that unkeyed hash roots provide cryptographic non-repudiation or authentication.
3. **Narrowest defensible claim**: On the named hostile mutation test cases in `host_contract.rs`, mutated carrier manifests yield `CARRIER_MANIFEST_MISMATCH`, mutated candidate vectors yield `CANDIDATE_NOT_REPLAYED_NORMAL_FORM`, and outcome field edits fail `verify_outcome_root`.
4. **Next test needed**: Expanding the hostile mutation test suite with combinatorial fault injection across boundary matrices and non-convex constraints.
