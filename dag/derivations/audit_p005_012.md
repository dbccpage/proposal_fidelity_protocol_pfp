## 1. Claim Statement

In the Paper 005 governor (`code/l1_symbol_game_governor.py`), proposing a relational CUT move via `step_cut(proposed_claims=...)` that omits any declared edge of the constraint graph or supplies a non-exact value (such as a float or Boolean) is refused with status `IncompleteProposal`. Upon refusal, active governor state—including recorded edge claims, vertex potential assignments, and primary obstruction $\Phi_1$—remains unchanged. A complete proposal supplying exact integer or rational values for every declared edge is scored by defect comparison.

## 2. Context & Hypotheses

- **Patched `step_cut` Logic (Review Finding R008-04)**:
  - Prior to the introduction of this check, omitted edge keys were interpreted as zero claims. Under that earlier behavior, an empty dictionary `{}` or partial proposal could achieve $\Phi_1 = 0$ and be admitted as `ExactRepair`.
  - The patched governor introduces a completeness barrier before computing proposed defect values.
- **Declared Graph Carrier**:
  - A finite constraint graph $G = (V, E)$ defines declared edges $E_{\text{keys}} = \{e.\text{key} \mid e \in E\}$.
  - A relational CUT proposal provides candidate claims $c_{\text{prop}}: E' \to \mathbb{Q}$.
- **Refusal Conditions**:
  - Missing declared edges: $E_{\text{keys}} \setminus \operatorname{dom}(c_{\text{prop}}) \neq \emptyset$.
  - Inexact value types: $\exists k \in \operatorname{dom}(c_{\text{prop}}) \cap E_{\text{keys}}$ with $\operatorname{type}(c_{\text{prop}}(k)) \notin (\operatorname{int}, \operatorname{Fraction})$.
- **Obligations**:
  - Zero state modification on refused proposals.

## 3. Derivation / Evidence

### 3.1 Completeness Barrier Implementation
In `l1_symbol_game_governor.py`, lines 695–715:
```python
declared = [e.key for e in self.graph.edges]
missing = [key for key in declared if key not in proposed_claims]
inexact = [
    key for key in declared
    if key in proposed_claims and type(proposed_claims[key]) not in (int, Fraction)
]
if missing or inexact:
    current = self.primary_obstruction()
    problems = []
    if missing:
        problems.append(f"omits declared edges {missing}")
    if inexact:
        problems.append(f"gives non-exact values for {inexact}")
    return GovernorVerdict(
        admitted=False,
        status="IncompleteProposal",
        defect_before=current,
        defect_after=current,
        details=f"Relational CUT {', and '.join(problems)}; must specify exactly one exact int or Fraction for every declared edge.",
        step_id=sid,
    )
```

### 3.2 Refusal on Omission of Declared Edges
Submitting an empty proposal `{}` or a partial dictionary omitting one or more declared edges returns `GovernorVerdict` with:
- `admitted: False`
- `status: "IncompleteProposal"`
- `details` indicating omitted declared edges
- `defect_before == defect_after == Fraction(3)`

### 3.3 Refusal on Non-Exact Types
Submitting a proposal containing a float (e.g. `0.5`) or Boolean (e.g. `True`) returns `GovernorVerdict` with:
- `admitted: False`
- `status: "IncompleteProposal"`
- `details` citing non-exact values

### 3.4 Verification of State Immutability
Following a refused `step_cut`, the governor's internal dictionaries `edge_claims` and `section` match their pre-proposal contents value-for-value. Recomputing `gov.primary_obstruction()` confirms that the active defect is unchanged.

### 3.5 Scoring of Complete Proposals
When every declared edge is explicitly assigned an exact integer or `Fraction` value, the proposal bypasses the completeness barrier. The governor calculates the proposed defect and applies the monotonic descent rule:
- Admitting an all-zero proposal that resolves contradictions as `ExactRepair` ($\Phi_1: 3 \to 0$).
- Refusing defect-increasing proposals with `DefectIncrease`.

## 4. Limits and Non-Claims

1. **Syntactic Completeness vs. Semantic Validity**: Admitting a complete proposal indicates that mathematical defect did not increase; it does not establish that the replacement claims correspond to factual real-world truths.
2. **Relational Scope**: The completeness barrier applies to relational CUT moves (`proposed_claims`); potential updates (`proposed_section`) are audited via section carrier checks.
3. **Finite Instance Bound**: Observations are verified on finite graph complexes; they do not imply that complete proposals can be computed in polynomial time on arbitrary constraint topologies.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `step_cut` refuses relational proposals omitting declared edges or supplying float/bool values with `IncompleteProposal`, and that governor state is preserved without change.
2. **What it does not support**: Does not support external truth of admitted claims, nor does it support automated repair discovery without candidate proposals.
3. **Narrowest defensible claim**: In `l1_symbol_game_governor.py`, `step_cut(proposed_claims=...)` refuses proposals where declared edges are missing or values are float/bool with status `IncompleteProposal`, leaving `edge_claims` and `primary_obstruction` unchanged.
4. **Next test needed**: Automated property-based fuzzing generating arbitrary dictionary shapes to verify that no partial dictionary can bypass `IncompleteProposal`.
