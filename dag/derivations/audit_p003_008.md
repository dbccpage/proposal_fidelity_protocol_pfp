## 1. Claim Statement

In the two-signal evaluation table, Signal 1 alone is diagnostic, a low or medium Signal 2 alone is diagnostic, a high or critical Signal 2 alone yields a refusal, and the co-occurrence of both signals yields a refusal.

## 2. Context & Hypotheses

- **Danger Gate Implementations**:
  - Domain implementation in `pfp/domain/immune/danger_gate.py` (`TwoSignalDangerGate.evaluate`).
  - Archived package implementation in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/danger_gate.py` (`evaluate_two_signal_gate`).
- **Input Spaces**:
  - Signal 1 match evidence $S_1 \in \{\text{absent}, \text{present}\}$, represented by a sequence of syntax/AST epitope match objects (`Sequence[Signal1AstMatch]`).
  - Signal 2 structural danger state $S_2 \in \{\text{absent}, \text{LOW}, \text{MEDIUM}, \text{HIGH}, \text{CRITICAL}\}$, represented by `Signal2DangerState | None` with categorical severity levels.
- **Exact Numeric Representation**:
  - Zero-float invariant: Signal weights and confidence values are represented as exact rationals (`Fraction`, `int`, or exact rational structures). Passing floating-point numbers triggers an immediate `TypeError` via `_assert_zero_float`.

## 3. Derivation / Evidence

### 3.1 Exhaustive Truth Table Evaluation
The two-signal gate maps the Cartesian product of Signal 1 presence $\{0, 1\}$ and Signal 2 severity $\{\text{None}, \text{LOW}, \text{MEDIUM}, \text{HIGH}, \text{CRITICAL}\}$ across 10 discrete cases:

1. **Neither Signal Present** ($S_1 = 0, S_2 = \text{None}$):
   - Decision: `DangerDecision.TOLERATED`.
   - Refusal status: `is_refusal = False`.
   - Disposition: `"TOLERATED"`.
   - Clean execution; no pathogen epitope or structural damage detected.

2. **Signal 1 Alone** ($S_1 = 1, S_2 = \text{None}$):
   - Decision: `DangerDecision.DIAGNOSTIC_ONLY`.
   - Refusal status: `is_refusal = False`.
   - Disposition: `"DIAGNOSTIC_ONLY"`.
   - Pattern match without structural damage is tolerated as benign diagnostic context per Matzinger Danger Theory.

3. **Signal 2 Low Alone** ($S_1 = 0, S_2 = \text{LOW}$):
   - Decision: `DangerDecision.DIAGNOSTIC_ONLY`.
   - Refusal status: `is_refusal = False`.
   - Disposition: `"DIAGNOSTIC_ONLY"`.

4. **Signal 2 Medium Alone** ($S_1 = 0, S_2 = \text{MEDIUM}$):
   - Decision: `DangerDecision.DIAGNOSTIC_ONLY`.
   - Refusal status: `is_refusal = False`.
   - Disposition: `"DIAGNOSTIC_ONLY"`.

5. **Signal 2 High Alone** ($S_1 = 0, S_2 = \text{HIGH}$):
   - Decision: `DangerDecision.DEFENSIVE_LOCKDOWN`.
   - Refusal status: `is_refusal = True`.
   - Disposition: `"REFUSE"`.

6. **Signal 2 Critical Alone** ($S_1 = 0, S_2 = \text{CRITICAL}$):
   - Decision: `DangerDecision.DEFENSIVE_LOCKDOWN`.
   - Refusal status: `is_refusal = True`.
   - Disposition: `"REFUSE"`.

7. **Both Signals Present, Low Severity** ($S_1 = 1, S_2 = \text{LOW}$):
   - Repository decision: `DangerDecision.DEFENSIVE_LOCKDOWN`.
   - Package decision: `DangerDecision.QUARANTINED`.
   - Refusal status: `is_refusal = True`.
   - Disposition: `"REFUSE"`.

8. **Both Signals Present, Medium Severity** ($S_1 = 1, S_2 = \text{MEDIUM}$):
   - Repository decision: `DangerDecision.DEFENSIVE_LOCKDOWN`.
   - Package decision: `DangerDecision.QUARANTINED`.
   - Refusal status: `is_refusal = True`.
   - Disposition: `"REFUSE"`.

9. **Both Signals Present, High Severity** ($S_1 = 1, S_2 = \text{HIGH}$):
   - Decision: `DangerDecision.QUARANTINED`.
   - Refusal status: `is_refusal = True`.
   - Disposition: `"REFUSE"`.

10. **Both Signals Present, Critical Severity** ($S_1 = 1, S_2 = \text{CRITICAL}$):
    - Decision: `DangerDecision.QUARANTINED`.
    - Refusal status: `is_refusal = True`.
    - Disposition: `"REFUSE"`.

### 3.2 Resolution of Severity-Dependence Obligation
The ledger recorded an obligation regarding the severity-dependence of the dual-signal row:
- In `pfp/domain/immune/danger_gate.py`, when both signals co-occur, the gate assigns `DEFENSIVE_LOCKDOWN` if severity is `LOW` or `MEDIUM`, and `QUARANTINED` if severity is `HIGH` or `CRITICAL`.
- In `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/danger_gate.py`, all dual-signal cases assign `QUARANTINED` with disposition `"REFUSED_DUAL_SIGNAL_CORROBORATION"`.
- Under both implementations, every dual-signal combination sets `is_refusal = True`. Thus, the operational refusal invariant holds uniformly across all severity levels when both signals are present.

### 3.3 Zero-Defect and Zero-Float Edge Controls
1. If $S_2$ is provided with `defect_count == 0`, `has_signal2` evaluates to `False`. The gate treats this as absent danger, resulting in `DIAGNOSTIC_ONLY` when $S_1$ is present and `TOLERATED` when $S_1$ is absent.
2. If float values are passed for confidence or weight fields, `_assert_zero_float` raises `TypeError`, preventing floating-point imprecision from affecting threshold comparisons.

## 4. Limits and Non-Claims

1. **Finite Operational Table**: This derivation documents the deterministic input-output mapping of the two-signal gate logic. It does not establish that external detectors provide accurate or unforgeable signals.
2. **No Claim of Security Against Forgery**: The gate assumes trusted upstream inputs; it does not authenticate evidence identifiers or verify the execution integrity of external detector scripts.
3. **No Statistical Generalization**: The decision table specifies categorical routing; it does not predict false-positive or false-negative rates in open-domain LLM evaluation environments.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `TwoSignalDangerGate.evaluate` in `pfp/domain/immune/danger_gate.py` and `evaluate_two_signal_gate` in the package archive compute the exact 10-state decision table where Signal 1 alone is diagnostic, low/medium Signal 2 alone is diagnostic, high/critical Signal 2 alone refuses, and both signals refuse across all severities.
2. **What it does not support**: Does not support claims that the danger gate prevents adversarial evasion, authenticates signal tokens, or provides formal security receipts.
3. **Narrowest defensible claim**: Under the declared discrete input space $\{0, 1\} \times \{\text{None}, \text{LOW}, \text{MEDIUM}, \text{HIGH}, \text{CRITICAL}\}$, the audited gate functions yield `is_refusal = False` if and only if neither signal is present, Signal 1 alone is present, or Signal 2 alone is present with low or medium severity.
4. **Next test needed**: Evaluating end-to-end latency and state stability when the gate is subjected to high-throughput concurrent detector streams.
