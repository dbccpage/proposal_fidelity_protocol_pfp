## 1. Claim Statement

Given an admitted `FiniteGroup` $G$ and `Lattice` $\Lambda$ (`open` with $L, M \ge 2$ or `periodic` with $L, M \ge 3$), `connection_from_directed_links(group, lattice, directed)` in `atlas/archive/pfp/010_pfp_holonomy_checks_and_model_pilots/code/holonomy.py` (lines 426–454, calling `parse_vertex` at lines 418–423 and `Connection` at lines 262–271) deterministically raises `LatticeError` whenever `directed` contains a malformed edge key or vertex coordinate, a duplicate canonicalized edge (such as zero-padded `"00,0->0,1"`), a non-string or undeclared group element, a positive edge $(u, v) \in E_+$ missing either $(u, v)$ or $(v, u)$, an orientation-reversal inverse mismatch $U_{vu} \ne U_{uv}^{-1}$, or any directed edge outside $E_+ \sqcup E_+^{\mathrm{op}}$.

## 3. Derivation / Evidence

### 3.1 Six-Stage Validation Pipeline in `connection_from_directed_links`
Let $E_+ = \text{lattice.positive\_edges()}$ and $E_+^{\mathrm{op}} = \{(v, u) : (u, v) \in E_+\}$. On every admitted `Lattice` (open $L, M \ge 2$ or periodic $L, M \ge 3$), $E_+ \cap E_+^{\mathrm{op}} = \varnothing$ and $|E_+ \sqcup E_+^{\mathrm{op}}| = 2|E_+|$. `connection_from_directed_links` (`code/holonomy.py:426-454`) executes six sequential checks:

1. **Edge-Key Delimiter and ASCII-Digit Vertex Parsing (`lines 436-439`, `parse_vertex` `lines 418-423`)**:
   - `ends = key.split("->") if type(key) is str else []`; if `len(ends) != 2`, raises `LatticeError(f"malformed edge key {key!r}")` (rejecting non-`str` keys, missing `"->"`, or chained `"0,0->0,1->0,2"`).
   - `parse_vertex(text)` splits on `","` if `type(text) is str` and checks `len(parts) == 2 and all(p.isascii() and p.isdigit() for p in parts)`, raising `LatticeError(f"malformed vertex name {text!r}")` on negative signs (`"-1,0"`), whitespace (`" 0,0"`), empty parts, non-ASCII Unicode digits, or extra commas.
2. **Canonicalized Duplicate-Edge Refusal (`lines 440-441`)**:
   - `if edge in parsed: raise LatticeError(f"duplicate parsed edge {key!r}")`.
   - Because `int(parts[0])` normalizes leading zeros (`"00"` $\mapsto 0$), distinct raw keys such as `"0,0->0,1"` and `"00,0->0,1"` map to the same canonical tuple `((0, 0), (0, 1))` and are refused regardless of whether their assigned values agree or conflict.
3. **Exact `str` Type and Group Carrier Membership (`lines 442-443`)**:
   - `if type(value) is not str or value not in group.elements: raise LatticeError(f"unknown group element on edge {key!r}")`.
   - Rejects `None`, lists, dicts, ints, booleans, `str` subclasses, and strings outside `group.elements`.
4. **Bidirectional Coverage Over $E_+$ (`lines 446-448`)**:
   - Iterating over `(u, v) in lattice.positive_edges()`, if `(u, v) not in parsed or (v, u) not in parsed`, raises `LatticeError(f"edge {u} -> {v} is not listed in both directions")`.
   - Refuses omission of either the forward positive edge `u -> v` or its reverse `v -> u`.
5. **Orientation-Reversal Inverse Consistency (`lines 449-450`)**:
   - `if parsed[(v, u)] != group.inv(parsed[(u, v)]): raise LatticeError(f"inverse mismatch on edge {u} -> {v}")`.
   - Enforces $U_{vu} = U_{uv}^{-1}$ for every $(u, v) \in E_+$. For non-involutive elements — such as `r` in $S_3$ ($r^{-1} = r^2 \ne r$ in `pois_01.json:78-79`) or `i` in $Q_8$ ($i^{-1} = -i \ne i$ in `base_13.json:114-115`) — setting both directions equal (`U_{uv} = U_{vu} = r` or `i`) triggers `inverse mismatch`, as does pairing any element with a non-inverse group element.
6. **Exact Cardinality Closure Refusing Out-of-Lattice Edges (`lines 452-453`)**:
   - `if len(parsed) != 2 * len(links): raise LatticeError("directed links name an edge that is not in the lattice")`.
   - *Derivation of exactness*: By Stage 2, every entry of `directed` inserts a distinct key into `parsed`. By Stage 4, every `(u, v) in E_+` inserts one key into `links` (`len(links) == |E_+|`) and witnesses `(u, v) in parsed` and `(v, u) in parsed`. Because $E_+ \cap E_+^{\mathrm{op}} = \varnothing$, the disjoint union $E_+ \sqcup E_+^{\mathrm{op}}$ has cardinality $2|E_+| = 2 \cdot \text{len}(\text{links})$ and satisfies:
     $$E_+ \sqcup E_+^{\mathrm{op}} \subseteq \mathrm{dom}(\text{parsed}) \implies |\mathrm{dom}(\text{parsed})| \ge 2 \cdot \text{len}(\text{links}),$$
     with equality if and only if $\mathrm{dom}(\text{parsed}) = E_+ \sqcup E_+^{\mathrm{op}}$. Any extraneous edge $(x, y) \notin E_+ \sqcup E_+^{\mathrm{op}}$ — whether a self-loop `(0,0)->(0,0)`, diagonal `(0,0)->(1,1)`, non-nearest-neighbour jump `(0,0)->(2,2)`, open-boundary wraparound `(0,2)->(0,0)` on a $3 \times 3$ open grid, or out-of-range coordinate `(3,0)->(3,1)` (even if supplied together with its reverse `(3,1)->(3,0)` and valid inverses!) — strictly increases `len(parsed)` above `2 * len(links)` and is refused with `LatticeError`.

### 3.2 Constructor-Level Defense in `Connection.__init__` and `connection_from_case`
- `Connection.__init__` (`code/holonomy.py:262-271`) independently checks `set(links) == set(lattice.positive_edges())` (`LatticeError("links must assign exactly the positive edges of the lattice")`) and `any(type(value) is not str or value not in members ...)` (`LatticeError("every link must be a group element")`), ensuring callers bypassing `connection_from_directed_links` cannot construct a `Connection` with missing/extra positive edges or invalid group elements.
- `connection_from_case` (`lines 457-474`) validates `isinstance(edges, Mapping)` (`LatticeError("case edges must be a mapping")`) before delegating to `connection_from_directed_links`, admits all five unmutated C017 fixtures (`pois_01` with `24` directed edges, `base_01` with `34`, `base_02` with `62`, `base_03` with `120`, `base_13` with `62`; total `302` directed edges), and refuses single-mutation corruptions of each fixture across all six refusal classes.

## 4. Limits and Non-Claims

1. **Caller JSON Duplicate-Key Responsibility**: `connection_from_directed_links` inspects an already-constructed `Mapping[str, str]`. While distinct string aliases such as `"0,0->0,1"` and `"00,0->0,1"` survive `json.loads` and are caught by Stage 2, byte-identical duplicate keys in raw JSON text are collapsed by standard `json.loads` unless the caller passes an `object_pairs_hook` (`paper.md:163-164`).
2. **Direct Call Type Precondition**: `connection_from_case` checks `isinstance(edges, Mapping)` (`LatticeError`), whereas calling `connection_from_directed_links` directly with a non-`Mapping` `directed` argument raises `AttributeError` when accessing `directed.items()`.

## 5. Claim Hygiene Summary

1. **What it supports**: Establishes via six-stage code analysis, exact set-cardinality derivation ($|\mathrm{dom}(\text{parsed})| = 2|E_+|$ iff $\mathrm{dom}(\text{parsed}) = E_+ \sqcup E_+^{\mathrm{op}}$), and fixture mutation checks on all five C017 cases that `connection_from_directed_links` admits consistent bidirectional link maps and raises `LatticeError` on malformed keys/vertices, canonicalized alias duplicates, unknown/non-string elements, missing forward or reverse directions, inverse mismatches $U_{vu} \ne U_{uv}^{-1}$, and edges outside the lattice.
2. **What it does not support**: Does not intercept identical duplicate keys collapsed upstream by `json.loads` without a custom `object_pairs_hook`, nor wrap `AttributeError` if `connection_from_directed_links` is called directly with a non-`Mapping`.
3. **Narrowest defensible claim**: For any admitted `FiniteGroup` and `Lattice`, `connection_from_directed_links` admits a `Mapping` iff its keys parse without alias collision to $E_+ \sqcup E_+^{\mathrm{op}}$ and its values lie in `group.elements` with $U_{vu} = U_{uv}^{-1}$ on every $(u, v) \in E_+$, raising `LatticeError` on every violation.
4. **Next test needed**: Pair `json.loads(..., object_pairs_hook=...)` duplicate-key rejection at JSON ingestion boundaries whenever raw model or untrusted JSON strings are parsed into case mappings.
