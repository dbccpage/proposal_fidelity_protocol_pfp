## 1. Claim Statement

PacketCodec applies NFC and tagged encoding; verify checks only payload digest and authority.

## 2. Context & Hypotheses

- **Hypotheses**: `packet_codec.py`
- **Canonical Envelope Representation**:
  - `PacketCodec` provides sealing and verification of Symbol Game envelopes (`PacketEnvelopeWireV2`).
  - To prevent key ambiguity across platforms, all string inputs, dictionary keys, and nested structures undergo Unicode Normalization Form C (NFC).
  - Byte serialization is governed by tagged canonical encoding (`canonical_json_bytes`), which explicitly encodes type tags (e.g. distinguishing integer `1` from string `"1"`).
- **Verification Boundary**:
  - `PacketCodec.verify` performs a bounded verification:
    1. Recomputes payload SHA-256 digest from canonical payload bytes and compares against `declared_sha`.
    2. Validates that `authority_effect == "None"`.
    3. Recomputes unsigned envelope SHA-256 digest and compares against `envelope_sha256`.
  - It does not validate payload domain schema conformance, packet lifecycle transition validity, or asymmetric cryptographic signatures.

## 3. Derivation / Evidence

### 3.1 Unicode NFC Normalization
1. In `_normalize_unicode`, string values and dictionary keys are transformed using `unicodedata.normalize("NFC", value)`.
2. A decomposed character sequence (such as `"cafe\u0301"`) normalizes to the composed form (`"caf\u00e9"`).
3. If two dictionary keys collapse to the same normalized key, `_normalize_unicode` raises `SymbolGameValidationError`, preventing dictionary key injection or silent key overwrite.

### 3.2 Tagged Canonical Encoding
1. `canonical_json_bytes` invokes the shared domain canonical serializer on normalized structures.
2. Distinct data types that serialize identically under RFC 8785 JSON (such as integer `1` and string `"1"`) produce distinct tagged byte sequences:
   - Integer `1` serializes with tag `int`.
   - String `"1"` serializes with tag `string`.
3. This ensures deterministic SHA-256 digests across environments.

### 3.3 Verification Scope Inspection
1. In `PacketCodec.verify(envelope)`:
   - Missing `payload` or `payload_sha256` raises `SymbolGameValidationError`.
   - A tampered payload results in `declared_sha != actual_sha` and returns `(False, actual_sha, "Payload SHA-256 mismatch: ...")`.
   - An authority effect other than `"None"` returns `(False, actual_sha, "Prohibited authority effect: ...")`.
   - An inconsistent envelope digest returns `(False, actual_sha, "Envelope SHA-256 mismatch: ...")`.
2. **Negative Control**: When a non-payload, non-authority field (such as `packet_family` or `carrier_id`) is edited and the envelope digest is recomputed, `PacketCodec.verify` returns `(True, actual_sha, "OK")`. This confirms that `verify` evaluates local digest consistency and authority invariants, without performing semantic schema validation or external producer authentication.

## 4. Limits & Non-claims

1. **What it supports**: Confirms that `PacketCodec` applies NFC normalization and tagged canonical encoding during sealing and verification, and that `verify` checks payload hash consistency, `authority_effect == "None"`, and envelope hash integrity.
2. **What it does not support**: Does not establish asymmetric producer authentication, public key infrastructure, or full protocol lifecycle valid-state transitions.
3. **Narrowest defensible claim**: `PacketCodec` enforces NFC normalization and tagged serialization on sealed structures, and its `verify` method rejects payload digest alterations and non-"None" authority effects while accepting re-digested modifications to non-payload metadata fields.
4. **Next test needed**: Verifying packet decoding behavior on streaming fragmented payloads.
