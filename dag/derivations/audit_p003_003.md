## 1. Claim Statement

At the baseline: a move after `VERIFY` or a malformed element id is refused and rolled back; an empty batch is charged and recorded `ACCEPTED`; with fuel 0 the next batch is recorded `FUEL_EXHAUSTED` and phase becomes `TERMINAL`.

## 2. Context & Hypotheses

- **Baseline Host Implementation**:
  - The baseline host engine is `Demo3HostEngine` in `pfp/infrastructure/adapters/mssn_scenarios/protocol.py`.
- **Transaction Accounting**:
  - Fuel is decremented by 1 prior to processing moves in each submitted batch attempt.
  - State snapshotting enables atomic semantic rollback upon validation failures.
- **Divergence with Package Re-implementation**:
  - In `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/host_engine.py`, empty batches are explicitly refused with `REJECT_EMPTY_BATCH`.
  - In baseline `protocol.py`, empty batches pass validation and record `ACCEPTED`.

## 3. Derivation / Evidence

### 3.1 Move After VERIFY Refusal and Rollback
1. In `protocol.py` lines 353–356:
   ```python
   if idx != len(moves) - 1:
       batch_ok = False
       host_decision = "REJECT_MOVE_AFTER_VERIFY"
       break
   ```
2. Any move positioned after `VERIFY` within a batch triggers structural refusal.
3. Lines 390–394 restore semantic state from the snapshot (`current_phase`, `covered_elements`, `witness_candidate`), and the fuel decrement (`remaining_fuel -= 1`) is retained.

### 3.2 Malformed Element Identifier Refusal
1. In `protocol.py` lines 290–300:
   ```python
   malformed_payload = any(
       not isinstance(move.payload, dict)
       or (
           move.move_type == "COVER_ELEMENT"
           and (
               type(move.payload.get("element_id")) is not str
               or not move.payload["element_id"]
           )
       )
       for move in moves
   )
   ```
2. Non-string, boolean, integer, or empty element identifiers set `malformed_payload = True`.
3. Lines 334–337 set `batch_ok = False` and `host_decision = "REJECT_MALFORMED_PAYLOAD"`, triggering rollback without committing invalid identifiers to `covered_elements`.

### 3.3 Empty Batch Charged and ACCEPTED
1. Fuel decrement occurs unconditionally at line 285: `self.state.remaining_fuel -= 1`.
2. For an empty moves list `moves = []`:
   - `malformed_payload` evaluates to `False` (`any([]) == False`).
   - The loop `for idx, move in enumerate(moves):` does not execute.
   - `batch_ok` remains `True` and `host_decision` remains `"ACCEPTED"`.
3. A receipt is generated with `host_decision = "ACCEPTED"` and `batch_rolled_back = False`, while remaining fuel reflects the 1-unit decrement.

### 3.4 Fuel Exhaustion and Terminal Transition
1. In `protocol.py` lines 267–283:
   ```python
   if self.state.remaining_fuel <= 0:
       self.state.terminal_exit = HostExit.FUEL_EXHAUSTED
       receipt = StepReceipt(
           ...
           phase_after=HostPhase.TERMINAL,
           host_decision=HostExit.FUEL_EXHAUSTED,
           remaining_fuel=0,
           batch_rolled_back=False,
       )
       self.state.history.append(receipt)
       return receipt
   ```
2. When remaining fuel reaches zero, the next submitted batch immediately sets `terminal_exit = HostExit.FUEL_EXHAUSTED`, records `phase_after = HostPhase.TERMINAL`, and emits decision `FUEL_EXHAUSTED`.
3. Once in terminal state, lines 246–266 intercept subsequent batches, returning `REJECT_TERMINAL_STATE` with zero further state changes.

## 4. Limits & Non-claims

1. **What it supports**: Confirms the exact state transitions of the baseline repository host across the four edge cases (move after VERIFY, malformed IDs, empty batches, and fuel exhaustion).
2. **What it does not support**: Does not assert that accepting empty batches is optimal design (package host re-implementation specifically diverged to refuse them); does not evaluate unconstrained multithreaded concurrency.
3. **Narrowest defensible claim**: In `pfp/infrastructure/adapters/mssn_scenarios/protocol.py:Demo3HostEngine`, moves after VERIFY and malformed element IDs roll back while charging fuel, empty batches consume fuel and record `ACCEPTED`, and attempts with zero fuel transition to `TERMINAL` with `FUEL_EXHAUSTED`.
4. **Next test needed**: Evaluating transaction isolation under concurrent multi-process worker submissions.
