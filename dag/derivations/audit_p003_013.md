## 1. Claim Statement

The native Rust port of the two-signal danger gate decision table (`pfp_host_detector::danger_gate`) and the candidate phrase canary scanner (`pfp_host_detector::canaries`), executed via the CLI binary `solve_host_detector`, returns output identical to the Python reference implementations (`danger_gate.py` and `canaries.py`) on each evaluated test case.

## 2. Context & Hypotheses

- **Rust Implementation**:
  - Located in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/rust/src/danger_gate.rs` and `canaries.rs`.
  - Binary entry point: `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/rust/src/bin/solve_host_detector.rs`.
- **Python Reference**:
  - Located in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/danger_gate.py` and `canaries.py`.
- **Invocation Bridge**:
  - Implemented in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/native_host_detector.py`.
- **Hypotheses**:
  - Build from the archived Paper 003 package using `cargo build --locked --release --bin solve_host_detector` in its `code/rust/` directory. The bridge discovers the resulting local executable or uses the path designated by `PFP003_HOST_DETECTOR_BIN`.
  - Payloads are restricted to the finite evaluated case list.
- **Obligations**:
  - Parity is defined strictly relative to the Python reference oracle; it does not establish correctness against an external mathematical specification.
  - Equivalence is bounded to tested inputs and does not extend to uninspected strings or malformed inputs outside the test fixtures.

## 3. Derivation / Evidence

### 3.1 Two-Signal Gate Evaluation Parity
The decision table in `danger_gate.py` maps pairs of inputs $(s_1, s_2)$—where $s_1$ is a list of syntactic epitope matches and $s_2$ is an optional structural defect alarmin—to a `TwoSignalDecision`.
The native Rust implementation in `danger_gate.rs` implements this table via `evaluate_two_signal_gate(&[Signal1Match], Option<&Signal2Danger>)`.

When evaluated across all five canonical gate configurations:
1. **Neither signal present** ($s_1 = \emptyset, s_2 = \text{None}$):
   - Both backends return decision `TOLERATED`, `is_refusal = False`, `is_suppressed = False`, disposition `TOLERATED_CLEAN_PROPOSAL`.
2. **Signal 1 alone** ($s_1 = [\text{Signal1Match("AM-FSP-8-TROYER-WIESE", ...)}], s_2 = \text{None}$):
   - Both backends return decision `DIAGNOSTIC_ONLY`, `is_refusal = False`, `is_suppressed = False`, `signal1_count = 1`.
3. **Signal 2 alone, low severity** ($s_1 = \emptyset, s_2 = \text{Signal2Danger("UNOPTIMIZED_CONTRACT", LOW)}$):
   - Both backends return decision `DIAGNOSTIC_ONLY`, `is_refusal = False`, `is_suppressed = False`.
4. **Signal 2 alone, critical severity** ($s_1 = \emptyset, s_2 = \text{Signal2Danger("CORRUPTED_EVENT_CHAIN", CRITICAL)}$):
   - Both backends return decision `DEFENSIVE_LOCKDOWN`, `is_refusal = True`, `is_suppressed = True`.
5. **Dual corroboration** ($s_1 = [\text{Signal1Match(...) }], s_2 = \text{Signal2Danger("ODD_CYCLE_OBSTRUCTION", MEDIUM)}$):
   - Both backends return decision `QUARANTINED`, `is_refusal = True`, `is_suppressed = True`, disposition `REFUSED_DUAL_SIGNAL_CORROBORATION`.

Field-by-field equality holds across all output attributes (`decision`, `is_refusal`, `disposition`, `signal1_count`, `signal2_severity`, `is_suppressed`, `rationale`).

### 3.2 Candidate Phrase Detector Parity
The four candidate detectors evaluate case-folded substring containment:
- `AM-FSP-8-UNRESTRICTED-SOLVER-CLAIM`
- `AM-FSP-2-FRUSTRATED-OBSTRUCTION`
- `AM-FSP-7-UNVERIFIED-MAJORANA-LIFT`
- `AM-FSP-4-ORBIT-SUM-MISMATCH`

Across all evaluated text corpora:
1. **Constructed fixture sentences**: Each detector flags its corresponding target sentence and produces identical finding records between Rust and Python (canary ID, matched pattern, severity, and exact confidence fraction $1/1$).
2. **Attractive-U true statement control**: `"For attractive U < 0 with equal spin populations, determinant QMC is sign-problem-free on any lattice."` returns zero findings in both backends.
3. **Negated sentence control**: `"There is no particle-hole symmetry on triangle plaquettes."` triggers `AM-FSP-2-FRUSTRATED-OBSTRUCTION` in both backends.
4. **Clean mathematical text**: `"We compute the discrete cochain boundary of a 1-chain on a bipartite square lattice over Q."` returns zero findings in both backends.

### 3.3 Boundary and Rejection Behavior
When `solve_host_detector` receives invalid JSON or an unrecognised command, it exits with a non-zero exit status or emits a typed error object `{"success": false, "error": ...}` without crashing or producing undefined behavior, matching the boundary protocol documented in `native_host_detector.py`.

## 4. Limits and Non-Claims

1. **Relative Oracle Only**: This derivation establishes parity relative to the Python reference implementation. It does not establish the correctness of either implementation against an independent specification.
2. **Finite Input Domain**: The demonstrated equivalence is restricted to the specific test suite cases. Unbounded UTF-8 string equivalence is not established.
3. **Unadmitted Status**: The candidate detectors tested are experimental fixtures from Paper 003 and are not admitted for host enforcement.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that the compiled Rust binary `solve_host_detector` produces outputs identical to the Python reference code across all tested two-signal gate inputs and canary detection sentences.
2. **What it does not support**: Does not support claims of general equivalence over arbitrary unseen inputs or equivalence of uncompiled source revisions.
3. **Narrowest defensible claim**: On the specific gate configurations and sentence fixtures defined in `test_danger_gate.py`, the native Rust port returns the Python reference output.
4. **Next test needed**: Automated differential fuzz testing generating random combinations of valid and invalid UTF-8 strings and multi-signal payloads.
