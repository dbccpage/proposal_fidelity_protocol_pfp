## 1. Claim Statement

The Demo 3 host decrements remaining fuel by one before processing each batch, restores semantic state (covered elements, witness candidate, and phase) on batch refusal, and retains the fuel decrement.

## 2. Context & Hypotheses

- **Host State Machine**:
  - The host is an instance of `Demo3HostEngine` (canonical adapter `pfp/infrastructure/adapters/mssn_scenarios/protocol.py` or package implementation `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/host_engine.py`).
  - State consists of semantic state components $(\text{phase}, \text{covered\_elements}, \text{witness\_candidate})$, remaining fuel $F \in \mathbb{N}_{\ge 0}$, receipt history, and SHA-256 state digest.
- **Initial Operational State**:
  - The host is initialized with positive remaining fuel $F_{\text{before}} \ge 1$ and operates in a non-terminal phase ($\text{phase} \ne \text{TERMINAL}$).
- **Batch Submission**:
  - A batch of proposed moves $B = [m_1, \ldots, m_k]$ is submitted to `execute_batch`.

## 3. Derivation / Evidence

### 3.1 Pre-Execution Fuel Decrement
1. Upon receiving batch $B$ while $F_{\text{before}} > 0$ and phase $\ne \text{TERMINAL}$, the host accounts for the execution attempt by decrementing fuel by exactly one:
   $$F_{\text{after}} = F_{\text{before}} - 1.$$
2. In `protocol.py` line 285: `self.state.remaining_fuel -= 1`.
3. In `code/host_engine.py` line 228: `attempt_fuel = self.state.remaining_fuel - 1`.
4. This decrement occurs prior to evaluating individual moves or validating the batch structure.

### 3.2 Semantic State Snapshot
1. Before applying moves, the host records a snapshot of the pre-batch semantic state:
   $$S_{\text{snap}} = (\text{phase}_{\text{before}}, \text{covered}_{\text{before}}, \text{witness}_{\text{before}}).$$
2. In `protocol.py` lines 326–329:
   - `snap_phase = self.state.current_phase`
   - `snap_covered = set(self.state.covered_elements)`
   - `snap_witness = self.state.witness_candidate`
3. In `code/host_engine.py` lines 267–270:
   - `snapshot = self.state.copy()`
   - `snapshot.remaining_fuel = attempt_fuel`

### 3.3 Refusal and Atomic Semantic Restoration
1. When any move in $B$ fails validation (e.g. unknown move, malformed payload, move after `VERIFY`, incomplete coverage, missing witness, or route refusal `NO_NATIVE_PORT`), execution halts and sets `batch_rolled_back = True`.
2. The semantic state is restored directly from the snapshot:
   - $\text{phase}_{\text{after}} = \text{phase}_{\text{before}}$
   - $\text{covered}_{\text{after}} = \text{covered}_{\text{before}}$
   - $\text{witness}_{\text{after}} = \text{witness}_{\text{before}}$
3. In `protocol.py` lines 390–394:
   ```python
   if not batch_ok:
       self.state.current_phase = snap_phase
       self.state.covered_elements = snap_covered
       self.state.witness_candidate = snap_witness
   ```
4. In `code/host_engine.py` lines 319–325:
   ```python
   if rollback:
       self.state = snapshot
       self.state.remaining_fuel = attempt_fuel
   ```

### 3.4 Non-Restoration of Fuel Charge
1. On rollback, the fuel decrement is retained:
   $$F_{\text{after}} = F_{\text{before}} - 1.$$
2. Fuel is not incremented or refunded when the transaction rolls back.
3. Therefore, repeated refused batches decrease fuel monotonically until exhaustion ($F = 0$).

### 3.5 Exhaustion and Terminal Transition
1. When a batch attempt expends the final unit of fuel ($F_{\text{before}} = 1 \implies F_{\text{after}} = 0$), the host transitions to `phase = TERMINAL` with exit condition `FUEL_EXHAUSTED`.
2. Any subsequent batch call while in `TERMINAL` state is rejected with decision `REJECT_TERMINAL_STATE`, incurring zero further semantic changes.

## 4. Limits & Non-claims

1. **Scope of Fuel Bounding**: Fuel bounds only the number of processed batches executed by the state machine (at most $F_{\text{initial}}$ charged batches). It does not bound caller HTTP retries, network latency, external process wall-clock execution time, or payload deserialization byte length.
2. **Scope of State Restoration**: Atomic rollback applies to declared semantic state fields (`phase`, `covered_elements`, `witness_candidate`). Audit receipt history and SHA-256 state digest chains advance monotonically and are retained to record the refusal event.
3. **Absence of Host Proof**: The refusal and rollback behavior documents the internal invariants of the host state machine; it does not assert that refusal codes identify adversarial model generation or semantic invalidity in unconstrained settings.
