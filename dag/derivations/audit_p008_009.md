## 1. Claim Statement

In `LevelEngineEvidenceResolver.read_bytes(version, path, revision=None, sha256=None)` (`pfp/infrastructure/tower_evidence/level_engine/resolver.py`), version `"v1"` reads exclusively from pinned Git object storage via `git -C <repository> cat-file blob <revision>:<path>` under a 40-character lowercase hexadecimal revision pin, version `"v2"` reads exclusively from installed package resources under `importlib.resources.files(__package__).joinpath("v2", *relative.parts)` with `revision is None`, and any lookup miss in `"v1"` raises `EvidenceRefusal("HISTORICAL_BYTES_UNAVAILABLE", ...)` while any lookup miss in `"v2"` raises `EvidenceRefusal("ACTIVE_RESOURCE_UNAVAILABLE", ...)` without consulting the opposite namespace or working-tree files. Content SHA-256 verification (`EVIDENCE_DIGEST_MISMATCH`) is enforced when `sha256` is supplied and skipped when `sha256 is None`.

## 3. Derivation / Evidence

### 3.1 Pre-Dispatch Path Sanitization (`_safe_path`, lines 23–35)
Before inspecting `version`, `_safe_path(path)` (`lines 23–35`) invokes `validate_path_security(path)` (`lines 24–27`, refusing empty paths, leading/trailing/double `/`, `:` drive letters or streams, `\\` separators, control characters, `.`/`..` segments, trailing dots/spaces, and base Windows device stems) and additionally checks every `/`-separated component stem `part.partition(".")[0].rstrip(" ")` via inline `re.fullmatch(r"(?:CON|PRN|AUX|NUL|CONIN\$|CONOUT\$|(?:COM|LPT)[1-9\u00b9\u00b2\u00b3])", ..., re.IGNORECASE)` (`lines 29–32`). Any violation raises `EvidenceRefusal("EVIDENCE_PATH_INVALID", "Expected a canonical relative resource path")` (`lines 27, 33`) prior to subprocess or resource access.

### 3.2 Disjoint Namespace Partition and Zero Cross-Fallback (`LevelEngineEvidenceResolver`, lines 37–74; `read_bytes`, lines 43–74)
`LevelEngineEvidenceResolver` begins at line `37` and defines `read_bytes` at `lines 43–74`. After `relative = _safe_path(path)` (`line 46`), `read_bytes` branches on `version` into three mutually exclusive arms with zero shared fallback handler:

1. **Historical arm (`version == "v1"`, lines 47–59)**:
   - Guards (`lines 48–49`): if `self.repository is None` or `revision is None` or `not re.fullmatch(r"[0-9a-f]{40}", revision)`, immediately raises `EvidenceRefusal("HISTORICAL_BYTES_UNAVAILABLE", "Historical evidence requires a repository and full recorded Git revision")`. Abbreviated commit prefixes, branch names (`"HEAD"`, `"main"`), uppercase hex, and `revision=None` are all refused before invoking `git`.
   - Subprocess read (`lines 50–56`): executes `result = subprocess.run(["git", "-C", str(self.repository), "cat-file", "blob", f"{revision}:{relative.as_posix()}"], capture_output=True, check=False)` in binary mode (`text=False`), preserving exact `\r\n` and `\x00` bytes stored in the Git blob regardless of working-tree mutations or deletions; any `OSError` raises `EvidenceRefusal("HISTORICAL_BYTES_UNAVAILABLE", str(error))`.
   - Failure closure (`lines 57–58`): when `result.returncode != 0`, raises `EvidenceRefusal("HISTORICAL_BYTES_UNAVAILABLE", f"Recorded blob unavailable: {revision}:{path}")`. Neither `self.repository / relative` on disk nor `resources.files(__package__).joinpath("v2", *relative.parts)` is accessed—even when `"manifest.json"` is simultaneously present in both the working tree and the `v2` package resource directory.

2. **Active arm (`version == "v2"`, lines 60–67)**:
   - Revision refusal (`lines 61–62`): if `revision is not None`, immediately raises `EvidenceRefusal("EVIDENCE_VERSION_INVALID", "v2 does not accept historical revisions")`.
   - Package resource read (`lines 63–65`): evaluates `item = resources.files(__package__).joinpath("v2", *relative.parts)` and `data = item.read_bytes()`.
   - Failure closure (`lines 66–67`): any `OSError` (including `FileNotFoundError` when a relative path is absent under `v2/`) raises `EvidenceRefusal("ACTIVE_RESOURCE_UNAVAILABLE", path)`. Neither `git cat-file` on `self.repository` nor `self.repository / relative` in the working tree is consulted—even when `self.repository` is configured on the resolver instance and commits that exact relative path at `HEAD`.

3. **Unknown version arm (`else`, lines 68–69)**:
   - Any `version not in {"v1", "v2"}` raises `EvidenceRefusal("EVIDENCE_VERSION_INVALID", f"Unsupported evidence version: {version}")` (`line 69`).

Let $D_{v_1}(r)$ denote the map of blobs committed at 40-hex revision $r$, $D_{v_2}$ the map of installed `v2/` package resources, and $D_{\text{wt}}$ the working-tree filesystem. For every safe path $p$:
$$\text{read\_bytes}(\text{"v1"}, p, r) = \begin{cases} D_{v_1}(r)[p] & \text{if } p \in \operatorname{dom}(D_{v_1}(r)), \\ \bot_{\text{HISTORICAL\_BYTES\_UNAVAILABLE}} & \text{if } p \notin \operatorname{dom}(D_{v_1}(r)), \end{cases}$$
$$\text{read\_bytes}(\text{"v2"}, p, \text{None}) = \begin{cases} D_{v_2}[p] & \text{if } p \in \operatorname{dom}(D_{v_2}), \\ \bot_{\text{ACTIVE\_RESOURCE\_UNAVAILABLE}} & \text{if } p \notin \operatorname{dom}(D_{v_2}), \end{cases}$$
establishing complete independence from $D_{\text{wt}}$ in both arms, independence from $D_{v_2}$ in `"v1"`, and independence from $D_{v_1}(r)$ in `"v2"`.

### 3.3 Optional SHA-256 Digest Verification (`read_bytes`, lines 70–74)
Lines 70–73 execute:
```python
if sha256 is not None:
    expected = sha256.removeprefix("sha256:")
    if not re.fullmatch(r"[0-9a-f]{64}", expected) or hashlib.sha256(data).hexdigest() != expected:
        raise EvidenceRefusal("EVIDENCE_DIGEST_MISMATCH", path)
```
- When `sha256` is provided (either bare 64-char lowercase hex or `"sha256:<64-hex>"`), both `"v1"` and `"v2"` verify `hashlib.sha256(data).hexdigest() == expected` and refuse mismatches or malformed digest strings (uppercase hex, wrong length) with `EVIDENCE_DIGEST_MISMATCH`.
- When `sha256 is None` (default), lines 70–73 are bypassed and `data` is returned without SHA-256 comparison. Callers requiring SHA-256 content pinning must supply `sha256` explicitly.

## 4. Limits and Non-Claims

1. **Optional `sha256` Parameter**: Because `sha256` defaults to `None`, SHA-256 verification is caller-opt-in rather than unconditional on every `read_bytes` call.
2. **External `git` Binary and Object Availability**: Historical `"v1"` resolution depends on a local `git` executable and local object presence in `self.repository`; shallow clones or pruned object stores refuse with `HISTORICAL_BYTES_UNAVAILABLE`.
3. **Mutable Editable Package Trees**: In editable installs, `"v2"` reads through `importlib.resources.files(__package__)` from the package's `v2/` directory on disk; immutability against local disk edits within `v2/` requires passing `sha256`.

## 5. Claim Hygiene Summary

1. **What it supports**: Verifies by full source inspection and bidirectional negative controls on `LevelEngineEvidenceResolver` that `"v1"` reads pinned 40-hex Git blobs without falling back to `"v2"` or working-tree files, `"v2"` reads `v2/` package resources without falling back to `"v1"` Git blobs or working-tree files, path escapes and Windows device names raise `EVIDENCE_PATH_INVALID`, and explicit `sha256` pins enforce `EVIDENCE_DIGEST_MISMATCH`.
2. **What it does not support**: Does not claim SHA-256 content checking occurs when `sha256=None`, and does not claim `"v1"` can resolve commits absent from the local Git object database.
3. **Narrowest defensible claim**: `LevelEngineEvidenceResolver.read_bytes` isolates `"v1"` (40-hex `git cat-file blob`) from `"v2"` (`importlib.resources` `v2/` tree) and from working-tree files, failing closed with `HISTORICAL_BYTES_UNAVAILABLE` or `ACTIVE_RESOURCE_UNAVAILABLE` on misses and checking SHA-256 digests when `sha256` is supplied.
4. **Next test needed**: Audit all call sites of `LevelEngineEvidenceResolver.read_bytes` to verify that manifest-backed callers pass non-`None` `sha256` digests rather than relying on the `sha256=None` default.
