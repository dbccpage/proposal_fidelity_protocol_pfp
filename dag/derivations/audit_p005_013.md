## 1. Claim Statement

The streaming language-model harness (`code/llm_streaming_harness.py`) refuses floating-point and Boolean claim values during turn envelope parsing, emitting status `FW-OP_Refusal` without passing invalid types to the governor. Proposed claim values formatted as integers or exact rational strings (such as `"-2"` or `1`) are converted into exact `fractions.Fraction` instances and scored by the governor on its Python evaluation path. Initial relational claims passed at session construction are validated by exact arithmetic guards during initialization.

## 2. Context & Hypotheses

- **Current Harness Pipeline**:
  - The streaming session `SymbolGameStreamingSession` coordinates between an LLM proposer (`MockLLMStreamingProposer`) and the underlying `L1SymbolGameGovernor`.
  - Proposals stream as discrete chunks, assembled into a JSON envelope by `StreamingEnvelopeParser`.
- **Pre-Execution Guard Boundary**:
  - An earlier implementation was reported to convert floats via `Fraction(...)` before type validation, converting binary float representations (e.g., `0.1`) into high-denominator approximations and treating `True` as `1`.
  - The reviewed harness executes an explicit type check `if isinstance(val, (bool, float)):` before attempting fraction construction.
- **Governor Python Path**:
  - Validated fraction dictionaries are evaluated by the governor under rational arithmetic.
- **Obligations**:
  - Verification that the earlier conversion defect is absent and that inexact types are refused at the parse stage.

## 3. Derivation / Evidence

### 3.1 Envelope Type Guard Implementation
In `llm_streaming_harness.py`, lines 356–367:
```python
if isinstance(val, (bool, float)):
    parse_error = (
        f"Claim value for edge '{key_str}' must be an exact integer or rational "
        f"string, not {type(val).__name__}."
    )
    break
try:
    proposed_cochain[endpoints] = Fraction(val)
except (ValueError, TypeError, ZeroDivisionError) as e:
    parse_error = f"Invalid claim value '{val}' for edge '{key_str}': {e}"
    break
```
When `val` is an instance of `float` or `bool`, `parse_error` is assigned and execution branches directly to:
```python
verdict.update({
    "status": "FW-OP_Refusal",
    "admitted": False,
    "reason": parse_error,
    "defect_after": str(self.governor.primary_obstruction()),
})
```
The invalid value is never passed to `Fraction(val)` or `governor.step_cut`.

### 3.2 Refusal of Float and Boolean Proposals
Simulating proposals where an edge claim is `0.5` or `True` results in:
- `admitted: False`
- `status: "FW-OP_Refusal"`
- `reason` indicating required exact integer or rational string
- Governor obstruction remaining at its prior level

### 3.3 Scoring of Exact Integer and Rational String Claims
Submitting proposals with exact representations such as `{"a, b": "-2", "b, c": 1, "c, a": 1}` succeeds:
- Chunks parse into dictionary `Fraction(-2)`, `Fraction(1)`, `Fraction(1)`.
- `governor.step_cut` receives complete exact claims.
- The turn returns `admitted: True` with `defect_after: "0"` (`ExactRepair`).

### 3.4 Initial Claims Exactness Gate
During session initialization, `session.initialize()` invokes `governor.step_assert` for each edge in `initial_claims`. Supplying a float or Boolean value in initial claims triggers governor exactness validation (`type(value) not in (int, Fraction)`), refusing the step and preventing unverified initial states.

## 4. Limits and Non-Claims

1. **Synthetic Proposer vs. Real-World LLMs**: Tests verify harness parsing against `MockLLMStreamingProposer`; they do not imply that commercial LLMs inherently generate valid rational strings without prompt constraints.
2. **Offline Scope**: Evaluations operate on local Python data structures; no network requests or remote API tokens are utilized.
3. **Semantic Correctness**: Admitting exact integer or rational string repairs indicates algebraic defect reduction; it does not verify external factual truth.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `llm_streaming_harness.py` refuses float and Boolean claim values at the envelope parsing stage with `FW-OP_Refusal`, scores integers and rational strings via `governor.step_cut`, and guards initial claims.
2. **What it does not support**: Does not support that LLM outputs are naturally error-free, nor does it guarantee model adherence to JSON output schemas.
3. **Narrowest defensible claim**: In `llm_streaming_harness.py`, `run_turn` refuses claim values of type float or bool with `FW-OP_Refusal` without calling `Fraction`, and evaluates integer and rational string claims on the governor's Python path.
4. **Next test needed**: Running the harness with an active JSON schema validator on live streaming tokens to test robustness against partial or malformed chunk boundaries.
