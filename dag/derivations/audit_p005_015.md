## 1. Claim Statement

In Paper 005's `L1SymbolGameGovernor` (`005_pfp_practitioners_field_manual/code/l1_symbol_game_governor.py`):
1. `step_assert(u, v, value)` refuses any value with `type(value) not in (int, Fraction)` (including `bool` subclasses `True`/`False` and `float` approximations) with `admitted=False` and `status="IncompleteProposal"`.
2. `step_cut(proposed_section=...)` refuses unknown vertex keys outside `self.graph.vertices` with `status="CarrierViolation"` and refuses non-exact section values (`type(value) not in (int, Fraction)`) with `status="IncompleteProposal"`.
3. `step_cut(proposed_section=..., proposed_claims=...)` refuses simultaneous section and relational payloads with `admitted=False` and `status="MoveViolation"`, preventing silent selection of one payload over the other.
4. Across all three refusal branches, active `edge_claims`, active `section`, and admitted `history` snapshots remain unchanged, while the internal attempt counter `_step_counter` advances by one per invocation.

## 2. Context & Hypotheses

- **Target Implementation**:
  - `atlas/archive/pfp/005_pfp_practitioners_field_manual/code/l1_symbol_game_governor.py` (`step_assert` lines 465–570; `step_cut` lines 572–657).

- **Exact Numeric Contract**:
  - In Python, `issubclass(bool, int)` is `True`; checking `type(value) not in (int, Fraction)` rather than `isinstance(value, (int, Fraction))` prevents `True` (`1`) and `False` (`0`) from entering cochain or potential arithmetic.
- **Declared Obligation**:
  - `paper_claim_ledger.md:28` and `paper.md:183` explicitly note that while `edge_claims`, `section`, and `history` are preserved upon refusal, `_step_counter` increments on entry.

## 3. Derivation / Evidence

### 3.1 `ASSERT` Non-Exact Value Refusal
In `L1SymbolGameGovernor.step_assert` (`l1_symbol_game_governor.py` lines 516–525), after irreflexivity, vertex-membership, and declared-edge checks and strictly before `self.edge_claims[(u, v)] = value` (line 528):
```python
if type(value) not in (int, Fraction):
    return GovernorVerdict(
        admitted=False,
        status="IncompleteProposal",
        defect_before=defect_before,
        defect_after=defect_before,
        details="ASSERT requires an exact int or Fraction, not float or bool.",
        step_id=sid,
    )
```
Evaluating `governor.step_assert("a", "b", value)` for `value` in `(True, False, 0.1, 1.0, "1")` returns `admitted=False`, `status="IncompleteProposal"`, and `defect_before == defect_after` without modifying `self.edge_claims`, `self.section`, or `self.history`.

### 3.2 Dual-Payload `CUT` Mutual Exclusion
At the top of `L1SymbolGameGovernor.step_cut` (`l1_symbol_game_governor.py` lines 591–600):
```python
if proposed_section is not None and proposed_claims is not None:
    current = self.section_defect()
    return GovernorVerdict(
        admitted=False,
        status="MoveViolation",
        defect_before=current,
        defect_after=current,
        details="CUT requires exactly one of proposed_section or proposed_claims.",
        step_id=sid,
    )
```
Because the check tests `is not None` rather than truthiness, even `step_cut(proposed_section={}, proposed_claims={})` (as well as calls supplying two otherwise-admissible repairs) returns `admitted=False` and `status="MoveViolation"`, avoiding silent dispatch to the `proposed_section` branch at line 602. Conversely, supplying neither payload (`proposed_section=None, proposed_claims=None`) reaches lines 773–780 and returns `admitted=False, status="Refused"`.

### 3.3 Section `CUT` Carrier and Value Guards
Inside the `if proposed_section is not None:` branch (`l1_symbol_game_governor.py` lines 603–615):
```python
defect_before = self.section_defect()
extra = set(proposed_section) - set(self.graph.vertices)
inexact = [v for v, value in proposed_section.items() if type(value) not in (int, Fraction)]
if extra or inexact:
    return GovernorVerdict(
        admitted=False,
        status="CarrierViolation" if extra else "IncompleteProposal",
        defect_before=defect_before,
        defect_after=defect_before,
        details=f"Section has undeclared vertices {sorted(extra, key=repr)} or non-exact values {inexact}.",
        step_id=sid,
    )
```
- Unknown vertex keys (`{"d": Fraction(9)}`) produce non-empty `extra == {"d"}` and return `status="CarrierViolation"`.
- Declared vertex keys with non-exact values (`{"a": True}`, `{"a": False}`, `{"a": 0.1}`) have `extra == set()`, non-empty `inexact == ["a"]`, and return `status="IncompleteProposal"`.
- Both checks precede `self.section = ...` (line 628) and `self.history.append(rec)` (line 647).

### 3.4 State Preservation vs. `_step_counter` Advancement
In both `step_assert` (line 481) and `step_cut` (line 588), `self._step_counter += 1` executes prior to guard evaluation to allocate `sid = step_id or f"step_{self._step_counter:03d}"`. Thus on any refused `ASSERT` or `CUT`:
- `(dict(governor.edge_claims), dict(governor.section), list(governor.history))` is invariant before and after the call.
- `governor._step_counter` increments by `1`, assigning a distinct step identifier to the refusal verdict without appending to the admitted snapshot trail `governor.history`.

## 4. Limits and Non-Claims

1. **Omitted Vertices in Section `CUT`**: Unlike relational `CUT` (which requires every declared edge), `step_cut(proposed_section=...)` retains the documented legacy convention (`paper.md:181`, `l1_symbol_game_governor.py:628`) that omitted *declared* vertices default to `Fraction(0)` via `proposed_section.get(v, Fraction(0))`.
2. **Custom `int` Subclasses**: Using `type(value) not in (int, Fraction)` rejects both `bool` and any custom subclass of `int` or `Fraction`, requiring exact base runtime types.
3. **Refusal Logging Boundary**: Refused moves are returned to the caller via `GovernorVerdict` and increment `_step_counter`, but are not stored inside `governor.history`; callers requiring a refusal transcript must record returned verdicts externally.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `step_assert` and section `step_cut` reject `bool`, `float`, and other non-exact inputs with `IncompleteProposal`, section `step_cut` rejects unknown vertices with `CarrierViolation`, dual-payload `step_cut` calls fail with `MoveViolation`, and active claims, section, and admitted history remain unchanged while `_step_counter` advances.
2. **What it does not support**: Does not claim completeness checking on omitted declared vertices in section `CUT` or automatic persistence of refused verdicts in `governor.history`.
3. **Narrowest defensible claim**: In `L1SymbolGameGovernor`, non-exact values in `step_assert` or `step_cut(proposed_section=...)` return `IncompleteProposal`, undeclared vertices in `proposed_section` return `CarrierViolation`, simultaneous `proposed_section` and `proposed_claims` return `MoveViolation`, and each refusal preserves `(edge_claims, section, history)` while incrementing `_step_counter`.
4. **Next test needed**: Property-based fuzzing across mixed malformed payloads (simultaneous unknown vertices, `Decimal`/`complex` numbers, and custom `int` subclasses) verifying state invariance.
