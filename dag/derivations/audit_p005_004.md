## 1. Claim Statement

In the worked session of Paper 005 (`code/play_demo.py`, Section 4), executing on the Python enumeration path on a directed 3-cycle with edge weights $(1,2,3)$ and initial claims $(1,1,1)$ yields an initial primary obstruction $\Phi_1 = 3$. Proposing replacement claims $(5,0,0)$ results in refusal with status `DefectIncrease`, leaving active claims untouched. Proposing repaired claims $(-2,1,1)$ is admitted with status `ExactRepair`, reducing the obstruction from $3$ to $0$. A subsequent `VERIFY ZERO_OBSTRUCTION` is admitted by the host. Executing `step_retract` to the post-assertion snapshot restores the prior state, returning $\Phi_1$ to $3$.

## 2. Context & Hypotheses

- **Declared Carrier Topology**:
  - Directed 3-cycle graph $G = (V, E)$ with vertices $V = \{a, b, c\}$.
  - Edges $E = \{(a,b,1), (b,c,2), (c,a,3)\}$.
- **Initial Relational Claims**:
  - Asserted claims: $c(a,b) = 1$, $c(b,c) = 1$, $c(c,a) = 1$.
  - Cycle holonomy sum: $1 + 1 + 1 = 3$.
- **Execution Path**:
  - Evaluated on the Python enumeration path (`l1_symbol_game_governor.py`) when native pins (`CORE_FUNCTIONAL_GRAPH_BIN` and `CORE_FUNCTIONAL_GRAPH_SHA256`) are absent.
  - Spanning-tree potentials are evaluated by exact rational arithmetic (`fractions.Fraction`).

## 3. Derivation / Evidence

### 3.1 Initial Setup and Assertion
The governor is initialized with constraint graph $G$:
```python
gov = L1SymbolGameGovernor(graph)
gov.step_assert("a", "b", Fraction(1))
gov.step_assert("b", "c", Fraction(1))
v_last_assert = gov.step_assert("c", "a", Fraction(1))
snapshot = v_last_assert.step_id
```
Evaluating `gov.primary_obstruction()` computes the quotient minimum:
$$\Phi_1 = \min_{s \in C^0} \sum_{e=(u,v) \in E} w_e |c(u,v) - (s(v) - s(u))|$$
For weights $(1,2,3)$ and claims $(1,1,1)$, the minimum cost attainable across spanning tree potentials is $3$ (attained by $s = (0, -2, -1)$).

### 3.2 Refusal of Defect-Increasing CUT Move (5, 0, 0)
The proposer submits a relational CUT move:
```python
bad = {("a", "b"): Fraction(5), ("b", "c"): Fraction(0), ("c", "a"): Fraction(0)}
v_bad = gov.step_cut(proposed_claims=bad)
```
1. The host recomputes $\Phi_1$ for the proposed claims: on $(5,0,0)$, the minimal quotient discrepancy is $5$.
2. Because the proposed score $5$ exceeds the active score $3$, the governor enforces monotonic non-increase.
3. The move is refused with:
   - `admitted: False`
   - `status: "DefectIncrease"`
   - `defect_before: Fraction(3)`
   - `defect_after: Fraction(5)`
4. The stored edge claims remain unmodified at $(1,1,1)$.

### 3.3 Admission of Repair CUT Move (-2, 1, 1)
The proposer submits a repaired relational proposal:
```python
repaired = {("a", "b"): Fraction(-2), ("b", "c"): Fraction(1), ("c", "a"): Fraction(1)}
v_good = gov.step_cut(proposed_claims=repaired)
```
1. The host recomputes $\Phi_1$: cycle sum is $(-2) + 1 + 1 = 0$, forming an exact coboundary with $\Phi_1 = 0$.
2. Because $0 \le 3$, monotonic non-increase is satisfied.
3. The move is admitted with:
   - `admitted: True`
   - `status: "ExactRepair"`
   - `defect_before: Fraction(3)`
   - `defect_after: Fraction(0)`
4. The governor commits the replacement claims and projects the updated section.

### 3.4 Verification and Snapshot Rollback
1. Host verification confirms zero obstruction:
   ```python
   v_verify = gov.step_verify("ZERO_OBSTRUCTION")
   assert v_verify.admitted is True
   ```
2. Rollback to the saved pre-repair snapshot:
   ```python
   gov.step_retract(snapshot, reason="demonstrate rollback")
   assert gov.primary_obstruction() == Fraction(3)
   ```
   The governor restores `snapshot_edge_claims` and `snapshot_section`, returning active obstruction to $3$.

## 4. Limits and Non-Claims

1. **Python Enumeration Setting**: This derivation records execution through the vendored Python governor's tree-enumeration routine; it does not substitute for a native Rust solver binary execution.
2. **Fixed Toy Topology**: Results apply to the declared 3-cycle instance with weights $(1,2,3)$; they do not establish asymptotic bounds for general graph complexes.
3. **Rollback Scope**: Retraction restores the specific recorded historical snapshot identified by step ID; it does not provide speculative branch merging.
