## 3. Derivation / Evidence

### 3.1 Historical Census Inventory and September 28 Author Run Accounting
In `docs/historical_census_inventory.json` (`revision = "a623568eb0f853b968bc419bf06dfc6af256ab02"`), `C011`, `C021`, and `C031` are classified as Category `A` solver packages with two independent checker modules each:
- **`C011`** (`b_cohomology/c011_cycle_rank_ladder_coboundary_repair`): `mutation_json_files = 40`, `hidden_json_files = 46`, receipt pointer `commitments/c011_scoring_receipt.json`.
- **`C021`** (`c_quantum/c021_q40_r`): `mutation_json_files = 40`, `hidden_json_files = 46`, receipt pointer `commitments/c021_q40_r_scoring_receipt.json`.
- **`C031`** (`d_physics_mtheory/c031_anomaly_free_u1_charges`): `mutation_json_files = 45`, `hidden_json_files = 46`, receipt pointer `commitments/c031_scoring_receipt.json`.

The retained September 28 author command table (`paper_claim_ledger.md` lines 85–89; `paper.md` lines 465–483) maps each pytest item count directly to the fixture structure:
1. `c011 .../test_checker_mutations.py`: `41 passed` = `1` inventory count check (`len(MUTATION_FILES) == 40`) + `40` parametrized dual-checker rejection cases (`circulation_checker.py` and `potential_checker.py`).
2. `c011 .../tests/test_dual_checkers.py`: `5 passed` across the `46` judge cases (`32` base + `8` controls + `6` poisoned).
3. `c021 .../test_checker_mutations.py`: `41 passed` = `1` inventory count check (`40` files at `a623568e`) + `40` parametrized dual-checker rejection cases (`algebraic_checker.py` and `spectral_checker.py`).
4. `c031 .../test_checker_mutations.py`: `47 passed` = `1` inventory count check (`len(MUTATION_FILES) == 45`) + `45` parametrized dual-checker rejection cases (`u1_algebraic_checker.py` and `u1_mitm_checker.py`) + `1` aggregate refusal-mutation test (`test_refusal_mutations_specifically_rejected`).
5. `c031 .../tests/test_reference_solver.py`: `9 passed`, checking chiral $\mathrm{U}(1)$ anomaly equations $\sum_{i=1}^n q_i = 0$ and $\sum_{i=1}^n q_i^3 = 0$, including non-existence for $n \in \{3, 4\}$ across bounds $\{3, 5, 10, 12\}$ and the unique canonical $n = 5$, bound $9$ solution $q = (-9, -5, -1, 7, 8)$ with $(-9) + (-5) + (-1) + 7 + 8 = 0$ and $(-729) + (-125) + (-1) + 343 + 512 = 0$.

### 3.2 Active Repository Execution and Post-Census Revision Delta
Executing the active challenge packages under `workflows/tasks/certified_challenges/` at `f606aa431` reproduces every retained rejection and identifies one post-census expansion on `C021`:
- **Active `C011`**: `MUTATION_FILES` contains `40` `mut_*.json` files; `test_c011_checker_mutations.py` passes all `41` checks, and `tests/test_dual_checkers.py` passes all `5` dual-checker checks over `46` cases.
- **Active `C021`**: Expanded after commit `a623568e` from `40` to `51` mutation files (`mut_01.json`–`mut_40.json` plus `mut_41.json`–`mut_51.json`), while `ALL_CASE_FILES` in `tests/test_dual_checkers.py` contains `44` cases (`30` base + `8` controls + `6` poisoned after removing two leaked base cases). Both `algebraic_checker` and `spectral_checker` reject `40/40` of the original `mut_01`–`mut_40` files and `11/11` of `mut_41`–`mut_51` (`52` checks including inventory count).
- **Active `C031`**: `MUTATION_FILES` contains `45` `mut_*.json` files; `test_c031_checker_mutations.py` passes all `47` checks, `tests/test_dual_checkers.py` passes all `5` dual-checker checks over `46` cases, and `tests/test_reference_solver.py` passes all `9` solver checks.

### 3.3 Untested Failure Modes and Single-Checker Blind-Spot Controls
Evaluating `c021_q40_r/judge_packet/checkers/dual_evaluator.py` on `case_06.json` illustrates both what dual-checker mutation suites catch and what remains outside their scope:
1. Uncorrupted `c021_q40_r.reference_solver.solver.solve(case)` output yields `verdict == "PASS"` and `agreement is True`.
2. If an upstream caller alters problem-instance data before solving (for example mutating `case["terms"][0]["weight"]` to `[99, 1]` prior to invoking `solve` and `evaluate_dual`), both checkers validate the certificate against the altered instance and return `"PASS"`. Static certificate-mutation files do not test upstream instance-ingest integrity.
3. Conversely, if a novel certificate fault outside the authored `mut_*.json` files bypasses one checker while failing the other (simulated by monkeypatching `verify_spectral_optimality` to return `(True, ...)` on a corrupted `minimizers = [7]` payload), `evaluate_dual` returns `verdict == "CHECKER_DISAGREEMENT"` (`agreement is False`) and `assert_dual_agreement` raises `CheckerDisagreementError`.

## 4. Limits and Non-Claims

1. **Finite Mutation Catalog Boundary**: Rejecting `40`, `40` (`51` active), and `45` authored mutation files verifies detection only on those enumerated fault patterns; untested certificate corruptions, shared specification defects across both checkers, and upstream case-loading drift remain open obligations.
2. **Historical Receipt Custody**: The September 28 run table in `paper_claim_ledger.md` is a historical author record, and the three `commitments/*_scoring_receipt.json` files listed at commit `a623568e` are not stored inside the active `c011`, `c021`, or `c031` directories in this repository.
3. **Post-Census `C021` Expansion**: Active `C021` has `51` mutation files and `44` judge cases rather than the historical `40` mutation files and `46` judge cases at commit `a623568e`.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms the `40`, `40`, and `45` historical mutation counts at commit `a623568e` and the `41`, `5`, `41`, `47`, and `9` pytest item counts in the September 28 ledger table, and verifies by local execution that active `C011` (`40`), `C021` (`40` original + `11` added = `51`), and `C031` (`45`) suites reject every mutation file while passing dual-checker and `C031` reference-solver tests.
2. **What it does not support**: Does not establish completeness over arbitrary certificate corruptions, exclude shared solver-checker specification errors, or replay the unmigrated `commitments/*_scoring_receipt.json` files from commit `a623568e`.
3. **Narrowest defensible claim**: Retained September 28 records and active repository reruns agree that the `C011`, `C021`, and `C031` dual-checker suites reject all `40`, `40` (`51` in active `C021`), and `45` authored mutation fixtures and pass the `C011`/`C031` dual-checker and `C031` reference-solver tests, subject to untested failure modes outside those finite catalogs.
4. **Next test needed**: Add property-based randomized certificate fuzzing and case-digest binding checks upstream of `evaluate_dual` to cover fault classes not represented in static `mut_*.json` files.
