## 1. Claim Statement

The graph tutorial adapter (`ops/adversary/infrastructure/providers/adapters/native_functional.py`) requires an explicit executable path (`CORE_FUNCTIONAL_GRAPH_BIN`) and an exact 64-character hexadecimal SHA-256 digest pin (`CORE_FUNCTIONAL_GRAPH_SHA256`) before dispatching native graph functional calculations, refusing execution without fallback if either configuration is missing or mismatched.

## 2. Context & Hypotheses

- **Graph Functional Adapter**:
  - Located in `ops/adversary/infrastructure/providers/adapters/native_functional.py`.
- **Environment Pin Fences**:
  - `CORE_FUNCTIONAL_GRAPH_BIN`: filesystem path to the native functional graph executable.
  - `CORE_FUNCTIONAL_GRAPH_SHA256`: 64-character lowercase hexadecimal SHA-256 hash.
- **Fail-Closed Semantics**:
  - As declared in module header (`native_functional.py:3-5`), the SHA-256 pin binds the executed binary bytes, and no Python numerical fallback is permitted for missing, refused, or malformed native results.

## 3. Derivation / Evidence

### 3.1 Executable Path and SHA-256 Pin Validation
In `ops/adversary/infrastructure/providers/adapters/native_functional.py:116-124`, `compute_graph_phi1` verifies the execution environment:
```python
binary = os.environ.get("CORE_FUNCTIONAL_GRAPH_BIN")
expected = os.environ.get("CORE_FUNCTIONAL_GRAPH_SHA256", "").lower()
if not binary or re.fullmatch(r"[0-9a-f]{64}", expected) is None:
    raise NativeFunctionalUnavailable("pinned native graph executable required")
try:
    executable = Path(binary).resolve(strict=True)
    digest = hashlib.sha256(executable.read_bytes()).hexdigest()
    if digest != expected:
        raise NativeFunctionalUnavailable("native graph executable digest mismatch")
    completed = subprocess.run(...)
except (OSError, subprocess.TimeoutExpired) as error:
    raise NativeFunctionalUnavailable("native graph executable could not run") from error
```
1. Configuration check: If `CORE_FUNCTIONAL_GRAPH_BIN` is unset or empty, or if `CORE_FUNCTIONAL_GRAPH_SHA256` fails the regex `^[0-9a-f]{64}$`, the function raises `NativeFunctionalUnavailable("pinned native graph executable required")`.
2. Existence check: `Path(binary).resolve(strict=True)` requires that the file exists on disk.
3. Content integrity check: The file bytes are read and hashed via SHA-256. If `digest != expected`, execution halts with `NativeFunctionalUnavailable("native graph executable digest mismatch")`.

### 3.2 Pre-Execution Input Refusals
Before checking binary pins or executing the subprocess, `compute_graph_phi1` enforces carrier and claim validity:
- Non-string or duplicate vertex identifiers raise `ValueError`.
- Edge definitions joining non-existent vertices, self-loops, duplicate edges, or non-positive weights raise `ValueError`.
- Non-exact weight numbers (e.g. `float` or `bool`) raise `TypeError`.
- Any claim asserted on an undeclared edge raises `NativeFunctionalInputRefused("claim edge absent from declared carrier")`.

### 3.3 Native Execution and Refusal Envelope Preservation
When a valid pinned executable runs, `subprocess.run` captures stdout and stderr:
1. If the executable exits non-zero or emits `{"status": "REFUSE", "reason": ...}`, `_native_refusal` catches the response and raises `NativeFunctionalRefusal`.
2. The exception retains the native reason string, return code, stdout, and stderr for caller inspection.
3. If the process emits `{"status": "PASS", "result": ...}`, the adapter verifies that result keys contain `{"phi1", "gauge", "forests_checked"}` and parses rational results using exact `Fraction` objects.

### 3.4 Zero Numerical Fallback
The adapter contains no fallback approximation branch: missing configuration, hash mismatches, and native refusals terminate immediately with typed exceptions.

## 4. Limits and Non-Claims

1. **Byte Binding Only**: The SHA-256 pin binds the exact bytes of the executable file; it does not verify compiler toolchain integrity or provide source-to-binary reproducibility proofs.
2. **Local Environment Fence**: Verification applies to the process environment variables `CORE_FUNCTIONAL_GRAPH_BIN` and `CORE_FUNCTIONAL_GRAPH_SHA256`.
3. **Graph Functional Scope**: Applies specifically to the graph quotient functional calculation ($\Phi_1$) handled by this adapter.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `native_functional.py` requires both a valid binary path and a matching 64-character SHA-256 digest pin, refusing execution with `NativeFunctionalUnavailable` if either is absent or mismatched.
2. **What it does not support**: Does not support claims that SHA-256 hashing verifies mathematical correctness or compiler toolchain provenance.
3. **Narrowest defensible claim**: `compute_graph_phi1` checks that `CORE_FUNCTIONAL_GRAPH_BIN` exists and that its SHA-256 digest matches `CORE_FUNCTIONAL_GRAPH_SHA256` before spawning a subprocess, failing closed without Python fallback.
4. **Next test needed**: Verification of adapter behavior when the target executable is replaced concurrently between hash check and process execution.
