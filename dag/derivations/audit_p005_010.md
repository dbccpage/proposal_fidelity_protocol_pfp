## 1. Claim Statement

The Python companion for Paper 005 (`005_pfp_practitioners_field_manual/code`) executes outside the repository root without requiring repository bootstrap packages or parent `.git` tracking. The vendored adapter (`native_functional.py`) and governor (`l1_symbol_game_governor.py`) record provenance headers linking each file to its upstream source commit and SHA-256 hash. The abstract syntax trees (ASTs) of unpatched functions match recorded source trees up to module import normalization, while documented behavioral patches (`compute_phi1`, `step_cut`, `step_assert`, `step_verify`) are localized and explicitly verified.

## 2. Context & Hypotheses

- **Recorded Source Commits**:
  - `native_functional.py` records upstream commit `52cb5457f6c485ba548cfd292f6012a941ed22cf`, path `providers.adapters.native_functional`, and source SHA-256 `bc99d3d71b3a15b7246482b9cb50c0986de196086fa67b1b3f8770583b3a3172`.
  - `l1_symbol_game_governor.py` records upstream commit `691a01ec3e0e7a17fe06dbbb37d353ea24a2ef39`, baseline commit `52cb5457f6c485ba548cfd292f6012a941ed22cf`, and source SHA-256 `c6cd30cc12a8470a3f7e5aae5956b213b07fd01bdb479f56e5390857745a74bb`.
- **Removal of Repository Dependencies**:
  - Unvendored imports (`sys`, `pathlib.Path`) and root resolution functions (`_find_repo_root`, `_REPO_ROOT`) were excised to allow self-contained execution.
  - Import path `providers.adapters.native_functional` was rebound to local `native_functional`.
- **Documented Behavioral Patches**:
  - Documented local patches include the `IncompleteProposal` completeness check in `step_cut` (review finding R008-04), refusal propagation without exception suppression in `compute_phi1`, and exact arithmetic guards in `step_assert`.
- **Obligations**:
  - Native binary separately required for native solver paths.

## 3. Derivation / Evidence

### 3.1 Vendored Header Verification
Direct inspection and `test_vendored_sources.py::test_vendored_header_is_complete` confirm that each vendored file begins with metadata fields:
```python
# vendored-from-path: providers.adapters.native_functional
# vendored-from-commit: 52cb5457f6c485ba548cfd292f6012a941ed22cf
# vendored-from-sha256: bc99d3d71b3a15b7246482b9cb50c0986de196086fa67b1b3f8770583b3a3172
```
In `l1_symbol_game_governor.py`, the header also documents `baseline-commit: 52cb5457f6c485ba548cfd292f6012a941ed22cf` and its baseline SHA-256 digest. All commits match 40-character hexadecimal strings and all hashes match 64-character hexadecimal digests.

### 3.2 AST Normalization and Equivalence
AST comparison normalizes import statements, removes bootstrap helpers (`_find_repo_root`, `_REPO_ROOT`), and extracts statement dumps for unpatched functions and methods. For unpatched code, the AST structure of the vendored copy matches the recorded upstream source blob byte-for-byte under `ast.dump`.

### 3.3 Localization of Patched Functions
Diff analysis between baseline commit `52cb5457f6c4` and vendored commit `691a01ec3e0e` isolates top-level behavioral modifications to `compute_phi1`.
1. In `compute_phi1`, AST traversal confirms zero `ast.ExceptHandler` instances (`test_vendored_sources.py::test_vendored_compute_phi1_has_no_exception_handler`), establishing that native execution errors are not replaced by a Python fallback.
2. In `step_cut`, AST traversal identifies the string literal `"IncompleteProposal"` (`test_vendored_sources.py::test_vendored_step_cut_carries_the_completeness_check`), confirming the local patch for review finding R008-04.

## 4. Limits and Non-Claims

1. **Native Solver Separate Requirement**: Does not indicate that external native binaries (`CORE_FUNCTIONAL_GRAPH_BIN`) are packaged or verified by Python source inspection alone.
2. **Interpreter Scope**: AST structural equivalence is evaluated under Python 3 abstract grammar; it does not claim bytecode identity across diverse Python virtual machines.
3. **Commit Integrity vs. Author Identity**: Verification confirms that vendored files agree with recorded commit and SHA-256 metadata; it does not authenticate the signing keys of recorded git authors.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that the companion modules in `code/` execute without parent repository dependencies, declare valid provenance headers matching recorded source commits and hashes, and retain AST equivalence with upstream sources outside declared patches.
2. **What it does not support**: Does not support native binary bundling, automatic binary verification, or semantic correctness of unreviewed modifications.
3. **Narrowest defensible claim**: The vendored modules in Paper 005 declare valid source metadata headers, exhibit AST equivalence with recorded source revisions outside documented patches, and run without repository root bootstrap imports.
4. **Next test needed**: Containerized verification running the full Paper 005 test suite in an isolated environment without access to the parent git repository.
