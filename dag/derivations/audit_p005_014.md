## 1. Claim Statement

In the vendored governor of Paper 005 (`005_pfp_practitioners_field_manual/code/l1_symbol_game_governor.py`), `compute_phi1(graph, claims)` validates the declared carrier and normalizes claim keys prior to either native delegation or offline spanning-forest enumeration:
1. Duplicate vertex names in `graph.vertices` and duplicate directed edges `(u, v)` in `graph.edges` raise `ValueError`.
2. Claim keys outside `declared = {edge.key for edge in graph.edges}` (including out-of-carrier endpoints, reversed or absent chords, and self-pairs) raise `ValueError("claim edge absent from declared carrier")` instead of being discarded.
3. Supported `Edge` dataclass keys are normalized to `(edge.u, edge.v)` pairs via `pair = key.key if isinstance(key, Edge) else key` before duplicate-claim checks and quotient minimization, while colliding `(Edge, tuple)` keys for the same directed edge raise `ValueError("duplicate claim for a directed edge")`.

## 3. Derivation / Evidence

### 3.1 Duplicate Carrier Entry Refusal
At the entry of `compute_phi1` (`l1_symbol_game_governor.py` lines 292–297):
```python
vertices = set(graph.vertices)
if len(vertices) != len(graph.vertices):
    raise ValueError("duplicate vertex in declared carrier")
declared = {edge.key for edge in graph.edges}
if len(declared) != len(graph.edges):
    raise ValueError("duplicate directed edge in declared carrier")
```
- If `graph.vertices` repeats `"a"` (for instance `("a", "b", "c", "a")`), `len(vertices) == 3 != 4`, raising `ValueError` with `"duplicate vertex in declared carrier"`.
- If `graph.edges` repeats an edge with identical `(u, v)` endpoints (whether identical `Edge("a", "b", 1)` or distinct weight `Edge("a", "b", 5)`), `len(declared) < len(graph.edges)`, raising `ValueError` with `"duplicate directed edge in declared carrier"`.

### 3.2 Undeclared Claim Edge and Malformed Key Refusal
During claim normalization (`l1_symbol_game_governor.py` lines 298–309):
```python
normalized = {}
for key, value in claims.values.items():
    pair = key.key if isinstance(key, Edge) else key
    if type(pair) is not tuple or len(pair) != 2:
        raise ValueError("claim keys must be declared directed edges")
    if pair not in declared:
        raise ValueError("claim edge absent from declared carrier")
```
- Non-tuple or wrong-length keys (such as `"ab"`, `["a", "b"]`, or `("a", "b", "c")`) raise `ValueError("claim keys must be declared directed edges")`.
- On the canonical directed 3-cycle $E = \{(a,b), (b,c), (c,a)\}$ with weights $(1, 2, 3)$, supplying `Cochain1({pair: Fraction(9)})` for `pair` in `{("d", "e"), ("a", "c"), ("a", "a")}` fails `pair not in declared` and raises `ValueError("claim edge absent from declared carrier")`. No undeclared claim is silently ignored during spanning-tree potential evaluation.

### 3.3 `Edge` Key Normalization and Duplicate-Claim Collision Guard
When a caller constructs `Cochain1({edge: Fraction(1) for edge in graph.edges})` keyed by `Edge` instances:
1. `isinstance(key, Edge)` evaluates to `True`, mapping `Edge("a", "b", 1)` to `("a", "b")`, `Edge("b", "c", 2)` to `("b", "c")`, and `Edge("c", "a", 3)` to `("c", "a")`.
2. If a caller supplies both `Edge("a", "b", 1)` and `("a", "b")` in the same mapping, the second entry triggers `if pair in normalized: raise ValueError("duplicate claim for a directed edge")`.
3. `exact_claims = Cochain1(values=normalized)` is passed to `find_spanning_forest_potentials(graph, exact_claims)` (where `claims.get(e.u, e.v)` looks up `(e.u, e.v)`). Without normalization, `claims.get(e.u, e.v)` on an `Edge`-keyed `Cochain1` would default to `Fraction(0)` and mis-score `(1, 1, 1)` as `0`; after normalization, offline enumeration evaluates $\Phi_1 = 3$ attained at potential $f = (0, -2, -1)$ with $\sum_{e} w_e |1 - (f_v - f_u)| = 1 \cdot |3| + 2 \cdot |0| + 3 \cdot |0| = 3$.

## 4. Limits and Non-Claims

1. **Unasserted Declared Edges**: While undeclared edges are refused, omitting a *declared* edge from `Cochain1.values` in direct `compute_phi1` calls still defaults that declared edge to `Fraction(0)` via `exact_claims.get(e.u, e.v)` (completeness of replacement proposals is enforced separately in `L1SymbolGameGovernor.step_cut`).
2. **Patched Companion Scope**: These checks describe the v0.1 patched companion copy in Paper 005 (`l1_symbol_game_governor.py`), not unpatched historical revisions prior to `2026-10-02`.
3. **Offline Path**: Tests exercising `compute_phi1` with `CORE_FUNCTIONAL_GRAPH_BIN` unset validate the Python enumeration route rather than the external Rust binary.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `compute_phi1` rejects duplicate vertices, duplicate directed edges, malformed claim keys, undeclared claim edges, and colliding normalized keys with `ValueError`, while normalizing `Edge` object keys to `(u, v)` pairs before scoring.
2. **What it does not support**: Does not establish native binary execution when pins are unset or factual external validity of declared graph weights and claims.
3. **Narrowest defensible claim**: In Paper 005's `l1_symbol_game_governor.compute_phi1`, undeclared claim edges and duplicate vertex/edge/claim entries raise `ValueError`, and `Edge`-typed claim keys normalize to `(u, v)` tuple keys yielding exact quotient minimum `3` on the `(1, 2, 3)` triangle with unit claims.
4. **Next test needed**: Differential test confirming identical `ValueError` messages and normalized payload forwarding when a pinned `solve_graph_phi1` binary is configured.
