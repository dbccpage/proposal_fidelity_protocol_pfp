## 1. Claim Statement

The canonical repository self panel consists of 1,000 entries and 40 distinct base contents, with 10 distinct base contents in each of four categories.

## 2. Context & Hypotheses

- **Self Panel Corpus**:
  - The canonical baseline self panel is stored in `pfp/domain/immune/self_panel.json`.
- **Parsing and Normalization Logic**:
  - `SelfPanel` domain object and normalization methods defined in `pfp/domain/immune/thymus.py`.
  - Normalization rule: `_SYNTHETIC_TRAILER = re.compile(r"\s*-- index \d+ hash_mod_\d+\s*$")`.
  - Method `SelfPanel.base_content(content: str) -> str` strips synthetic trailer comments while leaving valid semantic comments intact.
  - Method `SelfPanel.distinct_base_contents(self) -> frozenset[str]` returns the set of distinct base contents across all entries.
- **Categories**:
  - The panel entries are partitioned into four categories: `clean_lean4_proof`, `clean_architecture_port`, `clean_prompt_template`, and `clean_physics_expression`.

## 3. Derivation / Evidence

### 3.1 Total Entry Census
1. In `pfp/domain/immune/thymus.py`, `SelfPanel.load_canonical()` parses `pfp/domain/immune/self_panel.json`.
2. The entries array contains exactly 1,000 items:
   $$\text{len}(\text{panel.entries}) = 1000.$$
3. Each entry is validated as a `SelfPanelEntry` containing a non-empty string `entry_id`, a non-empty `category`, a string `content`, and a 64-character hex `content_sha256`.

### 3.2 Category Partition and Base Content Distribution
1. Grouping entries by category reveals an equal partition of 250 rows per category:
   - `clean_lean4_proof`: 250 rows.
   - `clean_architecture_port`: 250 rows.
   - `clean_prompt_template`: 250 rows.
   - `clean_physics_expression`: 250 rows.
   Total entries: $250 \times 4 = 1000$.
2. For each entry, evaluating `SelfPanel.base_content(entry.content)` removes the synthetic index and hash modulus comments.
3. Computing distinct base contents per category yields:
   - `len(distinct_base_contents("clean_lean4_proof")) = 10`
   - `len(distinct_base_contents("clean_architecture_port")) = 10`
   - `len(distinct_base_contents("clean_prompt_template")) = 10`
   - `len(distinct_base_contents("clean_physics_expression")) = 10`
4. Taking the union across all four disjoint categories yields exactly:
   $$\text{len}(\text{panel.distinct\_base\_contents}()) = 40.$$

### 3.3 Resolution of Fresh Baseline Replay Obligation
The ledger recorded an obligation for fresh baseline replay. Direct execution of `SelfPanel.load_canonical()` on the repository's sealed `self_panel.json` confirms that the entry count is 1,000 and the distinct base content count is 40. Furthermore, tests on synthetic generation in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/tests/test_demo_3_host.py` (`test_synthetic_self_panel_has_forty_distinct_base_contents`) confirm that the synthetic mirror constructs a panel of identical shape (1,000 rows, 40 distinct base contents, 10 per category).

### 3.4 Preservation of Semantic Comments
The trailer regex `\s*-- index \d+ hash_mod_\d+\s*$` matches only the generated suffix. Real semantic code comments (such as `-- comment explaining proof step` or Lean docstrings) do not match the suffix pattern and remain unmodified by `SelfPanel.base_content`.

## 4. Limits and Non-Claims

1. **Finite Regression Suite**: As emphasized in Paper 003 Section 2.1, the 1,000 entries and 40 base contents form a finite regression corpus for negative selection testing. They do not constitute an empirical sample or statistical distribution of open-domain text.
2. **No Claim of Comprehensive Semantic Coverage**: 40 distinct base contents cannot cover the full diversity of valid code or prompts; they provide a baseline filter to purge candidate detector rules that fire on healthy reference code.
3. **Synthetic Expansion**: The 1,000 entries are expanded from 40 base templates via indexed comment trailers; the raw entry count reflects replication, not independent semantic variance.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `pfp/domain/immune/self_panel.json` when loaded via `SelfPanel.load_canonical` yields 1,000 entries and 40 distinct base contents after trailer stripping, distributed evenly with 250 entries and 10 distinct base contents in each of the four categories.
2. **What it does not support**: Does not support claims that the self panel ensures zero false suppression on unobserved clean code, or that 40 templates suffice for real-world negative selection.
3. **Narrowest defensible claim**: The serialized JSON file `self_panel.json` in `pfp/domain/immune/` contains exactly 1,000 entries whose base contents under `SelfPanel.base_content` partition into four categories of 10 distinct strings each.
4. **Next test needed**: Evaluating the sensitivity of negative selection when expanding the self panel with diverse third-party open-source code repositories.
