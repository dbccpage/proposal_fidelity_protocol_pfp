## 1. Claim Statement

In the package host every refused batch (move after VERIFY, empty, malformed id) costs one fuel unit and rolls back; after initial fuel F refusals the host is TERMINAL with FUEL_EXHAUSTED.

## 2. Context & Hypotheses

- **Package Host Implementation**:
  - `Demo3HostEngine` in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/host_engine.py`.
  - Rust counterpart in `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/rust/src/host.rs`.
- **Fuel Invariant**:
  - Initial fuel $F \in \mathbb{N}_{\ge 0}$.
  - Every batch execution attempt decrements fuel by 1 upfront.
  - Batch refusal restores semantic state from snapshot but retains the consumed fuel decrement.

## 3. Derivation / Evidence

### 3.1 Charged Refusals and State Rollback
1. In `host_engine.py` line 223, `attempt_fuel = self.state.remaining_fuel - 1` is evaluated before any proposal is applied.
2. Across all three refusal classes:
   - **Empty batch**: lines 231–246 detect `not proposals`, return `REJECT_EMPTY_BATCH` with `batch_rolled_back = True`, and preserve `remaining_fuel = attempt_fuel`.
   - **Move after VERIFY**: lines 249–265 detect proposals trailing `VERIFY`, return `REJECT_MOVE_AFTER_VERIFY` with `batch_rolled_back = True`, and preserve `remaining_fuel = attempt_fuel`.
   - **Malformed element ID**: lines 281–286 detect non-string, boolean, or empty `element_id`, set `rollback = True`, restore `self.state = snapshot`, and preserve `remaining_fuel = attempt_fuel`.
3. In each case, `covered_elements` and `witness_candidate` remain unmodified, while fuel decreases by exactly 1 unit.

### 3.2 Finite-Step Induction to Terminal Exhaustion
1. Let the engine start with initial fuel $F \ge 0$.
2. For attempt $k \in \{1, \dots, F\}$:
   - Remaining fuel enters at $F - (k - 1)$.
   - Upfront decrement sets `attempt_fuel = F - k`.
   - Upon refusal and rollback, `remaining_fuel` is set to $F - k$.
3. When $k = F$:
   - `attempt_fuel = 0`.
   - The conditional branch (lines 236–238, 255–257, 322–324):
     ```python
     if attempt_fuel == 0:
         self.state.current_phase = HostPhase.TERMINAL
         self.state.terminal_exit = HostExit.FUEL_EXHAUSTED
     ```
     sets `current_phase = HostPhase.TERMINAL` and `terminal_exit = HostExit.FUEL_EXHAUSTED`.
4. Subsequent attempt $F+1$:
   - Triggers line 214:
     ```python
     if self.state.current_phase == HostPhase.TERMINAL:
         return StepReceipt(host_decision="REJECT_TERMINAL_STATE", batch_rolled_back=True, remaining_fuel=0)
     ```
   - Execution is rejected with `REJECT_TERMINAL_STATE` without modifying state or fuel.

### 3.3 Rust Parity
In `code/rust/src/host.rs` lines 200–235, the Rust host evaluates `let attempt_fuel = self.state.remaining_fuel.saturating_sub(1);` with identical rollback and exhaustion mechanics. Executable check via `cargo test` confirms passing `test_fuel_exhaustion`.

## 4. Limits & Non-claims

1. **What it supports**: Confirms that in `Demo3HostEngine` each refused batch decrements fuel by 1 and rolls back semantic state, and after $F$ refusals the host enters `TERMINAL` with `FUEL_EXHAUSTED`.
2. **What it does not support**: Does not bound execution time, memory usage, or network latency; applies to batch attempt accounting under non-negative integer fuel.
3. **Narrowest defensible claim**: For any integer initial fuel $F \ge 0$, submitting $F$ refused batches in `Demo3HostEngine` (Python or Rust) reduces remaining fuel to 0, rolls back each batch, and leaves the engine in `TERMINAL` phase with `terminal_exit == HostExit.FUEL_EXHAUSTED`.
4. **Next test needed**: Testing transaction isolation under concurrent multi-process worker submissions.
