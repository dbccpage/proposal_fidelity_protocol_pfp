## 3. Derivation / Evidence

### 3.1 Historical Implementation Inspection
In the historical packaged immune demonstration at commit `30609de2c`:
1. Line 178 of `run_packaged_immune.py` executes:
   ```python
   sensor.detect({"defect_count": len(matches)})
   ```
2. The danger sensor in `mssn_ports.py` (lines 27–39) emits a `Signal2` record:
   - If `defect_count > 0`, it produces `Signal2Danger(severity="HIGH", defect_count=len(matches))`.
   - If `defect_count == 0`, no danger record is produced (`None`).
3. Consequently, Signal 2 is a deterministic function of Signal 1 match count $c$:
   $$s_2(c) = \begin{cases} (\text{"HIGH"}, c) & \text{if } c > 0 \\ \text{None} & \text{if } c = 0 \end{cases}$$

### 3.2 Application of Lemma A(3)
The Lemma A oracle in `detector_lemmas.py` maps $(s_1, s_2)$ into `{TOLERATED, DIAGNOSTIC_ONLY, DEFENSIVE_LOCKDOWN, QUARANTINED}`:
- Neither present ($c = 0, s_2 = \text{None}$): `TOLERATED`.
- Signal 1 present alone ($c > 0, s_2 = \text{None}$): `DIAGNOSTIC_ONLY`.
- Signal 2 present alone ($c = 0, s_2 \ne \text{None}$): `DEFENSIVE_LOCKDOWN` if severe, else `DIAGNOSTIC_ONLY`.
- Both signals present ($c > 0, s_2 \ne \text{None}$): `QUARANTINED` if severe, else `DEFENSIVE_LOCKDOWN`.

When $s_2(c)$ is derived as defined above:
1. For $c = 0$: $s_2(0) = \text{None} \implies \text{gate}(0, \text{None}) = \text{TOLERATED}$.
2. For $c > 0$: $s_2(c) = (\text{"HIGH"}, c) \implies \text{gate}(c, (\text{"HIGH"}, c)) = \text{QUARANTINED}$, because severity is `HIGH` $\in \text{SEVERE}$.

The archived Python gate in `danger_gate.py` agrees on these two reachable cases. Its dual-signal branch quarantines at every severity. The oracle returns defensive lockdown for the dual-signal low-severity case, which this historical coupling never supplies.

Under this coupling:
$$\text{Reachable Decisions} = \{\text{TOLERATED}, \text{QUARANTINED}\}$$
The decision `DIAGNOSTIC_ONLY` cannot be reached for any match count $c > 0$. Every non-zero match count immediately triggers the refusal disposition `QUARANTINED`.

### 3.3 Formal Oracle Evaluation
In `atlas/archive/pfp/003_pfp_host_admitted_failure_detectors/code/detector_lemmas.py`:
- `audited_signal2(count)` models the exact historical function.
- Evaluating `reachable(audited_signal2, range(50))` yields exactly `frozenset({"TOLERATED", "QUARANTINED"})`.
- Evaluating `diagnostic_reachable_by_characterization(audited_signal2, range(50))` returns `False`.
- This confirms the statement of predecessor DAG node `PAPER003-DERIVED-SIGNAL-COLLAPSE`.

## 4. Limits and Non-Claims

1. **Historical Revision Scope**: This derivation assesses commit `30609de2c` and the mathematical consequence of coupling Signal 2 to Signal 1. It does not apply to the repaired codebase where independent host sensors are enforced.
2. **Control Cases Scope**: Applies to the 24 control cases described in Appendix A. As noted in the paper text, the demonstration's model-reply path took Signal 2 from a separate check.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that computing Signal 2 from the match count with fixed HIGH severity collapses the two-signal decision table to a one-input function reaching only `TOLERATED` and `QUARANTINED`.
2. **What it does not support**: Does not support claims that the current repository retains this failure mode or that two-signal architectures in general fail to provide diagnostic separation when inputs are genuinely independent.
3. **Narrowest defensible claim**: At commit `30609de2c`, computing Signal 2 from the match count satisfies the premise of Lemma A(3), restricting reachable decisions to tolerance or quarantine.
4. **Next test needed**: Automated static AST analysis in CI to detect and flag any pipeline where Signal 2 inputs are computed from pattern match objects.
