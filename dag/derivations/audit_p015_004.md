## 3. Step-by-Step Derivation

### Step 1 — What the six-step C-R-E-I-M-T compiler and runtime check

In `operads/infrastructure/ddc_code_repair.py` (lines 69–141), `load_code_repair_family` constructs a linear six-node `TypedWorkflowV1` (`c -> r -> e -> i -> m -> t`) with port colours `request/state -> state` (`ColourId("State")`) on `C..M` and `state -> terminal` (`ColourId("Receipt")`) on `T`, and effect set `EFFECTS = {"read_source", "write_workspace", "run_check", "emit_evidence"}` (line 58). In `ops/adversary/infrastructure/ddc_code_repair.py` (lines 113–123), `CodeRepairRuntime._state` enforces sequential phase ordering (`captured -> observed -> evaluated -> incorporated -> disposed`) and single-run identity equality (`run_key`, `candidate_id`, `request_digest`, `source_root`, `source_manifest`), emitting `RepairTerminalV1` with `authority_effect = "None"`, `admission = "Unadmitted"`, `production_activation = "HOLD"`, and `mathematical_measurement = "NOT_MEASURED"` (`operads/contracts/ddc_code_repair_v1.py`, lines 116–124).

### Step 2 — Structural non-equivalence with effectful multi-agent gluing

Let \(f_1, f_2 : S \to S \times O\) be two effectful operations with identical typed port signatures (`State -> State`) that mutate or depend on external workspace or process state \(S\):
1. **Non-commutativity of side effects**: Even when \(f_1\) and \(f_2\) each pass their local post-condition from initial state \(s_0\), sequential composition \(f_2 \circ f_1\) can fail \(f_2\)'s check or invalidate \(f_1\)'s post-condition (for example, `f_1` writes workspace file `a.py = 1` expecting `b.py = 0`, while `f_2` writes `b.py = 1` expecting `a.py = 0`: both have identical `State -> State` port types, yet no order of execution satisfies both post-conditions simultaneously).
2. **Callback opacity to port-colour typing**: `compile_typed_workflow` verifies slot arities, port schema digests, and declared effect subsets (`operads/infrastructure/ddc_code_repair.py`, lines 82–136); it does not inspect arbitrary Python/process callback bodies and cannot invert side effects or supply missing overlap constraints across concurrent agents.
3. **Explicit terminal scope fence**: Both `RepairTerminalV1.mathematical_measurement == "NOT_MEASURED"` (`operads/contracts/ddc_code_repair_v1.py:123`) and `CodeRepairRuntime.run` (`ops/adversary/infrastructure/ddc_code_repair.py:323`) record that a six-step run is one observed trace on fixed local check commands (`evidence_scope = "FIXED_LOCAL_COMMANDS"`), not a universal gluing proof over effectful agent compositions.
