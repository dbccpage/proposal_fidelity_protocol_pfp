## 3. Derivation / Evidence

### 3.1 Verification Functions and Scope Analysis
Source inspection of `ops/education/scripts/verify_system_integration.py` reveals four primary audit stages implemented across functions `audit_notebook`, `child`, `make_inventory`, and `main`:

1. **Structure Verification (`audit_notebook`)**:
   - Disallows UTF-8 Byte Order Marks (BOM):
     ```python
     if raw.startswith(b"\xef\xbb\xbf"):
         raise ValueError("UTF-8 BOM is disallowed")
     ```
   - Enforces Jupyter notebook format version 4.5:
     ```python
     if (nb.get("nbformat"), nb.get("nbformat_minor")) != (4, 5):
         raise ValueError("expected notebook format 4.5")
     ```
   - Checks uniqueness of cell identifiers:
     ```python
     identifiers = [cell["id"] for cell in nb["cells"]]
     if len(identifiers) != len(set(identifiers)):
         raise ValueError("duplicate cell identifier")
     ```
   - Requires at least three code cells (setup, worked computation, and exercise):
     ```python
     if len(code) < 3:
         raise ValueError("expected setup, worked computation, and adversarial exercise cells")
     ```

2. **Selected Arithmetic Restrictions (`audit_notebook`)**:
   - Parses code cells via the Python Abstract Syntax Tree (`ast.parse`) and inspects AST nodes:
     * Float literal rejection:
       ```python
       if isinstance(node, ast.Constant) and type(node.value) is float:
           raise ValueError("float literal in a lesson code cell")
       ```
     * Runtime float constructor rejection:
       ```python
       if (
           isinstance(node, ast.Call)
           and isinstance(node.func, ast.Name)
           and node.func.id == "float"
       ):
           raise ValueError("runtime float construction in a lesson code cell")
       ```
     * Constant assertion rejection (disallowing trivial or tautological asserts):
       ```python
       if isinstance(node, ast.Assert) and isinstance(node.test, ast.Constant):
           raise ValueError("constant assertion cannot support lesson evidence")
       ```

3. **Source Bindings Verification (`child`)**:
   - Verifies declared input source hashes against repository files:
     ```python
     declared = {
         source: sha(ROOT / source) for source in nb["metadata"]["system_integration"]["sources"]
     }
     ```
   - Records all imported Python source module hashes during cell execution and confirms that neither the notebook nor declared sources were modified during execution.

4. **Plain Python Execution (`child` and `main`)**:
   - Executes code cells in a sequential namespace using standard `exec(compile(source, ...))` in a dedicated CPython subprocess (`sys.executable, "-B", ..., "--child", lesson["path"]`).
   - Does not initialize an IPython kernel, render interactive widgets, or evaluate rich display outputs.

## 4. Limits and Non-Claims

1. **No Interactive Kernel or Rendering**: The verifier runs ordinary Python AST execution; it does not evaluate IPython magic commands, frontend notebook rendering, or interactive browser widgets.
2. **No Semantic Pedagogical Evaluation**: Structural checks and arithmetic restrictions do not evaluate whether a notebook teaches effectively or whether a student comprehends the material.
3. **Restricted Scope of Arithmetic Checks**: Rejection of `float` literals and `float()` calls enforces exact arithmetic in lesson cells, but does not inspect or constrain numerical algorithms inside imported third-party compiled packages.

## 5. Claim Hygiene Summary

1. **What it supports**: Confirms that `ops/education/scripts/verify_system_integration.py` enforces format structure, AST float and constant-assert restrictions, source hash bindings, and subprocess CPython execution.
2. **What it does not support**: Does not evaluate interactive Jupyter display features, learner mastery, or general absence of floating-point arithmetic across uninspected binary dependencies.
3. **Narrowest defensible claim**: The verifier script inspects notebook JSON structure, disallows float AST nodes and constant asserts, tracks source hashes, and runs code cells via standard CPython.
4. **Next test needed**: Negative-control tests asserting that notebooks containing float literals, float conversions, or duplicate cell IDs are rejected by `audit_notebook`.
