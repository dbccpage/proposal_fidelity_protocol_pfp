## Abstract

The Symbol Game demonstration corpus contains executable examples, retained
model outputs, reference solutions, certificate checkers, informal mechanism
sketches, and subsequently corrected findings. These objects support different
claims. This paper reconstructs the corpus through a source-bound inventory and
explicit replay procedures. Every result identifies the original source, the
executed algorithm, its dependencies, and the obligation that its output checks.
Historical reference self-scores and prompts containing answers remain visible
as limitations. A copied receipt does not become a new experiment, and an
unavailable operation does not become a verified computation. The present draft
retains unresolved reconstruction obligations until the complete corpus and its
positive examples have been independently replayed.

## The reconstruction problem

A heterogeneous demonstration archive cannot be reproduced by rerunning one
entry point. Some original modules refer to retired namespaces. Others call
native certificate engines, include retained answers, or describe a mechanism
without supplying executable cases. The findings also contain corrections that
withdraw earlier conclusions. Reconstruction must retain the mathematical task
and the historical record while making dependencies and interpretation explicit.

We use two source collections: the twenty findings notes and the complete tracked
PFP demos subtree. The source census at the captured repository revision contains
8,037 files in the latter and twenty notes in the former, totaling 34,722,866 bytes.
This census establishes the intended copy inventory. It does not establish that
copy custody or execution has completed. The companion custody and execution
records determine those outcomes separately.

## Source identity and execution identity

The source snapshot records a Git revision, each tracked path, its Git blob
identity, its raw file digest, and its destination digest. Raw digests are needed
because parsed JSON and normalized line endings do not bind physical file bytes.
The copied inventory must be a bijection with the declared tracked inventory.
Additional, missing, redirected, or corrupted entries cause custody verification
to fail. A retained historical file is inert evidence until a separately declared
replay executes it.

An execution record additionally binds the algorithm and any adaptation, actual
input and output bytes, process exit status, runtime configuration, and dependencies.
Archived Python algorithms are described as source recreations. Native results
identify the Rust executable and its independently checked certificate. Neither
kind of record is presented as a new model-performance result.

## Preserving the declared task

Changing an import path can restore executability without changing the intended
computation. Such an adaptation is acceptable only when its permitted change is
recorded and the original and adapted bytes remain available. Changes to carrier,
case data, protected constraints, answer format, or checker semantics require
separate disclosure. Success under an easier replacement does not reproduce the
original demonstration.

For a rational graph example, the host minimizes a declared residual objective

\[
\Phi_1(\omega)=\min_u\sum_{e=(a,b)}
\left|\omega_e-(u_b-u_a)\right|.
\]

Equality of primal and dual objectives is meaningful only after feasibility,
divergence balance, and the dual box bounds have been checked. A scalar returned
by a runner supplies no independent certificate. Higher-degree, gauge, stabilizer,
and formal-mathematics demonstrations have their own carriers and obligations;
the graph objective cannot silently substitute for those checks.

## Historical findings and corrected interpretations

The preserved findings report reference scores and empirical observations together.
Their correction notices impose material limits. Labels called `PASS_TO_MASTER`
are reference self-scores. Several formal-mathematics panels used answer-bearing
case identifiers. The reported paired-bout ten-of-ten count measured a field that
was true in every retained record. Passing blind-cluster runs followed prompts
containing the answer. The claimed twenty-eight-probe study has no retained study
behind it. These statements must be analyzed as corrected historical records.

The stealth-model observations also lack a disclosed model identity, size, and
training provenance. They fall outside the collection's declared open-weight
challenge regime. Replaying a checker over a retained answer may reproduce a
finite checking outcome, but it does not recover the missing live experiment or
establish unaided model accuracy.

Genesis labels require particular care: the findings quarantine an always-passing
artifact verifier and report timeout, failure, and absent-verifier cases among
records previously labeled checked. A new finite example could demonstrate a
mechanism, but it would be a new reconstruction with its own evidence, not a
retroactive confirmation of those labels.

## Replay protocol

1. Verify source custody and the pinned interpretation before execution.
2. Resolve explicit dependencies and validate executable digests.
3. Execute original finite cases with bounded resources and isolated outputs.
4. Preserve actual outputs and failures; run the corresponding checking obligation.
5. Rehash copied sources and controls after every mutable subprocess.
6. Emit a readable account and machine-readable records with the same identities.
7. Keep positive reconstruction gaps open until their computations are reproduced.

A refusal can correctly demonstrate a boundary when refusal is the declared
example. It cannot satisfy a positive computation merely because a current API
lacks that computation. Missing historical data and unavailable positive ports
remain distinct reconstruction obligations.

## Reproducibility and limits

The companion package retains source and adapted runtime identities separately.
Its code supplies reproduction machinery; dated output receipts supply execution
evidence. Package tests run from the extracted paper directory. Native operations
require explicitly supplied, digest-checked executables and a pinned engine
capability where declared. Missing configuration yields an explicit residual.

No universal natural-language formulation guarantee, unrestricted solver, general
model-accuracy result, solution of the dimension-six mutually unbiased bases
problem, or proof of every historical narrative follows from these finite checks.
The goal is a faithful and inspectable reconstruction of the declared corpus.
