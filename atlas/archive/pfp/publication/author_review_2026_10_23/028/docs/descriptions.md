# Operadic PFP: Typed Composition and Bounded DDC Repair

## Abstract

An implementation study of Proposal Fidelity Protocol using typed operations
and one bounded supplied-patch code repair.

## Why This Matters

Capability discovery, compatible types, executed checks and permission to act
are different things. The example makes their implementation boundaries visible.

## Core Theorems

No new mathematical theorem is claimed. Earlier finite claim-scoping and
assignment-gluing results remain separate from the effectful runtime example.

## Formal Verification and Computational Artifacts

The shared OEOP and Adversary runtime supplies the executable example. OEEIS
supplies an immune observation; Prompt Civilization records genealogy.
No new Lean proof or model experiment is claimed.

## Scope Boundaries and Non-Claims

Two supplied checks do not establish correctness on untested inputs. A working
copy is not a security sandbox. No source application, detector activation,
production admission, DOI or external publication is performed.

## Reproduction

Use the existing code-repair example and focused tests identified in the
companion reproduction note, with the current native host explicitly configured.
